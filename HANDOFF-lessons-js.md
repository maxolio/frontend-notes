# HANDOFF — Оптимизация уроков JS (`site/data/js/`)

## 1. Специфика этого трека
- **Роль чата:** внедрение, проверка и сборка готовых оптимизированных уроков JS (которые предварительно проходят смысловой аудит и доработку).
- **Главное правило:** не менять файлы без явного запроса/подтверждения пользователя; при получении готового текста урока — записывать его в целевой файл, проверять валидатором и пересобирать бандл.
- **Worklog трека:** [logs/lessons.md](file:///c:/Frontend/js-ucheba/logs/lessons.md).

## 2. Стандартный пайплайн на каждый урок
1. Записать обновлённый файл урока в `site/data/js/lesson-XX.md`.
2. Запустить валидатор:
   `node scripts/validate-lessons.mjs` (ожидается `Files with issues: 0. Total issues: 0`).
3. Пересобрать общий бандл JS:
   `python site/tools/convert_docx.py --subject js --bundle-only`.
4. По команде `/log` добавить запись сверху в `logs/lessons.md`.

## 3. Памятка по правилам оформления уроков JS
- **`Суть урока:`** — `2–4` коротких пункта списком с новой строки (`- **Якорь:** суть`).
- **Код и комментарии:** только блочные `/* ... */` (без `//` и вложенных `/*`), ширина строк комфортная для планшета (`<= 78` символов).
- **Без цветных эмодзи:** использовать `[+]` / `[!]` и обычный текст (`Да`, `Нет`, `SyntaxError`).
- **Разметка и парсер:**
  - ключевые слова, переменные, ошибки и теги в тексте — в `` ` `` (без двойных бэктиков);
  - в `<details>` обязательна пустая строка сразу после `</summary>`, перед `</details>` и перед списками.
- **Формат задач:** `1–2` предложения контекста -> нумерованный список требований (`1.`, `2.`, `3.`) -> строка `Проверка:` с ожидаемым выводом.
