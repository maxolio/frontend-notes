# Урок 01. Зачем нужен SCSS, синтаксис и настройка компиляции

Суть урока: препроцессор Sass (диалект `.scss` со скобками и `;`) решает проблему дублирования кода в чистом CSS за счёт вложенности, миксинов, функций, циклов и разбивки на модули, а браузер получает скомпилированный `.css`-файл (плюс `.css.map` для отладки в DevTools).

## 1. Какие проблемы CSS решает препроцессор (00:00–04:25)

[+] В больших проектах на чистом CSS накапливается много ручного дублирования:
1. Приходится постоянно повторять имя родителя (`.header .title`, `.button:hover`, `.header__menu`, `.header__logo`).
2. Неудобно переиспользовать наборы свойств без замусоривания HTML десятками утилитарных классов.
3. Нет циклов (например, для генерации сетки от `2` до `12` колонок) и встроенной модульной сборки файлов.

[+] **Препроцессор стилей** (Sass, Less, Stylus) — это программа, которая переводит удобный код из `.scss` в обычный `.css`, понятный браузеру. В `<link>` подключают всегда скомпилированный `.css`, а не `.scss`!

## 2. Два синтаксиса Sass: `.scss` против `.sass` (12:30–13:42)

[+] У Sass есть два синтаксиса:
- **`.scss` (*Sassy CSS*)** — полностью совместим с обычным CSS: есть `{ }` и `;`. Именно его используют в 95%+ проектов.
- **`.sass`** — старый синтаксис без фигурных скобок и точек с запятой, где вложенность строится строго отступами (как в Python).

```scss
/* Синтаксис .scss (рекомендуется — любой валидный CSS здесь уже работает): */
.header {
  padding: 16px;

  .title {
    color: #0f172a;
  }
}
```

## 3. Установка `sass` и настройка автокомпиляции (04:26–12:29)

[+] Для работы нужен установленный **Node.js (LTS)** и современный пакет **Dart Sass** (`npm install -g sass`, или локально в проект `npm i -D sass`).

```bash
# Установка Dart Sass глобально и запуск слежения за изменениями (watch)
npm install -g sass
sass --watch scss/styles.scss css/styles.css
```

[+] Удобные способы автокомпиляции без сборщиков вроде Vite/Webpack:
- **Prepros (`prepros.io`):** открываете папку проекта и держите программу запущенной. Полезные настройки: включить **`Process Automatically`** и **`Create a Source Map`** (файл `.css.map`, чтобы DevTools показывал строки прямо в `.scss`), а **`Prefix CSS`** и **`Minify CSS`** при разработке лучше отключить (минификацию включают только перед релизом).
- **WebStorm:** установить плагин `Sass` -> `Tools` -> `File Watchers` -> `+` -> `SCSS` (работает автоматически при автосохранении).

## 3 главные ловушки урока (чек-лист для повторения)

1. Подключать к HTML файл `<link rel="stylesheet" href="styles.scss">` — браузер не понимает SCSS-синтаксис; подключать нужно только скомпилированный `.css`.

2. Отключать генерацию `Source Map` (`.css.map`) при разработке — без неё DevTools в браузере показывает номера строк скомпилированного `.css` вместо исходного `.scss`.

3. Путать файлы `.sass` и `.scss` — в `.sass` нельзя ставить `{ }` и `;`, а в `.scss` они обязательны.

## Вопросы для закрепления

**1. Зачем при компиляции SCSS создают файл `styles.css.map` (Source Map)?**

<details>
<summary>Показать ответ</summary>

`Source Map` связывает строки скомпилированного `styles.css` с исходными файлами `.scss`. Благодаря этому при инспектировании элемента в DevTools вы видите точный файл и номер строки в вашем SCSS-коде (например, `_header.scss:14`), а не в общем CSS.

</details>

**2. Чем диалект `.scss` отличается от `.sass` и почему в продакшене почти всегда выбирают `.scss`?**

<details>
<summary>Показать ответ</summary>

В `.scss` сохраняются фигурные скобки `{ }` и точки с запятой `;`, поэтому любой обычный CSS-код является валидным SCSS. В `.sass` скобок и `;` нет — блоки определяются отступами, что непривычно и легко ломается при копировании обычного CSS.

</details>

**3. Что делает флаг `--watch` в команде `sass --watch styles.scss styles.css`?**

<details>
<summary>Показать ответ</summary>

Переводит компилятор в режим наблюдения: при каждом сохранении `styles.scss` (или его подключённых модулей) Dart Sass автоматически пересобирает `styles.css` без повторного ручного запуска команды.

</details>

# Урок 02. Вложенность селекторов, оператор `&` и БЭМ

Суть урока: SCSS позволяет вкладывать дочерние селекторы внутрь родителя, а символ амперсанда `&` подставляет имя родителя целиком — для псевдоклассов (`&:hover`), составных классов (`&.is-active`) и БЭМ-суффиксов (`&__item`, `&--big`). Главное правило индустрии — не углубляться глубже **3 уровней вложенности**.

## 1. Вложенность селекторов и «правило 3 уровней» (13:43–15:05)

[+] Вложенные селекторы избавляют от повторения родителя. Хороший тон — сначала писать собственные свойства блока, затем оставлять **пустую строку** и после неё размещать вложенные селекторы.

[!] **Правило 3 уровней (Best Practice):** никогда не вкладывайте селекторы глубже 3 уровней (иначе итоговый CSS превращается в монстров `.page .section .card .header .title span` с раздутой специфичностью и жёсткой привязкой к HTML).

```scss
.section {
  padding: 24px 0;

  /* Скомпилируется в .section .title */
  .title {
    margin-bottom: 16px;
    font-size: 28px;
  }

  /* Отделяем вложенные блоки пустой строкой для читаемости */
  .list {
    display: flex;
    gap: 12px;
  }
}
```

## 2. Оператор `&` для псевдоклассов, состояний и БЭМ (15:06–16:17)

[+] Знак **`&`** (*parent selector*) подставляет точный селектор родителя **без пробела**:
- **`&:hover`**, `&:focus-visible` -> `.button:hover`, `.button:focus-visible`.
- **`&.is-active`** -> `.tab.is-active` (два класса на одном теге).
- **`&__inner`**, **`&--big`** -> `.header__inner`, `.button--big` (БЭМ-элементы и модификаторы!).

[!] Важно: вложенная конструкция `&__menu { &-list { ... } }` скомпилируется в `.header__menu` и `.header__menu-list`, сохранив плоскую специфичность **`0-1-0`** (один класс), даже несмотря на вложенность в SCSS! Правда, при поиске имени класса по проекту через `Ctrl+F` склеенный `&__menu-list` не находится целиком — в командной разработке это учитывают заранее.

```scss
.header {
  padding: 12px 0;

  /* Склейка через & даёт плоский класс .header__inner (вес 0-1-0) */
  &__inner {
    display: flex;
    align-items: center;
  }

  &__menu {
    margin-left: auto;

    /* Скомпилируется в .header__menu-list — тоже один класс без потомков! */
    &-list {
      display: flex;
      gap: 16px;
      list-style: none;
    }
  }
}
```

<!-- demo-html:
<style>

<button class="btn-demo" type="button">Обычная</button>

```css
.btn-demo:hover {

  color: #2563eb;
}
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Вкладывать селекторы на 4–6 уровней (`.card { .body { .list { .item { a { ... } } } } }`) — итоговый CSS приобретает огромный вес `0-5-1` и ломается при малейшей перестановке тегов.

2. Забывать `&` перед `:hover` или модификатором: запись `.button { :hover { ... } }` превратится в `.button :hover` (с пробелом — сработает на **потомках** кнопки, а не на самой кнопке!).

3. Писать вложенные БЭМ-селекторы без `&` (`&__title` вместо `.header__title`) и забывать, что в SCSS-файле склеенное `&-list` нельзя найти простым поиском `Ctrl+F` по слову `header__menu-list`.

## Вопросы для закрепления

**1. В чём разница между `.button { &:hover { ... } }` и `.button { :hover { ... } }` после компиляции в CSS?**

<details>
<summary>Показать ответ</summary>

`&:hover` склеивается с родителем без пробела и даёт `.button:hover` (наведение на саму кнопку). А `:hover` без амперсанда добавляет пробел — получается `.button :hover` (наведение на любой вложенный элемент внутри кнопки).

</details>

**2. Какой CSS-код сгенерируется из `.card { &__header { &-title { color: red; } } }` и какая у него будет специфичность?**

<details>
<summary>Показать ответ</summary>

Сгенерируется одиночный плоский селектор `.card__header-title { color: red; }` со специфичностью **`0-1-0`** (один класс). Несмотря на визуальную вложенность в SCSS, в итоговом CSS никакой вложенности потомков не будет.

</details>

**3. Почему в лучших гайдах по SCSS советуют не делать вложенность глубже 3 уровней?**

<details>
<summary>Показать ответ</summary>

Глубокая вложенность порождает длинные селекторы с высокой специфичностью (их потом трудно переопределять), увеличивает размер итогового CSS-файла и жёстко привязывает стили к конкретной структуре HTML-тегов.

</details>

# Урок 3: Переменные $, миксины, функции, math.div и циклы @for

**Суть урока:** Переменные `$` хранят настройки до компиляции, `@mixin` генерирует готовые наборы свойств, `@function` возвращает одно вычисленное значение, а `@for` автоматизирует создание повторяющихся классов.

---

## Переменные `$var` против CSS-переменных `--var`

В SCSS переменные начинаются со знака `$`. При компиляции они **полностью исчезают**, превращаясь в обычные статичные значения в CSS.

```scss
/* Переменные SCSS для констант сборки */
$color-accent: #ff5500;
$container-width: 1200px;

.button {
  background-color: $color-accent;
  max-width: $container-width;
}
```

- **Когда брать `$var`:** брейкпоинты `@media`, размеры сетки, расчёты в функциях и миксинах (CSS `--var` в `@media` не работают).
- **Когда брать `--var`:** цвета тем (светлая/тёмная), отступы и всё, что нужно менять в браузере на лету через `@media` или JavaScript.

---

## Интерполяция `#{$var}`

Если переменную нужно подставить в **имя класса**, имя свойства или внутрь CSS-функции вроде `calc()` / `clamp()`, её оборачивают в `#{...}`.

```scss
/* Подстановка переменной в имя класса и в clamp() */
$name: card;
$min-size: 16;
$max-size: 32;

.#{$name}__title {
  font-size: clamp(#{$min-size}px, 2vw, #{$max-size}px);
}
```

Без `#{...}` внутри `clamp()` или имени селектора Sass воспримет `$name` как обычный текст или выдаст ошибку синтаксиса.

---

## Миксины `@mixin` и `@include`

Миксин — это шаблон набора CSS-свойств с параметрами и значениями по умолчанию (`$arg: default`). Вызывается через `@include`.

```scss
/* Миксин обрезки текста с параметром по умолчанию */
@mixin line-clamp($lines: 1) {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: $lines;
  overflow: hidden;
}

/* Вызов с аргументом по умолчанию (1 строка) */
.card__title {
  @include line-clamp;
}

/* Вызов с явным числом строк */
.card__desc {
  @include line-clamp(3);
}
```

Внутри миксинов удобно использовать условия `@if` / `@else`, например для центрирования `flex` или `inline-flex`:

```scss
/* Условная генерация свойства через @if / @else */
@mixin flex-center($is-inline: false) {
  @if $is-inline {
    display: inline-flex;
  } @else {
    display: flex;
  }

  justify-content: center;
  align-items: center;
}

.badge {
  @include flex-center(true);
}
```

---

## Функции `@function`, `@return` и `math.div()`

В отличие от миксина, `@function` **не вставляет CSS-свойства**, а возвращает ровно одно значение через `@return`.

В современном Dart Sass деление через слэш `/` устарело (в `font: 16px/1.5` слэш — разделитель CSS). Для математического деления подключают встроенный модуль `sass:math` и вызывают `math.div($a, $b)`.

```scss
/* Подключение встроенного модуля математики */
@use 'sass:math';

/* Функция перевода px в rem на базе 16px */
@function rem($px) {
  @return math.div($px, 16) * 1rem;
}

/* Использование функции в значении свойства */
.hero__title {
  font-size: rem(32);
  margin-bottom: rem(24);
}
```

---

## Цикл `@for` для генерации классов

Цикл `@for` создаёт серию однотипных классов, например модификаторы колонок сетки `.grid--2` .. `.grid--12`.

- `from 2 through 12` — включает `12`.
- `from 2 to 12` — останавливается на `11` (не включая `12`).

```scss
/* Генерация модификаторов сетки от 2 до 4 колонок */
.grid {
  display: grid;
  gap: 16px;

  @for $i from 2 through 4 {
    &--#{$i} {
      grid-template-columns: repeat(#{$i}, 1fr);
    }
  }
}
```

---

## 3 главные ловушки урока

1. **[!] Деление через `$a / $b` устарело:** в современном Dart Sass нужно `@use 'sass:math';` и `math.div($a, $b)`.
2. **[!] Путаница `@mixin` и `@function`:** `@mixin` вставляет блок свойств (`@include`), а `@function` возвращает только одно значение (`@return`).
3. **[!] Забытая интерполяция `#{$var}`:** без `#{...}` нельзя подставить переменную в имя селектора (`.grid--#{$i}`) или внутрь `calc()`/`clamp()`.

## Вопросы для закрепления

<details>
<summary>1. В чём главное отличие переменной $accent от CSS-переменной --accent?</summary>

`$accent` существует только на этапе компиляции и в итоговом CSS заменяется на конкретное значение. `--accent` попадает в браузер и может меняться динамически в `@media` или через JavaScript.

</details>

<details>
<summary>2. Почему в современном Sass для деления используют math.div($a, $b) вместо $a / $b?</summary>

Потому что в самом CSS слэш `/` используется как разделитель (например, `font: 16px/1.5` или `grid-column: 1 / 3`). Чтобы не было конфликтов со стандартом CSS, деление в вычислениях вынесли в `math.div()` из модуля `sass:math`.

</details>

<details>
<summary>3. Чем @for $i from 1 through 4 отличается от @for $i from 1 to 4?</summary>

Ключевое слово `through` включает конечное число (`1, 2, 3, 4`), а `to` останавливается перед ним (`1, 2, 3`).

</details>

# Урок 4: Архитектура (Partials), @use, @forward и @extend

**Суть урока:** Крупный проект разбивают на файлы-партиалы (`_name.scss`), подключают их через современный `@use` с пространствами имён и переэкспортируют через `@forward`, а общий CSS без параметров выносят в `@extend %placeholder`.

---

## Что такое партиалы (`_partials`)

Файл, имя которого начинается с нижнего подчёркивания (`_variables.scss`, `_mixins.scss`), называется **партиалом**. Компилятор Sass не создаёт для него отдельный `.css`-файл — он нужен только для подключения в главный файл `styles.scss`.

```text
scss/
|-- base/
|   |-- _normalize.scss
|   |-- _variables.scss
|   |-- _globals.scss
|-- helpers/
|   |-- _mixins.scss
|   |-- _index.scss
|-- blocks/
|   |-- _header.scss
|   |-- _card.scss
|-- styles.scss
```

Такая структура разделяет базовые настройки, хелперы и БЭМ-блоки: искать и править стили становится в разы быстрее.

---

## Почему `@import` устарел и чем его заменяет `@use`

В старых уроках часто показывают `@import 'variables';`. В современном Dart Sass **`@import` официально устарел** и удаляется из языка по трём причинам:
1. Загружал файл заново при каждом импорте (дублировал CSS).
2. Вываливал все переменные и миксины в глобальную область (конфликты имён).
3. Не давал понять, из какого файла пришла переменная `$accent`.

**Современная замена — `@use`:**
- Файл компилируется **ровно один раз**, сколько бы раз его ни подключили.
- Переменные и миксины получают **пространство имён** (по умолчанию — имя файла).

```scss
/* Подключение с именем пространства по умолчанию */
@use 'base/variables';

/* Короткий псевдоним через as */
@use 'helpers/mixins' as m;

/* Подключение без префикса (удобно только для 1-2 общих файлов) */
@use 'base/globals' as *;

.header {
  color: variables.$color-text;
  @include m.flex-center;
}
```

---

## `@forward` и паттерн `_index.scss`

Чтобы в каждом файле блоков не писать по пять строчек `@use`, в папке создают индексный партиал `_index.scss` и переэкспортируют файлы через `@forward`.

```scss
/* Файл helpers/_index.scss: собираем все хелперы в одну точку */
@forward 'variables';
@forward 'mixins';
@forward 'functions';
```

Теперь любой БЭМ-блок подключает всю папку одной строкой:

```scss
/* Файл blocks/_card.scss */
@use '../helpers' as h;

.card {
  padding: h.rem(16);
  background-color: h.$color-surface;
}
```

Важно: `@use` и `@forward` всегда должны стоять **в самом верху файла** (до любых CSS-правил).

---

## `@extend %placeholder` против `@mixin`

Плейсхолдер `%name` — это заготовка стилей, которая **не попадает в итоговый CSS**, пока её не расширят через `@extend`. В отличие от миксина, `@extend` не копирует свойства в каждый класс, а **объединяет селекторы через запятую**.

```scss
/* Плейсхолдер не попадёт в CSS сам по себе */
%button-reset {
  border: none;
  background: transparent;
  cursor: pointer;
}

.nav__btn {
  @extend %button-reset;
  color: #222;
}

.modal__close {
  @extend %button-reset;
  font-size: 20px;
}
```

В итоговом CSS оба селектора объединятся в один блок: `.nav__btn, .modal__close { border: none; ... }`.

**Как выбирать между `@extend` и `@mixin`:**
- Нужны **аргументы** (`$color`, `$size`) или работа внутри `@media` -> только `@mixin`.
- Нужен **одинаковый статичный набор** правил для многих элементов (сброс кнопки, скрытие `.visually-hidden`) -> `@extend %placeholder`.

---

## 3 главные ловушки урока

1. **[!] Использовать `@import` в новом проекте:** он объявлен устаревшим в Dart Sass; используйте `@use` и `@forward`.
2. **[!] `@extend` через границу `@media`:** Sass запрещает расширять плейсхолдер, объявленный снаружи, находясь внутри `@media` — для адаптива используйте `@mixin`.
3. **[!] Обычный класс вместо `%placeholder` в `@extend`:** расширяйте именно `%name`, чтобы не тянуть лишние случайные каскады и не оставлять мёртвый класс в CSS.

## Вопросы для закрепления

<details>
<summary>1. Для чего нужно нижнее подчёркивание в начале имени файла _variables.scss?</summary>

Оно помечает файл как партиал (частичный файл). Компилятор Sass не создаёт из него отдельный `variables.css`, а ждёт, пока его подключат через `@use` или `@forward` в основной файл.

</details>

<details>
<summary>2. Зачем в папке делают _index.scss с директивой @forward?</summary>

Чтобы объединить несколько партиалов (`_variables.scss`, `_mixins.scss`, `_functions.scss`) в одну точку входа и подключать их все одной строкой `@use 'helpers';`.

</details>

<details>
<summary>3. В чём разница между результатом компиляции @include и @extend %placeholder?</summary>

`@include` дублирует блок CSS-свойств внутри каждого селектора, а `@extend %placeholder` группирует сами селекторы через запятую над общим блоком свойств. При этом `@extend` не принимает параметры и не работает через границу `@media`.

</details>
