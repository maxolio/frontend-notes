# Урок 01. Зачем нужен SCSS, синтаксис и настройка компиляции

Суть урока: препроцессор Sass (диалект `.scss` со скобками и `;`) решает проблему дублирования кода в чистом CSS за счёт вложенности, миксинов, функций, циклов и разбивки на модули, а браузер получает скомпилированный `.css`-файл (плюс `.css.map` для отладки в DevTools).

## 1. Какие проблемы CSS решает препроцессор (00:00–04:25)

[+] В больших проектах на чистом CSS накапливается много ручного дублирования:
1. Приходится постоянно повторять имя родителя (`.header .title`, `.button:hover`, `.header__menu`, `.header__logo`).
2. Неудобно переиспользовать наборы свойств без замусоривания HTML десятками утилитарных классов.
3. Нет циклов (например, для генерации сетки от `2` до `12` колонок) и встроенной модульной сборки файлов.

[+] **Препроцессор стилей** (Sass, Less, Stylus) — это программа, которая переводит удобный код из `.scss` в обычный `.css`, понятный браузеру. В `<link>` подключают всегда скомпилированный `.css`, а не `.scss`!

## 2. Два синтаксиса Sass: `.scss` против `.sass` (12:30–13:42)

[+] У Sass есть два синтаксиса:
- **`.scss` (*Sassy CSS*)** — полностью совместим с обычным CSS: есть `{ }` и `;`. Именно его используют в 95%+ проектов.
- **`.sass`** — старый синтаксис без фигурных скобок и точек с запятой, где вложенность строится строго отступами (как в Python).

```scss
/* Синтаксис .scss (рекомендуется — любой валидный CSS здесь уже работает): */
.header {
  padding: 16px;

  .title {
    color: #0f172a;
  }
}
```

## 3. Установка `sass` и настройка автокомпиляции (04:26–12:29)

[+] Для работы нужен установленный **Node.js (LTS)** и современный пакет **Dart Sass** (`npm install -g sass`, или локально в проект `npm i -D sass`).

```bash
# Установка Dart Sass глобально и запуск слежения за изменениями (watch)
npm install -g sass
sass --watch scss/styles.scss css/styles.css
```

[+] Удобные способы автокомпиляции без сборщиков вроде Vite/Webpack:
- **Prepros (`prepros.io`):** открываете папку проекта и держите программу запущенной. Полезные настройки: включить **`Process Automatically`** и **`Create a Source Map`** (файл `.css.map`, чтобы DevTools показывал строки прямо в `.scss`), а **`Prefix CSS`** и **`Minify CSS`** при разработке лучше отключить (минификацию включают только перед релизом).
- **WebStorm:** установить плагин `Sass` -> `Tools` -> `File Watchers` -> `+` -> `SCSS` (работает автоматически при автосохранении).

## 3 главные ловушки урока (чек-лист для повторения)

1. Подключать к HTML файл `<link rel="stylesheet" href="styles.scss">` — браузер не понимает SCSS-синтаксис; подключать нужно только скомпилированный `.css`.

2. Отключать генерацию `Source Map` (`.css.map`) при разработке — без неё DevTools в браузере показывает номера строк скомпилированного `.css` вместо исходного `.scss`.

3. Путать файлы `.sass` и `.scss` — в `.sass` нельзя ставить `{ }` и `;`, а в `.scss` они обязательны.

## Вопросы для закрепления

**1. Зачем при компиляции SCSS создают файл `styles.css.map` (Source Map)?**

<details>
<summary>Показать ответ</summary>

`Source Map` связывает строки скомпилированного `styles.css` с исходными файлами `.scss`. Благодаря этому при инспектировании элемента в DevTools вы видите точный файл и номер строки в вашем SCSS-коде (например, `_header.scss:14`), а не в общем CSS.

</details>

**2. Чем диалект `.scss` отличается от `.sass` и почему в продакшене почти всегда выбирают `.scss`?**

<details>
<summary>Показать ответ</summary>

В `.scss` сохраняются фигурные скобки `{ }` и точки с запятой `;`, поэтому любой обычный CSS-код является валидным SCSS. В `.sass` скобок и `;` нет — блоки определяются отступами, что непривычно и легко ломается при копировании обычного CSS.

</details>

**3. Что делает флаг `--watch` в команде `sass --watch styles.scss styles.css`?**

<details>
<summary>Показать ответ</summary>

Переводит компилятор в режим наблюдения: при каждом сохранении `styles.scss` (или его подключённых модулей) Dart Sass автоматически пересобирает `styles.css` без повторного ручного запуска команды.

</details>

## Задачи

**Задача 1. Подключение скомпилированного файла в HTML**

В корне проекта лежат `styles.scss`, скомпилированный `styles.css` и `styles.css.map`. Напиши правильный тег `<link>` в `<head>`, чтобы страница получила стили, и укажи, какой файл читает браузер.

```html
<head>
  <!-- Подключи стили правильно -->
</head>
```

<details>
<summary>Подсказка и решение</summary>

```html
<head>
  <!-- Браузер понимает только итоговый .css, а .scss и .css.map нужны на этапе разработки и в DevTools -->
  <link rel="stylesheet" href="styles.css">
</head>
```

</details>

**Задача 2. Перевод фрагмента из синтаксиса `.sass` в `.scss`**

Перепиши фрагмент на `.sass` (без скобок) в валидный `.scss`-код.

```sass
.card
  padding: 16px
  .card-title
    font-size: 20px
```

<details>
<summary>Подсказка и решение</summary>

```scss
/* В .scss обязательны фигурные скобки вокруг блоков и ';' в конце каждого свойства */
.card {
  padding: 16px;

  .card-title {
    font-size: 20px;
  }
}
```

</details>

**Задача 3. Запуск наблюдения (watch) в терминале**

Напиши CLI-команду для Dart Sass, которая будет следить за файлом `src/scss/main.scss` и автоматически компилировать его в `dist/css/main.css`.

```bash
# Напиши команду sass с флагом автоматического отслеживания
```

<details>
<summary>Подсказка и решение</summary>

```bash
# Формат: sass --watch <входной_scss>:<выходной_css> (или через пробел)
sass --watch src/scss/main.scss dist/css/main.css
```

</details>
