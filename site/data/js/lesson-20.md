# Урок 20. Таймеры в JavaScript: setTimeout, setInterval, clear и вложенный вызов

Суть урока:

- **Таймеры:** `setTimeout` запускает функцию один раз с задержкой в миллисекундах, а `setInterval` повторяет её регулярно.
- **Точная пауза:** чтобы интервал считался строго после выполнения кода, используют вложенный `setTimeout`.

## 1. Отложенный запуск (setTimeout), аргументы и отмена (clearTimeout) (00:24 – 04:01)

```js
/*
  1-й аргумент — функция (стрелка или ссылка БЕЗ скобок ()!),
  2-й — задержка в мс (2000 мс = 2 сек; без него по умолчанию 0),
  3-й и далее — аргументы, которые передадутся внутрь при срабатывании:
*/
function logMessage(name, age) {
  alert(`Привет, ${name}! Возраст: ${age}`);
}

/* Передаём по ссылке (с logMessage() сработает сразу и без задержки!): */
const timerId = setTimeout(logMessage, 2000, 'Вася', 21);

/* setTimeout возвращает ID. Отменить ДО срабатывания -> clearTimeout: */
clearTimeout(timerId); /* Окно alert через 2 секунды НЕ появится */

/*
  Важно:
  1) Не передавай код строкой: setTimeout('alert(1)', 1000) — устарело.
  2) Потеря this: setTimeout(user.sayHi, 1000) потеряет объект user!
     Фикс: setTimeout(() => user.sayHi(), 1000) или .bind(user).
*/
```

## 2. Регулярный запуск — setInterval и clearInterval (04:04 – 05:50)

```js
/*
  Синтаксис как у setTimeout, но функция запускается циклически каждые N мс.
  (Одинаковые подряд console.log браузер группирует со счётчиком слева.)
*/
const intervalId = setInterval(() => {
  console.log('Привет');
}, 1000);

/* Чтобы остановить интервал позже (например, через 5 сек): */
setTimeout(() => {
  /* Обязательно отменяй ненужный интервал (иначе утечка памяти!) */
  clearInterval(intervalId);
}, 5000);
```

## 3. Минус setInterval и вложенный (рекурсивный) setTimeout (05:51 – 07:28)

```js
/*
  ПРОБЛЕМА setInterval: он НЕ ждёт завершения предыдущего вызова!
  Если код внутри работал долго (например, висел alert), вызовы начнут
  идти без паузы или накладываться друг на друга.
*/

/*
  РЕШЕНИЕ — вложенный setTimeout: новый таймер заводится ТОЛЬКО ПОСЛЕ того,
  как текущий вызов закончился — это гарантирует честную паузу 1000 мс:
*/
function showNextAlert() {
  alert('Сообщение'); /* Ждём, пока пользователь закроет окно */
  setTimeout(showNextAlert, 1000); /* Только потом отсчитываем 1 сек */
}
setTimeout(showNextAlert, 1000);
```

## 4. Ловушка нулевой задержки setTimeout(..., 0) (07:30 – 08:30)

```js
console.log('1');
setTimeout(() => console.log('2'), 0); /* Или без 2-го аргумента */
console.log('3');

/*
  Вывод в консоли будет: '1', '3', и ТОЛЬКО ПОТОМ '2'!
  1) Любой setTimeout ждёт окончания всего текущего синхронного кода ниже.
  2) После 5 вложенных таймеров минимальная задержка браузера — >= 4 мс.
  3) На неактивной вкладке браузер замедляет таймеры примерно до 1000 мс.
*/
```

## 5. Как движок JS и браузер работают с таймером (под капотом)

1. Передача браузеру: сам JS время не считает и работает в 1 поток. Дойдя до setTimeout(fn, 2000), JS отдаёт fn и задержку браузеру и сразу идёт к следующим строкам.

2. Отсчёт на фоне: браузер отдельно отсчитывает 2000 мс, пока JS выполняет весь обычный код ниже.

3. Очередь ожидания: когда время вышло, браузер НЕ прерывает JS, а кладёт fn в очередь задач.

4. Запуск (Event Loop): только когда весь обычный код полностью закончился, Event Loop берёт fn из очереди и запускает её. Поэтому задержка в 2000 мс — минимальная, а не точная.

## 3 главные ловушки урока (чек-лист для повторения)

1. Круглые скобки в первом аргументе: setTimeout(fn(), 1000) — функция вызовется мгновенно без ожидания, а в таймер передастся undefined.

2. Ожидание, что setTimeout(..., 0) выполнится «тут же» — колбэк всё равно выполнится только ПОСЛЕ всех обычных строк кода ниже.

3. Наложение вызовов в setInterval — если операция внутри занимает больше времени, чем интервал (например, запрос на сервер), используй вложенный setTimeout.

## Вопросы для закрепления

**1. Что выведется в консоль и в каком порядке сработают строки ниже?**

```js
let count = 0;
setTimeout(() => console.log('Таймер:', count), 0);

for (let i = 0; i < 5; i++) {
  count++;
}

console.log('Синхронно:', count);
```

<details>
<summary>Показать ответ</summary>

Выведется сначала **`'Синхронно: 5'`**, а потом **`'Таймер: 5'`**. Даже при задержке `0` `setTimeout` не прерывает текущий код: JS отдаёт колбэк браузеру в очередь задач, полностью завершает цикл `for` и `console.log`, и только когда синхронный код закончился, Event Loop запускает таймер (который видит уже обновлённый `count === 5`).

</details>

**2. Что произойдёт при запуске обоих таймеров в строгом режиме?**

```js
'use strict';

const user = {
  name: 'Алекс',
  sayHi() { console.log(`Привет, ${this.name}`); },
};

setTimeout(user.sayHi, 1000);
setTimeout(user.sayHi(), 1000);
```

<details>
<summary>Показать ответ</summary>

1. Первый таймер через секунду упадёт с **`TypeError`**, потому что `setTimeout` получил оторванную функцию без объекта `user` и вызвал её с `this === undefined` (исправляется обёрткой `() => user.sayHi()` или `.bind(user)`).
2. Второй таймер вызовет `user.sayHi()` **мгновенно без ожидания** (`'Привет, Алекс'`), а в `setTimeout` уйдёт `undefined`.

</details>

**3. Чем вложенный `setTimeout` надёжнее `setInterval` и почему забытый `setInterval` вызывает утечку памяти?**

<details>
<summary>Показать ответ</summary>

`setInterval` не ждёт окончания работы предыдущего запуска: если задача внутри выполняется дольше интервала, вызовы начнут идти без паузы или накладываться друг на друга. Вложенный `setTimeout` заводит следующий таймер **только после завершения** текущей функции, обеспечивая честную паузу. А неостановленный `clearInterval` таймер навсегда остаётся в памяти и не даёт сборщику мусора удалить саму функцию и её внешние переменные.

</details>

**Задача 2. Вывод чисел каждую секунду через `setInterval` (`printNumbers`)**

Напиши функцию `printNumbers(from, to)` на основе `setInterval`:

1. Если `from > to`, сразу сделай ранний выход (`return`).
2. Каждые `1000` мс выводи в консоль текущее число от `from` до `to` включительно.
3. Как только выведено число `to`, останови таймер через `clearInterval`.

Проверка: `printNumbers(3, 6)` выведет раз в секунду `3`, `4`, `5`, `6` и остановится.

```js
'use strict';

/* Твоё решение: */

printNumbers(3, 6); /* выведет раз в секунду: 3, 4, 5, 6 */
```

<details>
<summary>Подсказка и решение</summary>

```js
'use strict';

function printNumbers(from, to) {
  /* Защита от бесконечного интервала, если начало больше конца */
  if (from > to) return;

  let current = from;

  const intervalId = setInterval(() => {
    console.log(current);

    /* Как только дошли до конечного числа — отменяем интервал по его ID */
    if (current === to) {
      clearInterval(intervalId);
    }

    current++;
  }, 1000);
}

printNumbers(3, 6);
```

</details>

**Задача 3. Вложенный `setTimeout` с мгновенным первым выводом**

Напиши функцию `printNumbersNested(from, to)` на основе **вложенного `setTimeout`** (без `setInterval`):

1. Если `from > to`, сразу выйди из функции.
2. Первое число `from` должно выводиться **сразу** при вызове функции (без секундной задержки).
3. Если `current < to`, увеличь счётчик и запланируй следующий шаг через `setTimeout(step, 1000)`.

Проверка: `printNumbersNested(1, 3)` сразу выведет `1`, через 1 сек — `2`, ещё через 1 сек — `3`.

```js
'use strict';

/* Твоё решение: */

printNumbersNested(1, 3); /* сразу: 1, через 1 сек: 2, затем: 3 */
```

<details>
<summary>Подсказка и решение</summary>

```js
'use strict';

function printNumbersNested(from, to) {
  if (from > to) return;

  let current = from;

  function step() {
    console.log(current);

    /*
      Планируем следующий запуск ТОЛЬКО если не достигли границы to,
      и уже после текущей логики — пауза будет ровно 1000 мс
    */
    if (current < to) {
      current++;
      setTimeout(step, 1000);
    }
  }

  /* Запускаем первый шаг синхронно, чтобы from вывелось без задержки */
  step();
}

printNumbersNested(1, 3);
```

</details>
