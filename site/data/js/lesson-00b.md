# Вводный 02. Инструменты веб-разработки: полная классификация

Суть урока:

- **Код и UI:** базовые языки (HTML/CSS/JS) плюс готовые библиотеки и фреймворки.
- **Сборка и публикация:** локальная среда (`Node.js`, `npm`, `Vite`), контроль версий (`Git`, `GitHub`) и хостинг.
- **Качество:** утилиты проверки и форматирования кода.

## 1. Полка 1: Языки браузера и «переводчики»

[+] Браузер (Chrome, Safari, Firefox) понимает напрямую только три языка: `HTML` (структура), `CSS` (внешний вид) и `JavaScript` (логика и интерактив). Все остальные форматы — это надстройки для удобства программиста, которые перед запуском нужно перевести в один из этих трёх языков.

```js
/*
  Что понимает браузер напрямую vs что нужно переводить (компилировать):
  1. HTML       -> понимает напрямую
  2. CSS        -> понимает напрямую
  3. JavaScript -> понимает напрямую (включая <script type="module">)

  Надстройки (требуют переводчика перед показом пользователю):
  - Markdown (.md)   -> переводится в HTML (через marked.js или при сборке)
  - SCSS / Sass      -> компилируется в обычный CSS (вложенность и миксины)
  - TypeScript (.ts) -> компилируется в обычный JS (проверка типов до старта)
*/
```

[!] Браузер никогда не запускает `.scss` или `.ts` напрямую — если подключить такой файл в `<link>` или `<script>` без компиляции, сайт его не поймёт.

## 2. Полка 2: Библиотеки против фреймворков

[+] Чтобы не писать с нуля парсер Markdown или раскраску синтаксиса, разработчики подключают готовый код — **библиотеки** или **фреймворки**. Главное отличие между ними — кто кем управляет.

```js
/* БИБЛИОТЕКА: ты сам вызываешь нужную функцию тогда, когда хочешь */
const html = window.marked.parse('# Привет');
window.hljs.highlightElement(codeBlock);

/*
  ФРЕЙМВОРК (React, Vue, Astro, Next.js):
  Задаёт жёсткие правила и структуру папок, а ты встраиваешь код внутрь него.
  Фреймворк сам решает, когда вызвать твои функции и как обновить экран.
*/
```

[!] Для небольших проектов и обучения чистому JS достаточно пары лёгких библиотек (`marked`, `highlight.js`). Фреймворк берут тогда, когда экранов и компонентов становятся десятки.

## 3. Полка 3: Среда на компьютере (`Node.js`, `npm`, `CDN`, сервер и сборщики)

[+] Даже если сайт потом работает только в браузере, на компьютере разработчику нужна среда для запуска инструментов:

```js
/*
  1. Node.js        — запускает JS прямо на ПК без браузера
                      (нужен для работы npm, live-server и Vite).
  2. npm            — менеджер пакетов: качает библиотеки в node_modules/.
  3. CDN            — альтернатива npm: скрипт подключается ссылкой в <head>,
                      без скачивания тысяч файлов в node_modules.
  4. live-server    — мини-сервер на ПК: раздаёт сайт по http://localhost,
                      чтобы работали fetch() и модули (без блокировки CORS).
  5. Сборщик (Vite) — берёт код (JS, SCSS, TS, пакеты из node_modules),
                      переводит в чистые HTML/CSS/JS и сжимает в папку dist/.
*/
```

[!] Не путай `Node.js` как **инструмент сборки** на твоём ПК (для `live-server` или `Vite`) и `Node.js` как **бэкенд-сервер** в интернете (который отвечает пользователям 24/7). Наш `site/` использует `live-server` только локально, а в интернете работает вообще без Node.js.

## 4. Полка 4: Хранение кода (`Git`, `GitHub`) и хостинг

[+] Когда сайт готов, его нужно сохранить с историей изменений и выложить в интернет по HTTPS-адресу.

```js
/*
  Контроль версий:
  - Git    — программа на ПК, хранит историю коммитов (можно откатить баг).
  - GitHub — сайт-облако для хранения Git-репозиториев и командной работы.

  Хостинг (где физически лежат файлы сайта):
  - GitHub Pages / Vercel / Netlify — бесплатный хостинг статики и SPA.
  - VPS / Docker / Облако           — арендованный сервер для своего бэкенда.
  - BaaS (Supabase, Firebase)       — готовая база данных и вход в облаке.
*/
```

[!] Никогда не храни папку `node_modules/` и личные настройки редактора (`.idea/`) в Git — их всегда добавляют в файл `.gitignore`.

## 5. Полка 5: Утилиты, линтеры и автоматизация

[+] В реальных проектах вокруг кода работают «невидимые помощники», которые экономят время и ловят опечатки:
- **Форматтеры (`Prettier`)** — сами расставляют отступы, кавычки и переносы строк по единому стилю.
- **Линтеры (`ESLint`)** — подсвечивают потенциальные баги (неиспользуемые переменные, опасные сравнения `==`) ещё до запуска кода.
- **Свои скрипты автоматизации** — например, наш Python-скрипт `convert_docx.py`, который переводит `.docx`-конспекты в `.md` и собирает `all-lessons.md`.

## 3 главные ловушки урока (чек-лист для повторения)

1. Открывать сайт с `fetch()` и `<script type="module">` двойным кликом как `file://...`: из-за политики безопасности браузера (CORS) скрипты и загрузка `.md` не сработают — нужен локальный сервер (`live-server` или `Vite`).

2. Путать `Git` и `GitHub`: `Git` работает локально на твоём компьютере даже без интернета, а `GitHub` — это лишь удалённый сервер для хранения копии и публикации через Pages.

3. Забыть добавить `node_modules/` в `.gitignore`: в репозиторий попадут десятки тысяч чужих мелких файлов, а проект раздуется на сотни мегабайт.

## Вопросы для закрепления

**1. В чём разница между библиотекой (например, `marked.js`) и фреймворком (например, `React`)?**

<details>
<summary>Показать ответ</summary>

Библиотеку вызываешь ты сам в нужном месте кода (`marked.parse(text)`), сохраняя полный контроль. Фреймворк сам задаёт архитектуру проекта и решает, когда вызывать твои компоненты и как обновлять DOM.

</details>

**2. Зачем на этапе разработки нужен `live-server`, если сайт потом всё равно работает на GitHub Pages без своего бэкенда?**

<details>
<summary>Показать ответ</summary>

При открытии локального файла через `file://` браузер блокирует `fetch()`-запросы и ES-модули (`type="module"`) из-за правил безопасности. `live-server` поднимает локальный HTTP-адрес (`http://127.0.0.1:8080`), имитируя настоящий хостинг.

</details>

**3. Можно ли залить `.scss` и `.ts` файлы на GitHub Pages напрямую, без сборки, и ожидать, что браузер их выполнит?**

<details>
<summary>Показать ответ</summary>

Нет. Браузер понимает только чистые `HTML`, `CSS` и `JS`. Файлы `SCSS` и `TypeScript` нужно предварительно скомпилировать (например, через `Vite` или `Sass`), и выкладывать уже готовые `CSS` и `JS`.

</details>
