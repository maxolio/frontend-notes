# Вводный 03. Инструменты на практике: что попробовать, чтобы понять всё

Суть урока:

- **Сборка и контент:** `Vite` + `TypeScript`, а для контентных сайтов — `VitePress` и `Astro`.
- **Интерфейс и данные:** `React` + `Tailwind` для UI и `Supabase` для бэкенда/БД.
- **Качество кода:** связка `ESLint + Prettier`.

## 1. Сборка и строгий код: Vite и TypeScript

[+] **Vite** — главный современный сборщик и сервер разработки. Он заменил тяжёлый Webpack за счёт мгновенного старта и умной работы с ES-модулями.

```js
/* Что даёт Vite на практике:
   1. Локальная разработка — мгновенно обновляет экран при правке кода (HMR) без сброса state.
   2. Импорты из npm      — позволяет писать import { marked } from 'marked' без CDN.
   3. Сборка (npm run build) — компилирует SCSS/TS, сжимает всё в папку dist/ для хостинга. */
```

[+] **TypeScript (TS)** — надстройка над JavaScript со строгими типами данных. Перед запуском в браузере TS компилируется в обычный JS.

```ts
/* Главный плюс TS: опечатка в названии поля или неверный тип ловится ещё в редакторе */
interface Lesson {
  id: string;
  number: number;
  traps: string[];
}
/* Понимание структур данных и контрактов (TS) — обязательный стандарт от уровня Middle. */
```

[!] Пытаться учить `Vite` и `TypeScript` до базы JS тяжело — сначала важно понять, как работает сам JS и браузерный DOM без сборщика.

## 2. Генераторы статики и доков: VitePress и Astro

[+] **VitePress** — готовый движок для документации и баз знаний поверх Markdown и Vite (под капотом использует Vue).

```js
/* Плюсы VitePress:
   - Разворачивает готовый сайт из папки с .md-файлами за 5 минут.
   - Поиск, темы, оглавление и подсветка кода идут «из коробки».
   Что даёт для понимания: наглядно показывает силу SSG (генерации статики)
   и объясняет, почему в коммерции документацию не пишут руками. */
```

[+] **Astro** — современный фреймворк для контентных сайтов с «островной архитектурой» (Islands Architecture).

```js
/* Главная идея Astro:
   - 95% страницы отдаётся в браузер как сверхбыстрый чистый HTML без единого байта JS.
   - Интерактивные блоки («островки» вроде тренажёра или фильтра) подгружают JS точечно.
   Что даёт для понимания: учит не тащить тяжёлый JS туда, где достаточно простого HTML. */
```

## 3. UI-фреймворк и стили: React и Tailwind CSS

[+] **React** — самая популярная библиотека для создания сложных интерфейсов и SPA-приложений через состояние (`UI = render(state)`).

```jsx
/* В чистом JS ты руками ищешь теги и обновляешь DOM.
   В React ты описываешь интерфейс от данных, а DOM обновляется сам: */
function LessonStatus({ isDone }) {
  return <span>{isDone ? '✓ Изучено' : '↻ Повторить'}</span>;
}
/* Что даёт: после ручного my-site/ ты сразу поймёшь, какую именно рутину убирает React. */
```

[+] **Tailwind CSS** — подход utility-first, где стили пишутся готовыми короткими классами прямо в HTML/JSX вместо отдельных `.scss`-файлов.

```html
<!-- Сравни с БЭМ из future-tech: здесь не нужно придумывать имена классов -->
<button class="px-4 py-2 rounded-lg font-medium border">Изучено</button>
```

[!] Tailwind удобно пробовать уже после того, как ты уверенно владеешь обычным CSS/SCSS (`flex`, `grid`, `rem`, медиазапросы) — иначе легко не понять, что происходит под капотом классов.

## 4. Облачные данные и качество кода: Supabase, ESLint и Prettier

[+] **Supabase** — облачный BaaS (Backend-as-a-Service): готовая база данных `PostgreSQL`, авторизация и API без написания своего сервера с нуля.

```js
/* Вместо localStorage одного браузера данные живут в облачной таблице: */
const { data } = await supabase.from('lessons').select('*');
/* Что даёт: за один вечер даёт опыт работы с настоящей БД, токенами и правами доступа. */
```

[+] **ESLint и Prettier** — два обязательных инструмента в любой команде разработки:
- **Prettier** отвечает за красоту (отступы, кавычки, переносы строк при сохранении файла).
- **ESLint** отвечает за правильность (предупреждает о неиспользуемых переменных, забытом `await` или опасном `==`).

## 5. Рекомендуемый порядок освоения (чтобы не распыляться)

```js
/* Оптимальный маршрут без каши в голове:
   Шаг 1 -> Чистый JS (наш my-site/): понять fetch, DOM, state, localStorage, модули.
   Шаг 2 -> Vite + TypeScript: перенести проект на сборку и строгие типы.
   Шаг 3 -> React (+ Tailwind): переписать тот же проект и прочувствовать разницу.
   Шаг 4 -> VitePress / Astro / Supabase: пощупать за 1–2 вечера для расширения кругозора. */
```

## 6. Главный секрет: почему всё сводится к HTML, CSS и JS (и что происходит за их пределами)

[+] Браузер (Chrome, Safari, Firefox) не понимает ни React, ни Tailwind, ни TypeScript, ни VitePress. На стороне браузера **абсолютно любой сайт в итоге превращается в обычный `HTML + CSS + JS`**. Вся «магия» инструментов делится на 3 конкретных этапа:

```js
/* 1. ДО БРАУЗЕРА (Build Time в Node.js: Vite, TypeScript, Sass, VitePress, Astro):
      - Проверяет типы и ошибки до запуска (TS, ESLint).
      - Переводит .scss -> .css, .ts -> .js, .md -> .html.
      - Вырезает неиспользуемый код (Tree Shaking) и сжимает файлы для быстрой загрузки.
      Браузер получает уже готовый, чистый HTML/CSS/JS.

   2. ВНУТРИ БРАУЗЕРА (Runtime: React, Vue):
      - Под капотом React делает ровно то же, что мы пишем руками: вызывает document.createElement,
        меняет textContent и классы.
      - Его главная фишка — он сам вычисляет разницу между старым и новым state, чтобы не
        перерисовывать всю страницу, а точечно обновить только одну изменившуюся строчку.

   3. ВНЕ БРАУЗЕРА (Сеть и Сервер: HTTP, Supabase, Next.js, PostgreSQL):
      - База данных, проверка паролей и секретные API-ключи живут на удалённом сервере.
      - Браузер туда не заходит — он общается с сервером по сети через HTTP-запросы (fetch + JSON). */
```

[!] Именно поэтому сильный фундамент в `HTML + CSS + JS` — лучшая инвестиция: меняются модные фреймворки, но все они в итоге управляют тем же DOM, теми же стилями и теми же запросами `fetch`.

## Главные ловушки урока (чек-лист для разбора с ИИ)

1. Учить сразу всё подряд (React + Next + Tailwind + TypeScript + Supabase в одном первом проекте): мозг перегружается от магии инструментов, и при первой ошибке непонятно, кто именно сломался.

2. Использовать Tailwind CSS без понимания обычного CSS (`flex`, `grid`, `rem`, `z-index`): невозможно нормально отлаживать сложную вёрстку и адаптив.

3. Писать сайт документации вручную на React, когда задача решается за 10 минут через готовый VitePress или Astro.

4. Класть секретные API-ключи или пароли от базы прямо в код фронтенда (JS/React): любой пользователь откроет DevTools → Network/Sources и заберёт их, поэтому секреты хранят только на сервере (или в Edge-функциях).

5. Ждать, что TypeScript защитит от кривого ответа сервера: TS проверяет типы только на этапе сборки (`Build Time`), а в реальном браузере сервер может прислать `null` или другое поле — нужны проверки в рантайме.

6. Выкладывать на GitHub Pages исходники Vite-проекта вместо собранной папки `dist/` (или указывать пути от корня `/data/...` вместо относительных `data/...`, из-за чего на адресе `username.github.io/repo/` всё отдаёт 404).

7. Пытаться запустить серверный код (Express, серверный Next.js, работу с файлами БД) на обычном GitHub Pages — он умеет раздавать только статику и клиентский SPA.

8. Считать, что `localStorage` — это «облачная база»: на самом деле он привязан только к одному браузеру на одном устройстве и пропадёт при смене телефона или очистке данных сайта.

9. В React менять состояние напрямую (например, `items.push(newItem)` вместо создания нового массива `[...items, newItem]`): React сравнивает ссылки и при мутации просто не перерисует экран.

10. Тащить на сайт 500 КБ тяжёлого JS там, где хватило бы чистого HTML + CSS (например, для лендинга или простой статьи — именно эту проблему решает Astro).

11. Забыть про Jekyll на GitHub Pages при наличии `.md`-файлов: без пустого файла `.nojekyll` в корне сборка может упасть из-за фигурных скобок `{{ ... }}` в примерах кода.

12. Отключать ESLint и не использовать Prettier: мелкие баги (лишние переменные, забытый `await`, нестрогое `==`) накапливаются и превращают код в нечитаемую кашу.
