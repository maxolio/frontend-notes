# Шпаргалка. Как проектировать и читать функции (HtDF + CQS)

Суть урока:

- **Снаружи внутрь (HtDF):** прежде чем писать тело функции, задай контракт (`Вход -> Выход`) и 2–3 примера — логика сложится сама.
- **Команда или Запрос (CQS):** любая функция либо делает действие (`undefined`), либо возвращает данные без побочных эффектов — не смешивай оба подхода.
- **Вход диктует защиту:** тип аргумента сразу определяет первую строку (Guard Clause), а тело всегда строится в 3 этажа: `Защита -> Логика -> Выход`.

## 1. Калька создания функции (методика HtDF — снаружи внутрь)

[+] Не начинай с кода внутри `{ ... }`. Пройди 4 быстрых шага сверху вниз:

1. **Контракт (`Вход -> Выход`):** одной строкой определи типы аргументов и результата (например: `number, number -> number | null` или `boolean -> function`).
2. **Примеры (`Вход => Ожидание`):** запиши 2 рабочих вызова и 1 крайний случай (`calcFinalPrice(1000) -> 900`, `calcFinalPrice('1000') -> null`).
3. **Имя и параметры:** выбери префикс под роль (Раздел 4), поставь обязательные данные в начало, а все значения по умолчанию `=` — в самый конец.
4. **3 этажа тела:**
   - **Этаж 1 — Защита (Guard Clauses):** ранние `return` на плохих данных, чтобы не плодить глубокую лесенку `if / else`.
   - **Этаж 2 — Логика:** одно понятное действие (правило «1 функция = 1 сценарий»).
   - **Этаж 3 — Выход:** возврат предсказуемого типа (или `undefined`, если это команда).

## 2. Калька чтения чужой функции за 15 секунд (CQS)

[+] Принцип **CQS (Command-Query Separation)** гласит: *«Задавать вопрос не должно менять ответ»*. Разбирай любую незнакомую функцию по 3 шагам:

1. **Имя + `return` (Команда или Запрос?):**
   - **Команда** (`show`, `log`, `clear`, `set`): делает побочный эффект (выводит в консоль, меняет DOM/данные), возвращает `undefined`.
   - **Запрос** (`calc`, `format`, `get`, `is`, `has`, `create`): вычисляет или создаёт результат и отдаёт его через `return`, **не меняя ничего снаружи**.
2. **Скобки `(...)` (что на входе?):** определи типы аргументов по справочнику ниже и посмотри, какие параметры необязательные (`=`).
3. **3 этажа внутри:** найди, где кончаются ранние `return` (защита), какое одно действие выполняется в центре и какой тип уходит наружу.

## 3. Справочник по входу: какая защита нужна под каждый тип

### 3.1. Ничего не ждёт — `fn()`
- **Роль:** **команда** (`showMenu()`, `clearCart()`) или **поставщик данных** (`getPi()`, `getAdminGreeting()`).
- **Первая строка (защита):** не нужна.
- **Что внутри:** либо сразу делает 1 действие (`undefined`), либо вычисляет и отдаёт значение через `return`.

### 3.2. Ждёт число — `fn(num)`
- **Роль:** математика, цены, скидки, счётчики, циклы (`calcBonus(sum)`, `pow(x, n)`).
- **Первая строка (защита):** `if (!Number.isFinite(num)) return null;` *(плюс границы вроде `num <= 0`, если отрицательные нельзя)*.
- **Ловушка:** `typeof num !== 'number'` пропускает `NaN` и `Infinity` — поэтому надёжнее `Number.isFinite(num)`. Ставь проверки на границах ввода (`prompt`, `<input>`), а не в каждой 1-строчной функции.

### 3.3. Ждёт строку — `fn(str)`
- **Роль:** форматирование текста, имён, поиск (`formatGreeting(userName)`).
- **Первая строка (защита):** `if (typeof str !== 'string' || str.trim() === '') return ...;` *(или дефолт `str = 'Гость'`, если параметр необязательный)*.
- **Ловушка:** проверка `typeof str !== 'string'` обязана идти **первой** — иначе `.trim()` на `null` или числе уронит код с `TypeError`.

### 3.4. Ждёт `boolean` — `fn(isFlag)`
- **Роль:** развилка, переключатель режима или фабрика (`createGreeting(isAdmin)`).
- **Подсказка по имени:** параметр почти всегда начинается с `is...`, `has...`, `can...`.
- **Первая строка (защита):** обычно хватает дефолта `(isAdmin = false)` или строгой проверки `isAdmin === true`.
- **Ловушка:** непустая строка `'false'` внутри `if (isFlag)` станет `true`. А 2+ флага подряд (`fn(true, false)`) путают при чтении — на вырост их заменяют объектом настроек.

### 3.5. Ждёт функцию (колбэк) — `fn(callback)`
- **Роль:** универсальный оркестратор (`ask(q, yes, no)`, `processPayment(sum, ok, err)`).
- **Первая строка (защита):** для необязательного колбэка — пустышка `callback = () => {}`; для жёсткой защиты — `if (typeof callback !== 'function') return;`.
- **Главное правило:** снаружи передаём **без `()`**, а внутри запускаем **со скобками `()`** (пустыми или передавая результат `callback(result)`).

### 3.6. Ждёт массив или объект — `fn(arr)` / `fn(obj)` *(На вырост: Блок 2–3)*
- **Роль:** работа с группой данных (корзина товаров, карточка пользователя).
- **Первая строка (защита):** для массива — `if (!Array.isArray(arr)) return ...;`; для обычного объекта — `if (typeof obj !== 'object' || obj === null || Array.isArray(obj)) return ...;` *(плюс `obj?.prop` при чтении)*.
- **Ловушка:** массивы и объекты передаются **по ссылке** — изменив их внутри функции, ты изменишь исходные данные снаружи. В JS `typeof null === 'object'` и `typeof [] === 'object'`, поэтому без `!== null` и `!Array.isArray(obj)` защита пропустит и `null`, и массив.

## 4. Порядок параметров и 5 ролей по имени

### Порядок параметров (когда их 2 и больше)
- **1-е место:** главные обязательные данные (`amount`, `text`).
- **2-е место:** обязательные колбэки (`onSuccess`), если функция без них не имеет смысла.
- **3-е место (в самом конце):** все необязательные настройки, флаги и колбэки с дефолтом (`rate = 0.1`, `isAdmin = false`, `onError = () => {}`).
- **Правило дефолтов:** параметры с `=` всегда идут **после** обязательных, иначе придётся передавать `undefined` для пропуска. *(Дефолт `=` срабатывает только при `undefined`, но не при `null` или `''`.)*

### Имя заранее задаёт роль и выход (5 ролей по CQS)
- **`show...`, `log...`, `clear...`** -> **Команда** (делает эффект, возвращает `undefined`).
- **`calc...`, `format...`, `get...`** -> **Запрос-вычислитель** (чисто считает и возвращает данные).
- **`is...`, `has...`, `can...`, `check...`** -> **Запрос-предикат** (**всегда** возвращает `true` или `false`).
- **`create...`, `make...`** -> **Запрос-фабрика** (возвращает новую функцию или объект).
- **`run...`, `process...`, `ask...`** -> **Оркестратор** (принимает колбэки и управляет порядком шагов).

## 5. Живой пример по всей кальке (HtDF + CQS + 3 этажа)

```js
'use strict';

/*
  1. Контракт (HtDF): (number, number?) -> number | null
  2. Примеры:
     calcFinalPrice(1000)      -> 900
     calcFinalPrice(1000, 0.2) -> 800
     calcFinalPrice('1000')    -> null
  3. Роль (CQS): Запрос-вычислитель (только считает, без console.log)
*/
function calcFinalPrice(price, discount = 0.1) {
  /* Этаж 1. Защита (Guard Clauses): отсекаем NaN, строки и плохие границы */
  if (!Number.isFinite(price) || price <= 0) return null;
  if (!Number.isFinite(discount) || discount < 0 || discount >= 1) {
    return null;
  }

  /* Этаж 2. Логика: одно понятное вычисление */
  const finalPrice = price * (1 - discount);

  /* Этаж 3. Выход: предсказуемый тип (число) */
  return finalPrice;
}

/* Отдельная Команда (CQS): только выводит результат, возвращает undefined */
function showPrice(label, amount) {
  if (amount === null) {
    console.log(`${label}: некорректная цена`);
    return;
  }
  console.log(`${label}: ${amount} руб.`);
}

showPrice('Со скидкой 10%', calcFinalPrice(1000));
showPrice('Со скидкой 20%', calcFinalPrice(1000, 0.2));
showPrice('Ошибка ввода', calcFinalPrice('1000'));
```

## Главная закономерность (1 правило на всё)

> **Контракт задаёт рамку, вход диктует защиту, а имя (CQS) — выход:**
> - **Создаёшь функцию:** `Контракт (Вход -> Выход)` -> `2–3 примера` -> `Защита -> Логика -> Выход`.
> - **Читаешь функцию:** `Команда или Запрос?` -> `Какие типы в (...)?` -> `Где 3 этажа?`.
> - **Не смешивай роли:** если функция считает или создаёт (`calc`, `create`), пусть возвращает результат, а выводом (`console.log`) занимается отдельная команда (`show`).
