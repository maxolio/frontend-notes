# Урок 02. Переменные (`var`, `let`, `const`), строгий режим `"use strict"` и именование

Суть урока:

- **Динамическая типизация:** тип переменной заранее не указывают — он определяется при записи и может меняться.
- **Выбор объявления:** по умолчанию берём `const` (нельзя переназначить), для меняемых значений — `let`, а `var` устарел.
- **Строгий режим и имена:** `'use strict'` в начале файла запрещает запись без объявления, а имена пишут в `camelCase`.

## 1. Объявление переменных, присваивание (`=`) и смена значения (00:23–02:47)

[+] Знак `=` в JS — оператор присваивания (запись справа налево), а не равенство. Тип данных определяется автоматически в момент записи и может меняться в процессе работы (**динамическая типизация**).

```js
let message = 'Привет'; /* объявление + запись начального значения (string) */
console.log(message);   /* выведет: Привет */

message = 'Пока';       /* переопределяем значение (повторно let НЕ пишем!) */
message = 42;           /* тип спокойно сменился на number */
console.log(message);   /* выведет: 42 */
```

## 2. Порядок объявления и разница `var` / `let` / `const` (02:48–05:57)

[!] До строки объявления к `let` и `const` обращаться нельзя (сработает **TDZ** — временная мёртвая зона). У устаревшего `var` вместо ошибки выведется `undefined`, к тому же он игнорирует блоки `{}` — в современном коде `var` не используют. Переменные пишут с новой строки, а повторное объявление одного имени в той же области запрещено.

```js
/* 1. TDZ (Temporal Dead Zone) и базовые правила let / const */
/* console.log(title); -> ReferenceError: Cannot access 'title' (TDZ) */
let title = 'Новость';

const name = 'Александр'; /* const — выбор по умолчанию */
/* const empty;           -> SyntaxError: значение нужно задать сразу! */
/* name = 'Иван';         -> TypeError: Assignment to constant variable */

const admin = name;       /* копирование значения в другую константу */
/* const admin = 123;     -> SyntaxError: 'admin' has already been declared */

/*
  Важный нюанс: const замораживает лишь саму привязку =,
  но свойства внутри const-объекта или const-массива менять МОЖНО!
*/
```

```js
/* 2. Почему var опасен: всплытие (undefined) и утечка из блока {} */
console.log(oldVar); /* undefined (ошибки нет — баг легко не заметить!) */
var oldVar = 'Старый код';

if (true) {
  var leaked = 'Я вытек наружу';   /* var игнорирует if/for */
  let inside = 'Я только в блоке'; /* let и const живут строго внутри {} */
}
console.log(leaked); /* 'Я вытек наружу' */
/* console.log(inside); -> ReferenceError: inside is not defined */
```

| Характеристика | `const` | `let` | `var` (устарел) |
| :--- | :--- | :--- | :--- |
| Область видимости | Блок `{}` | Блок `{}` | Функция (игнорирует `if`/`for`) |
| Можно переназначить (`=`) | Нет | Да | Да |
| Обязательно задать значение сразу | Да | Нет | Нет |
| Повторное объявление в той же области | `SyntaxError` | `SyntaxError` | Разрешено (перезапишет!) |
| Обращение до строки объявления | `ReferenceError` (TDZ) | `ReferenceError` (TDZ) | `undefined` |

## 3. Строгий режим `"use strict"` (05:58–07:52)

[+] Без строгого режима неявная запись вроде `age = 10` не выдаст ошибку, а молча создаст **глобальную переменную** (свойство объекта `window`), засоряя глобальную область. Директива `'use strict'` в самом начале файла включает строгие правила ES5+ (отключить обратно в файле нельзя). Внутри ES-модулей (`type="module"`) и классов (`class`) строгий режим включён автоматически.

```js
'use strict'; /* строго в начале файла (до неё можно только комментарии) */

/* age = 10; -> без 'use strict' создаст глобальную, а с ним ReferenceError */
const age = 10;
```

## 4. Правила именования переменных и регистр (07:53–09:09)

[+] В имени разрешены буквы (в реальной разработке — только английский, без транслита вроде `imya`), цифры, `$` и `_`. Запрещены зарезервированные слова языка (`let`, `class`, `return` и т.п. -> `SyntaxError`). **Регистр имеет значение.**

```js
const userName = 'Alex';  /* camelCase — стандарт для обычных переменных */
const username = 'Max';   /* это ДРУГАЯ переменная (регистр N vs n важен!) */

const $el = 1;            /* символы $ и _ разрешены */
const user2 = 2;          /* цифры внутри и в конце можно */
/* const 2user = 2;       -> SyntaxError: начинать имя с цифры нельзя! */

const COLOR_RED = '#F00'; /* SCREAMING_SNAKE_CASE — известно ДО запуска */
const pageLoadTime = 120; /* вычисляемые при старте const пишут в camelCase */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Обратиться к `let`/`const` до строки их объявления (`ReferenceError`, TDZ) или поставить `'use strict'` не первой строкой и случайно создать глобальную переменную без ключевого слова.

2. Попытаться перезаписать `const` (`TypeError`), объявить `const` без начального значения или повторно объявить переменную с тем же именем (`SyntaxError`).

3. Начать имя с цифры (`2user`), взять зарезервированное слово (`class`, `let`) или перепутать регистр букв (`userName` и `username`).

## Вопросы для закрепления

**1. Что выведется в консоль при обращении к `var` и `let` до строки их объявления, и какие две главные проблемы делают `var` опасным?**

<details>
<summary>Показать ответ</summary>

Для `var` код не упадёт, а выведет `undefined` — из-за этого в проекте легко пропустить баг, когда данных ещё нет. Вторая проблема: `var` игнорирует блоки `{}` (`if`, `for`) и «вытекает» наружу, к тому же разрешает случайно объявить переменную с тем же именем повторно. У `let` и `const` есть блочная область `{}` и временная мёртвая зона (TDZ), поэтому движок сразу страхует ошибкой `ReferenceError`.

</details>

**2. Включит ли строгий режим этот код и что произойдёт при записи `age = 25`?**

```js
console.log('Запуск');
'use strict';
age = 25;
console.log(age);
```

<details>
<summary>Показать ответ</summary>

Строгий режим **не включится**, потому что директива `'use strict'` работает только в самом начале файла (до неё разрешены лишь комментарии). После `console.log` движок её просто проигнорирует, поэтому `age = 25` молча создаст глобальную переменную без ключевого слова и выведет `25`.

</details>

**3. Когда константу через `const` называют заглавными буквами (`COLOR_RED`), а когда в `camelCase` (`startTime`), и почему запись `const token;` сразу ломает скрипт?**

<details>
<summary>Показать ответ</summary>

В `SCREAMING_SNAKE_CASE` пишут жёстко заданные значения, известные ещё до запуска программы (цвета, лимиты, коды), а в `camelCase` — константы, чьё значение вычисляется уже во время работы скрипта. Запись `const token;` вызывает `SyntaxError`, потому что константу запрещено объявлять без начального значения справа от `=`.

</details>

**4. Значит ли `const`, что данные внутри переменной вообще никак нельзя изменить?**

<details>
<summary>Показать ответ</summary>

Нет. `const` запрещает только **переназначение** самой переменной через `=` (привязать к ней другое значение). Если в `const` лежит примитив (число, строка), поменять его действительно нельзя. Но если в `const` лежит объект или массив (их разберём в следующих уроках), их внутренние свойства и элементы можно свободно менять.

</details>

Потренируйся копировать примитивное значение и менять `let`-переменную:

2. Скопируй значение `userName` в константу `adminName`.
3. Перезапиши `userName` на `'Иван'` и выведи в консоль сначала `adminName`, а затем `userName`.

Проверка: в консоли должны появиться `'Алекс'` и `'Иван'`.

```js
'use strict';

/* Твоё решение: */
```

<details>
<summary>Подсказка и решение</summary>

```js
'use strict';

/*
  Переменная userName будет меняться, поэтому объявляем её через let.
  Значение 'Алекс' записывается справа налево оператором присваивания =
*/
let userName = 'Алекс';

/*
  adminName менять не нужно — берём const по умолчанию.
  Строка копируется как независимое значение, а не ссылка на userName
*/
const adminName = userName;

/*
  Меняем значение без повторного let (иначе будет SyntaxError).
  Константа adminName при этом по-прежнему хранит 'Алекс'
*/
userName = 'Иван';

console.log(adminName); /* выведет: Алекс */
console.log(userName);  /* выведет: Иван */
```

</details>
