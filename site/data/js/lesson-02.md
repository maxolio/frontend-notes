# Урок 02. Переменные (var, let, const), строгий режим use strict и именование

Суть урока: В JS динамическая типизация (тип заранее не указывают); по умолчанию берут const (нельзя переназначить), для меняемых значений — let, var устарел, директива "use strict" запрещает ошибки вроде записи без объявления, имена — в camelCase.

## 1. Объявление переменных, присваивание (=) и смена значения (00:23–02:47)

[+] Знак = в JS — оператор присваивания (запись справа налево), а не равенство. Тип данных определяется автоматически в момент записи (динамическая типизация).

```js
let message = 'Привет'; /* объявление + сразу запись начального значения */
console.log(message);   /* выведет: Привет */

message = 'Пока';       /* переопределяем значение (повторно let писать НЕ нужно!) */
console.log(message);   /* выведет: Пока */
```

## 2. Порядок объявления и разница var / let / const (02:48–05:57)

[!] До строки объявления к let и const обращаться нельзя. У устаревшего var вместо ошибки выведется undefined (и много скрытых багов — в современном коде var не берут). Разные переменные лучше писать каждую с новой строки, а одинаковые имена запрещены.

```js
/* Зона от начала блока {} до строки let/const — TDZ (Temporal Dead Zone, ReferenceError) */
/* console.log(title); -> ОШИБКА: Cannot access "title" before initialization */
let title = 'Новость';

/* let/const живут только внутри блока {}, а var игнорирует if/for и вытекает наружу! */
/* console.log(oldVar); -> undefined (опасное поведение старого var) */
var oldVar = 'Старый код';

const name = 'Александр'; /* const — по умолчанию, переназначить нельзя: */
/* const empty;        -> СИНТАКСИЧЕСКАЯ ОШИБКА: у const значение нужно задать сразу! */
/* name = 'Иван';      -> ОШИБКА: Assignment to constant variable */
/* const замораживает лишь привязку =, но свойства const-объекта менять можно! */
const admin = name;       /* копирование значения из одной переменной в другую */
/* const admin = 123;  -> ОШИБКА: Identifier "admin" has already been declared */
```

## 3. Строгий режим "use strict" (05:58–07:52)

[+] Без строгого режима неявная запись вроде age = 10 сработает без ошибки. Директива "use strict" в самом начале файла включает строгие правила ES5+ (отключить обратно в файле нельзя). Внутри ES-модулей (type="module") и классов (class) строгий режим включается автоматически сам, без этой строки.

```js
'use strict'; /* строго в начале JS-файла, в нижнем регистре, в любых кавычках */

/* age = 10; -> без "use strict" сработает, а со строгим режимом сразу ОШИБКА! */
const age = 10;
```

## 4. Правила именования переменных и регистр (07:53–09:09)

[+] В имени можно использовать буквы (лучше латиницу), цифры, символы $ и _. Запрещены зарезервированные слова языка (let, class, return и т.п. -> Unexpected token). Регистр имеет значение.

```js
const userName = 'Alex'; /* camelCase — стандарт для обычных переменных */
const $el = 1;           /* символы $ и _ разрешены */
const user2 = 2;         /* цифры внутри/в конце можно */
/* const 2user = 2;      -> СИНТАКСИЧЕСКАЯ ОШИБКА: начинать имя с цифры нельзя! */

const COLOR_RED = "#F00"; /* SCREAMING_SNAKE_CASE — для значений, известных ДО запуска */
/* А вычисляемые при запуске константы (например, время загрузки) пишут в camelCase! */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Обратиться к let/const до строки их объявления (Cannot access before initialization) или забыть "use strict" и случайно создать переменную без ключевого слова.

2. Попытаться перезаписать const (Assignment to constant variable) или повторно объявить переменную с тем же именем (Identifier has already been declared).

3. Начать имя переменной с цифры (2user) или взять зарезервированное слово (class, let).

## Вопросы для закрепления

**1. Что выведется в консоль при обращении к `var` и `let` до строки их объявления, и почему `var` считают опасным?**

<details>
<summary>Показать ответ</summary>

Для `var` код не упадёт, а выведет `undefined` — из-за этого в проекте легко пропустить баг, когда переменная на самом деле ещё не получила данные. У `let` и `const` срабатывает временная мёртвая зона (TDZ): от начала блока `{}` до строки объявления к переменной обращаться нельзя, и движок сразу выдаёт `ReferenceError`.

</details>

**2. Включит ли строгий режим этот код и что произойдёт при записи `age = 25`?**

```js
console.log('Запуск');
'use strict';
age = 25;
console.log(age);
```

<details>
<summary>Показать ответ</summary>

Строгий режим **не включится**, потому что директива `'use strict'` работает только в самом начале файла (до неё разрешены лишь комментарии). После `console.log` движок её просто проигнорирует, поэтому `age = 25` молча создаст переменную без ключевого слова и выведет `25`.

</details>

**3. Когда константу через `const` называют заглавными буквами (`COLOR_RED`), а когда в `camelCase` (`startTime`), и почему запись `const token;` сразу ломает скрипт?**

<details>
<summary>Показать ответ</summary>

В `SCREAMING_SNAKE_CASE` пишут значения, которые «зашиты» заранее до запуска программы (цвета, лимиты, коды), а в `camelCase` — константы, чьё значение вычисляется уже во время работы скрипта. Запись `const token;` вызывает `SyntaxError`, потому что константу запрещено объявлять без начального значения справа от `=`.

</details>

## Задачи

**Задача 1. Передача значения и переопределение переменной**

Объяви переменную `userName` со значением `'Алекс'`, скопируй её значение в константу `adminName`, затем поменяй `userName` на `'Иван'` и выведи в консоль сначала `adminName`, а потом `userName`.

```js
'use strict';

/* Твоё решение: */
```

<details>
<summary>Подсказка и решение</summary>

```js
'use strict';

/*
  Переменная userName будет меняться, поэтому объявляем её через let.
  Значение 'Алекс' записывается справа налево оператором присваивания =
*/
let userName = 'Алекс';

/*
  adminName менять не нужно — берём const по умолчанию.
  Строка копируется как независимое значение, а не ссылка на userName
*/
const adminName = userName;

/*
  Меняем значение без повторного let (иначе будет SyntaxError).
  Константа adminName при этом по-прежнему хранит 'Алекс'
*/
userName = 'Иван';

console.log(adminName); /* выведет: Алекс */
console.log(userName);  /* выведет: Иван */
```

</details>

**Задача 2. Спаси скрипт от строгого режима, TDZ и плохих имён**

Код ниже написан с нарушениями: строгий режим не работает, одна строка падает ещё при чтении файла, другая — в TDZ, а одна переменная создаётся вообще без объявления. Исправь код так, чтобы строгий режим реально работал, а в консоль по очереди вывелись `'Старт'`, `'Борис'`, `30` и `'admin'`.

```js
/* Твоё решение: */
console.log('Старт');
'use strict';

console.log(user);
let user = 'Алекс';
let user = 'Борис';

var 2age = 30;
role = 'admin';

console.log(user);
console.log(2age);
console.log(role);
```

<details>
<summary>Подсказка и решение</summary>

```js
/*
  Директиву 'use strict' ставим строго в самом начале файла (до неё можно
  только комментарии) — иначе движок её проигнорирует
*/
'use strict';

console.log('Старт');

/*
  Убираем чтение user до объявления (TDZ) и второе let перед user:
  переопределять существующую переменную нужно простым присваиванием =
*/
let user = 'Алекс';
user = 'Борис';

/*
  Заменяем устаревший var на const и убираем цифру из начала имени (2age -> userAge).
  Для role тоже добавляем const, иначе в строгом режиме будет ReferenceError
*/
const userAge = 30;
const userRole = 'admin';

console.log(user);
console.log(userAge);
console.log(userRole);
```

</details>

**Задача 3. Рефакторинг имён и выбор `const` / `let`**

Замени устаревший `var` и непонятные имена `a`, `b`, `c` на осмысленные названия в правильном регистре (`camelCase` или `SCREAMING_SNAKE_CASE`). Учти, что цвет темы `#2B2D42` известен заранее и никогда не меняется, а имя игрока и его счёт по ходу игры будут меняться.

```js
'use strict';

/* Твоё решение: */
var a = '#2B2D42';
var b = 'Максим';
var c = 10;

c = 25;
console.log(a, b, c);
```

<details>
<summary>Подсказка и решение</summary>

```js
'use strict';

/*
  Значение цвета зашито заранее до запуска и не меняется —
  используем const и регистр SCREAMING_SNAKE_CASE
*/
const THEME_COLOR = '#2B2D42';

/*
  Имя текущего игрока и счёт могут меняться во время игры —
  поэтому используем let и стандартный стиль camelCase
*/
let currentPlayerName = 'Максим';
let playerScore = 10;

/* Обновляем счёт без повторного let */
playerScore = 25;

console.log(THEME_COLOR, currentPlayerName, playerScore);
```

</details>
