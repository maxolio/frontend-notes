# Урок 01. Введение: подключение JS, console.log, синтаксис и ошибки

Суть урока: Скрипт подключают через `<script src="script.js">``</script>` перед `</body>` (или в `<head>` с defer), вывод смотрят в DevTools -> Console, ; ставят перед [ и ( из-за ASI, а любая ошибка останавливает выполнение дальнейшего кода файла.

## 1. Подключение JS к странице и атрибуты defer / async (01:46–02:44)

[+] Браузер читает HTML сверху вниз: обычный `<script>` в `<head>` блокирует отрисовку страницы и не видит разметку ниже. Поэтому ставят в конце `<body>` или с defer в `<head>`.

```html
<!-- Способ 1 — в конце разметки (HTML уже построен, код внутри тега с src игнорируется!): -->
<script src="script.js"></script>
</body>

<!-- Способ 2 — в <head>: defer ждёт DOM и соблюдает порядок; async (аналитика) нет -->
<script src="script.js" defer></script>
```

## 2. Вывод данных в DevTools -> Console (02:45–03:43)

[+] console.log(...) выводит неограниченное число значений через запятую в консоль браузера (клавиша F12). Для наглядности таблиц и ошибок есть table, warn и error.

```js
console.log('Привет', 555, true); /* можно переносить аргументы на разные строки */
console.table([10, 20, 30]);      /* удобная таблица для массивов и объектов */
console.error('Ошибка!');         /* красное сообщение с трассировкой стека */
```

## 3. Инструкции, ловушка ; (ASI) и комментарии (03:44–06:09)

[!] Каждую инструкцию пишут с новой строки. Движок сам подставляет ; (механизм ASI), но перед строкой с [ или ( точку с запятой ставить ОБЯЗАТЕЛЬНО, иначе строки склеятся!

```js
console.log('Привет 1');
[1, 2].forEach(console.log); /* без ";" выше JS попытался бы склеить "Привет 1"[1, 2]! */

// Однострочный комментарий (горячая клавиша в IDE: Ctrl + /)
/* Многострочный комментарий — но вкладывать /* /* */ */ друг в друга НЕЛЬЗЯ! */
```

## 4. Обнаружение и чтение ошибок в консоли (06:10–07:25)

[+] При ошибке (например, console.lg) выполнение файла сразу прерывается. Справа от красной плашки ошибки указана кликабельная ссылка вида script.js:2:9 — клик по ней открывает точную строку во вкладке Sources.

## 3 главные ловушки урока (чек-лист для повторения)

1. Подключить `<script src="...">` в `<head>` без defer (не найдёт HTML-элементы) или написать JS внутрь тега, у которого уже есть атрибут src (внутренний код проигнорируется).

2. Отказаться от ; и начать следующую строку с [ или ( — механизм ASI не поставит точку с запятой, и код упадёт.

3. Вложить многострочный комментарий /* /* */ */ внутрь другого (SyntaxError) или ждать, что код после ошибки в консоли продолжит выполняться.

# Урок 02. Переменные (var, let, const), строгий режим use strict и именование

Суть урока: В JS динамическая типизация (тип заранее не указывают); по умолчанию берут const (нельзя переназначить), для меняемых значений — let, var устарел, директива "use strict" запрещает ошибки вроде записи без объявления, имена — в camelCase.

## 1. Объявление переменных, присваивание (=) и смена значения (00:23–02:47)

[+] Знак = в JS — оператор присваивания (запись справа налево), а не равенство. Тип данных определяется автоматически в момент записи (динамическая типизация).

```js
let message = 'Привет'; /* объявление + сразу запись начального значения */
console.log(message);   /* выведет: Привет */

message = 'Пока';       /* переопределяем значение (повторно let писать НЕ нужно!) */
console.log(message);   /* выведет: Пока */
```

## 2. Порядок объявления и разница var / let / const (02:48–05:57)

[!] До строки объявления к let и const обращаться нельзя. У устаревшего var вместо ошибки выведется undefined (и много скрытых багов — в современном коде var не берут). Разные переменные лучше писать каждую с новой строки, а одинаковые имена запрещены.

```js
/* Зона от начала блока {} до строки let/const — TDZ (Temporal Dead Zone, ReferenceError) */
/* console.log(title); -> ОШИБКА: Cannot access "title" before initialization */
let title = 'Новость';

/* let/const живут только внутри блока {}, а var игнорирует if/for и вытекает наружу! */
/* console.log(oldVar); -> undefined (опасное поведение старого var) */
var oldVar = 'Старый код';

const name = 'Александр'; /* const — по умолчанию, переназначить нельзя: */
/* const empty;        -> СИНТАКСИЧЕСКАЯ ОШИБКА: у const значение нужно задать сразу! */
/* name = 'Иван';      -> ОШИБКА: Assignment to constant variable */
/* const замораживает лишь привязку =, но свойства const-объекта менять можно! */
const admin = name;       /* копирование значения из одной переменной в другую */
/* const admin = 123;  -> ОШИБКА: Identifier "admin" has already been declared */
```

## 3. Строгий режим "use strict" (05:58–07:52)

[+] Без строгого режима неявная запись вроде age = 10 сработает без ошибки. Директива "use strict" в самом начале файла включает строгие правила ES5+ (отключить обратно в файле нельзя). Внутри ES-модулей (type="module") и классов (class) строгий режим включается автоматически сам, без этой строки.

```js
'use strict'; /* строго в начале JS-файла, в нижнем регистре, в любых кавычках */

/* age = 10; -> без "use strict" сработает, а со строгим режимом сразу ОШИБКА! */
const age = 10;
```

## 4. Правила именования переменных и регистр (07:53–09:09)

[+] В имени можно использовать буквы (лучше латиницу), цифры, символы $ и _. Запрещены зарезервированные слова языка (let, class, return и т.п. -> Unexpected token). Регистр имеет значение.

```js
const userName = 'Alex'; /* camelCase — стандарт для обычных переменных */
const $el = 1;           /* символы $ и _ разрешены */
const user2 = 2;         /* цифры внутри/в конце можно */
/* const 2user = 2;      -> СИНТАКСИЧЕСКАЯ ОШИБКА: начинать имя с цифры нельзя! */

const COLOR_RED = "#F00"; /* SCREAMING_SNAKE_CASE — для значений, известных ДО запуска */
/* А вычисляемые при запуске константы (например, время загрузки) пишут в camelCase! */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Обратиться к let/const до строки их объявления (Cannot access before initialization) или забыть "use strict" и случайно создать переменную без ключевого слова.

2. Попытаться перезаписать const (Assignment to constant variable) или повторно объявить переменную с тем же именем (Identifier has already been declared).

3. Начать имя переменной с цифры (2user) или взять зарезервированное слово (class, let).

# Урок 03. Типы данных, typeof, интерполяция строк и преобразование типов

Суть урока: В JS 8 типов данных (string, number, bigint, boolean, symbol, null, undefined и object); для подстановки в строки используют бэктики ${...}, тип узнают через typeof (typeof null === "object" — баг языка), а типы приводят через String(), Number(), Boolean().

## 1. Строки (string) и интерполяция в обратных кавычках (00:39–02:04)

[+] Одинарные ('...') и двойные ("...") кавычки равны, но переносы строк в них запрещены. Обратные кавычки (бэктики `...`) умеют и многострочность, и интерполяцию ${...} — вставку переменных и любых выражений внутрь строки.

```js
const greeting = 'Привет';
const name = 'Александр';
const message = `${greeting}, ${name}!`; /* интерполяция вместо склейки через + */
const a = 5, b = 10;
console.log(`Сумма a и b равна ${a + b}`); /* Сумма a и b равна 15 */
```

## 2. Числа (Number), NaN, Infinity и сверхбольшие BigInt (02:05–04:45)

[+] Тип number хранит целые и дробные числа. Безопасная точность — примерно до ±9 квадриллионов; для больших целых есть BigInt (суффикс n, смешивать с number нельзя). Разряды удобно разделять нижним подчёркиванием _ (на вычисления не влияет).

```js
console.log('текст' / 2); /* NaN (typeof NaN === 'number'!), заразен в операциях */
console.log(NaN === NaN); /* false! NaN не равен сам себе -> проверяют Number.isNaN() */
console.log(1 / 0);       /* Infinity; а -1 / 0 -> -Infinity */
console.log(0.1 + 0.2);   /* 0.30000000000000004 (дробная память IEEE 754) */

const bigNum = 9007199254740991n + 2n; /* BigInt: суффикс n обязателен у обоих чисел! */
const price = 1_000_000; /* подчёркивание _ для удобного чтения разрядов */
```

## 3. boolean, null, undefined, object и оператор typeof (04:46–08:28)

[+] Все типы кроме object — примитивы. null ставит сам разработчик («пока пусто»), а undefined значит «значение не присвоено» (вручную лучше ставить null). Оператор typeof возвращает тип в виде строки.

```js
const isChild = 11 < 18; /* boolean: true или false */
let userData = null;     /* null — намеренная пустота (например, до ответа сервера) */
let notAssigned;         /* undefined — переменная объявлена без значения */

console.log(typeof 100);       /* "number" */
console.log(typeof 100n);      /* "bigint" */
console.log(typeof undefined); /* "undefined" */
console.log(typeof null);      /* "object" — исторический БАГ языка JS! */
console.log(typeof [1, 2]);    /* "object" — массивы тоже объекты */
console.log(typeof alert);     /* "function" — спец. удобство typeof (на деле object) */
```

## 4. Неявное и явное преобразование типов (08:29–13:32)

[!] Оператор + со строкой склеивает в строку, а -, *, / пытаются превратить строки в числа — смешивать типы неявно считается плохой практикой. Надёжнее приводить явно через глобальные функции String(), Number() и Boolean().

```js
console.log(111 + '222');  /* '111222' (string) — при + число стало строкой */
console.log('16' / '8');   /* 2 (number) — деление превратило строки в числа */

console.log(String(11));   /* "11"; любой объект -> "[object Object]" */
console.log(Number('10')); /* 10; строка с буквой '10px' -> NaN */
console.log(Number('   '));/* 0! пробелы по краям обрезаются (пустая строка -> 0) */
console.log(Number(true), Number(false));      /* 1 и 0 */
console.log(Number(null), Number(undefined));  /* ВНИМАНИЕ: 0 и NaN! */

/* Все 8 Falsy-значений: false, 0, -0, 0n, "", null, undefined, NaN (иначе -> true) */
console.log(Boolean('0'), Boolean(' ')); /* true! непустая строка всегда true */
console.log(Boolean(0), Boolean(''));    /* false */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Думать, что typeof null вернёт "null" — всегда возвращает "object" (официальный баг JS); и не забывать скобки, проверяя выражение: typeof (1 + "2").

2. Ждать от Boolean("0") или Boolean(" ") значения false — любая строка даже с одним пробелом даёт true (false даёт только пустая строка "").

3. Путать Number(null) (даёт 0) и Number(undefined) (даёт NaN), а также складывать BigInt (10n) с обычным числом (5) без суффикса n.

# Урок 04. Арифметика, приоритет операторов, инкремент и сравнение

Суть урока: Унарный + превращает строку в число и срабатывает раньше бинарного +; разница между ++x (вернёт новое) и x++ (вернёт старое) видна при присваивании; строки сравниваются посимвольно по Unicode, а для равенства используют строгое === вместо ==.

## 1. Арифметические операторы, унарный + и приоритет (00:19–04:40)

[+] Бинарные операторы работают с двумя числами (ставят пробелы вокруг), а унарные — с одним (пишут слитно: -5, +"123"). Приоритет: скобки -> унарные -> ** -> * / -> + - -> =.

```js
console.log(2 ** 10); /* 1024 — возведение в степень */
console.log(13 % 5);  /* 3 — остаток от деления (проверка чётности: num % 2 === 0) */
console.log(-13 % 5); /* -3 — знак остатка всегда совпадает с левым числом! */

console.log('3' + '5');   /* '35' — бинарный + склеивает строки */
console.log(+'3' + +'5'); /* 8 — унарный + имеет более высокий приоритет и даёт числа */

const result = 1 + -2 - 3 * +'4' / 5 ** 2; /* -1.48: унарный -> ** -> * -> / -> + - -> = */
```

## 2. Операторы присваивания (+=) и инкремент / декремент (04:41–08:00)

[+] Сокращённые операторы (+=, -=, *=, /=) обновляют let-переменную. Инкремент (++) и декремент (--) меняют число на 1; отличие префикса от постфикса проявляется при записи.

```js
let count = 1;
count += 2; /* то же самое, что count = count + 2 (работает и со строками) */

let a = 10;
const prefix = ++a;  /* СНАЧАЛА увеличит a до 11, ПОТОМ запишет 11 в prefix */

let b = 10;
const postfix = b++; /* СНАЧАЛА запишет старое 10 в postfix, ПОТОМ увеличит b до 11 */
/* ++ и -- работают ТОЛЬКО с переменными! Запись (2 + 2)++ даст SyntaxError. */
```

## 3. Сравнение строк (Unicode) и строгое === против == (08:01–10:51)

[!] Операторы сравнения всегда дают boolean. Строки сравниваются посимвольно слева направо по кодам Unicode (кириллица > латиницы). Нестрогое == приводит типы (опасно!), поэтому в коде используют только строгое === и !==.

```js
console.log('JavaScript' > 'Java'); /* true — начало равно, дальше 'S' против пустоты */
console.log('а' > 'z');             /* true — кириллица в Unicode дальше латиницы */

console.log(2 == '2');  /* true — НЕСТРОГОЕ == само привело строку '2' к числу 2 */
console.log(2 === '2'); /* false — СТРОГОЕ === учитывает и значение, и тип данных */
console.log(3 !== '3'); /* true — строгое неравенство */

/* Загадка JS (разные алгоритмы у == и >/>=): */
console.log(null == undefined); /* true — при == они равны ТОЛЬКО друг другу */
console.log(null == 0, null > 0); /* false, false; но null >= 0 даст true (0 >= 0)! */
console.log('' == false);       /* true — оба приводятся к 0, поэтому всегда === ! */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Сложить две строки из полей ввода через "3" + "5" без унарного + или Number() — получите склейку "35" вместо математической суммы 8.

2. Написать const next = count++ и ждать уже увеличенного числа — постфиксный ++ сначала отдаёт старое значение (10), а увеличивает count потом.

3. Сравнивать значения через == вместо === (получая скрытое приведение типов) или сравнивать числа как строки (в строках "20" > "100" даст true, т.к. "2" > "1").

# Урок 05. Условия if/else, тернарный оператор, логические операторы и ??

Суть урока: if/else выбирает ветку кода, тернарный ? : записывает выбор в const; операторы || и && не превращают результат в true/false, а возвращают сам операнд (у && приоритет выше ||), а ?? реагирует только на null и undefined (сохраняя 0 и "").

## 1. Конструкция if / else if / else и тернарный оператор (00:24–05:22)

[+] Условие внутри (...) автоматически приводится к boolean; срабатывает только первая истинная ветка. Если цель — просто выбрать значение для const, удобнее тернарник ? :.

```js
const year = 2024;
if (year === 2024) {
  console.log('Ура!');
} else if (year === 3000) {
  console.log('Нейросети победили');
} else {
  console.log('Неизвестный год');
}

/* Тернарный оператор для выбора значения сразу при объявлении const: */
const message = year === 2024 ? 'Начинаем учиться' : 'Неизвестный год';

/* Совет (Explaining Variable): длинные условия лучше вынести в понятные переменные! */
/* const isAdult = age >= 18; -> if (isAdult && hasTicket) читается намного легче */
```

## 2. Операторы || (ИЛИ), && (И) и приоритет (05:23–09:42, 10:57–12:17)

[!] Логические || и && приводят к boolean только внутри себя для проверки, но всегда возвращают саму исходную сущность! Приоритет: оператор && выполняется раньше ||.

```js
/* || (ИЛИ) ищет ПЕРВЫЙ истинный (truthy) операнд, иначе возвращает ПОСЛЕДНИЙ: */
console.log(null || '' || 100); /* 100 — остановился на первом истинном значении */
console.log(0 || '' || false);  /* false — все ложные, вернул последний операнд */

/* && (И) ищет ПЕРВЫЙ ложный (falsy) операнд, иначе возвращает ПОСЛЕДНИЙ: */
console.log('Hi' && null && 10); /* null — остановился на первом ложном */
console.log('Hi' && 5 && 10);    /* 10 — все истинные, вернул последний */

/* Ленивое вычисление: правая часть даже не запустится, если исход уже ясен! */
/* false && alert('Не покажется');  |  true || alert('Не покажется'); */
/* Приоритет: ! выше &&, а && выше || ->  a || b && c  ===  a || (b && c) */
```

## 3. Логическое НЕ (!) и оператор нулевого слияния ?? (09:43–10:56, 12:18–13:55)

[+] Оператор ! сначала приводит значение к boolean, затем инвертирует в true/false (двойное !! — то же, что Boolean(x), но Boolean читается яснее). Оператор ?? проверяет строго на null и undefined, не ломая 0, "" и false.

```js
console.log(!'Привет');  /* false */
console.log(!!'Привет'); /* true (аналог Boolean('Привет')) */

/* Разница || и ?? на примере нуля (a = 0): */
const a = 0;
const b = 100;
console.log(a || b); /* 100 — || считает 0 ложным значением (falsy) и отбрасывает его! */
console.log(a ?? b); /* 0 — ?? считает 0 нормальным значением (не null и не undefined) */

/* Смешивать ?? с || или && без скобок ЗАПРЕЩЕНО (SyntaxError)! */
/* 1 && 2 ?? 3 -> ОШИБКА;  нужно явно: (1 && 2) ?? 3 */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Думать, что || и && возвращают true/false — они всегда возвращают исходное значение одного из операндов (например, 0 || 100 вернёт 100, а "a" && null вернёт null).

2. Ставить || вместо ?? для значений по умолчанию, когда 0, "" или false допустимы (например, количество товара или скидка 0 исчезнет при ||).

3. Забывать, что && срабатывает раньше || (лучше ставить явные круглые скобки), и писать if (cond) ... без фигурных скобок или длинные вложенные тернарники.

# Урок 06. Функции alert, prompt, confirm и конструкция switch / case

Суть урока: Модалки alert(), prompt() и confirm() ставят код на паузу (prompt отдаёт строку или null при отмене, confirm — true/false); в switch/case без break после совпадения выполняются все следующие ветки подряд.

## 1. Модальные окна браузера: alert, prompt и confirm (00:25–05:40)

[+] Все три функции останавливают выполнение JS до закрытия окна. В продакшене их не используют (окно нельзя стилизовать), но они удобны в обучении и быстрых тестах.

```js
alert('Привет'); /* выводит только 1-й аргумент, приводя его к строке */

/* prompt(вопрос, значениеПоУмолчанию) -> возвращает строку или null при Cancel/Esc: */
const rawAge = prompt('Сколько тебе лет?', 18);
/* Совет: задавайте 2-й аргумент ("") — в старом IE без него в поле писалось "undefined"; */
/* отмену проверяйте явно: if (rawAge === null) ... (пустой OK даст "", а +"" === 0!) */
const userAge = +rawAge; /* если нужно число, приводим! Но +null === 0! */

/* confirm(вопрос) -> две кнопки (OK и Cancel), всегда возвращает boolean: */
const isUserReady = confirm('Готов начать?'); /* OK -> true, Cancel/Esc -> false */
```

## 2. Конструкция switch / case и зачем нужен break (05:41–08:29)

[!] switch сравнивает значение в (...) с каждым case. Если в конце case забыть break, JS «провалится» и выполнит все следующие ветки подряд, даже не проверяя их условия!

```js
const age = +prompt('Ваш возраст?', '');
/* ВНИМАНИЕ: в switch сравнение СТРОГОЕ (===)! Строка "0" НЕ совпадёт с case 0! */

/* Вариант 1 — точное совпадение (и группировка нескольких case без break): */
switch (age) {
  case 0:
    console.log('Такого возраста не бывает');
    break; /* обязателен, иначе провалится в следующий case! */
  case 1:
  case 2:
    console.log('Один или два года');
    break;
  case 18:
    console.log('Не верю, покажи паспорт');
    break;
  default:
    /* Если поставить default в середине без break, он провалится в следующий case! */
    console.log(`Твой возраст: ${age}`); /* сработает, если ничего не подошло */
}

/* Вариант 2 — проверка диапазонов/условий через switch (true): */
switch (true) {
  case age < 1: console.log('Малыш'); break;
  case age > 125: console.log('Вампир?'); break;
}
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть, что prompt() возвращает строку (введённый "0" не равен числу 0 без + или Number), а нажатие Cancel / Esc возвращает null (и +null превратится в 0!).

2. Пропустить break внутри case в switch — после первого совпадения выполнятся все нижестоящие case и даже блок default.

3. Передать в alert(a, b) несколько аргументов как в console.log — alert покажет только первый и заморозит весь JS-код до нажатия ОК.

# Урок 07. Циклы while, do..while и for, break, continue и область видимости

Суть урока: while проверяет условие ДО тела (0+ раз), do..while — ПОСЛЕ тела (минимум 1 раз), а for собирает старт, условие и шаг в скобках; переменные внутри цикла видны только внутри него, break завершает весь цикл, а continue пропускает только текущий шаг.

## 1. Циклы while, do..while и риск бесконечного цикла (00:15–04:30)

[!] В реальных проектах while применяют осторожно: если забыть обновить счётчик (count++), условие всегда будет true — вкладка браузера уйдёт в бесконечный цикл и съест всю оперативную память.

```js
let count = 0;
while (count < 10) {
  console.log(count); /* выведет 0..9 */
  count++;            /* без этой строки цикл станет БЕСКОНЕЧНЫМ! */
}

/* do..while выполнит тело минимум 1 раз, даже если условие с самого начала false: */
let n = 100;
do {
  console.log(n); /* выполнится 1 раз и выведет 100 */
  n++;
} while (n < 10);
```

## 2. Цикл for, порядок шагов и область видимости (04:31–08:49)

[+] for (начало; условие; шаг): «начало» запускается 1 раз, «условие» проверяется перед каждым шагом, а «шаг» — после тела. Любую часть можно пропустить, оставив обе ;. Код после цикла ждёт его полного завершения.

```js
for (let i = 0; i < 4; i++) {
  const message = `Шаг ${i}`; /* видна ТОЛЬКО внутри фигурных скобок цикла */
  console.log(message);
}
/* console.log(i); -> ОШИБКА: ReferenceError: i is not defined (вне области видимости) */

/* Пропуск частей внутри for (две точки с запятой обязательны!): */
let k = 0;
for (; k < 3; ) { console.log(k); k++; } /* по сути то же, что while (k < 3) */

/* Нюанс (let vs var в for): при let на КАЖДЫЙ шаг создаётся своя переменная i (для */
/* таймеров/колбэков сохранит 0, 1, 2), а var делит одну переменную на все шаги (3, 3, 3) */
```

## 3. Досрочный выход break и пропуск итерации continue (08:50–10:37)

[+] break мгновенно прекращает весь цикл, а continue обрывает только текущий шаг и переходит к следующей итерации (удобно для фильтрации прямо внутри цикла).

```js
for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) continue; /* чётные пропускаем — сразу идём к следующему i */
  if (i > 7) break;          /* выходим из цикла полностью после числа 7 */
  console.log(i);            /* выведет только: 1, 3, 5, 7 */
}

/* Метка (label:) нужна, чтобы break/continue выходил сразу из внешнего вложенного цикла: */
outer: for (let y = 0; y < 3; y++) {
  for (let x = 0; x < 3; x++) { if (y === 1 && x === 1) break outer; }
}
/* НЕЛЬЗЯ писать break/continue справа от ? : (например, cond ? log() : continue -> Error) */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть шаг изменения счётчика в while (или написать условие всегда true) — получите бесконечный цикл и зависание браузера.

2. Пытаться прочитать счётчик let i или переменную из тела цикла после } — будет ReferenceError (они живут только внутри блока цикла).

3. Перепутать break (обрывает весь цикл) и continue (пропускает лишь 1 шаг) или не учесть, что while без единого выполнения пропустит тело при false, а do..while — нет.

# Урок 08. Функции: объявление, область видимости, параметры и return

Суть урока: Функция (Function Declaration) выполняется только в момент вызова name(), имеет локальную область видимости {}, принимает аргументы по порядку (дефолтные параметры ставят последними) и всегда возвращает результат (или undefined без return).

## 1. Объявление функции и область видимости (00:15–06:38)

[+] Любые фигурные скобки {} (функция, цикл или отдельный блок) создают локальную область видимости: изнутри видно внешние переменные, а снаружи внутренние — нет. Локальное имя перекрывает глобальное только внутри своего блока.

```js
const message = 'Глобальный привет';

function logMessage() { /* при объявлении код внутри НЕ выполняется */
  const message = 'Локальный привет'; /* затеняет глобальную только здесь */
  const innerOnly = 'Секрет';
  console.log(message); /* "Локальный привет" */
}

logMessage();         /* запуск кода функции */
/* Hoisting: Function Declaration всплывает и её можно вызывать даже ДО строки объявления! */
console.log(message); /* "Глобальный привет" */
/* console.log(innerOnly); -> ReferenceError: innerOnly is not defined */
```

## 2. Параметры, аргументы и значения по умолчанию (06:39–13:33)

[+] Параметры в (...) при объявлении ведут себя как локальные let-переменные, а при вызове в них по порядку попадают аргументы. Хороший стиль: не менять сам параметр внутри тела и ставить необязательные параметры по умолчанию в конец списка.

```js
function repeatMessage(text = 'Мяу', count = 1) { /* значения по умолчанию */
  for (let i = 0; i < count; i++) {
    console.log(text);
  }
}

repeatMessage('Привет', 3);       /* text = 'Привет', count = 3 */
repeatMessage('Привет');          /* count станет 1 (по умолчанию) */
repeatMessage(undefined, 2);      /* пропуск 1-го аргумента — сработает "Мяу" */
/* Дефолт сработает ТОЛЬКО при undefined (null, 0 и "" его НЕ включают)! */
/* Выражение по умолчанию (напр. text = getTitle()) вычисляется заново в момент вызова! */
```

## 3. Возврат значения (return) и ранний выход (13:34–19:04)

[+] Инструкция return вычисляет выражение, отдаёт его наружу и сразу завершает функцию (код ниже return не сработает). Если return нет или он пустой — вернётся undefined. Удобно для раннего выхода при проверках на старте функции.

```js
function getAgeType(age) {
  if (typeof age !== 'number') return 'Возраст указан некорректно';
  if (age < 1 || age > 125)    return 'Такого возраста не может быть';
  if (age < 18)                return 'Несовершеннолетний';
  return 'Взрослый'; /* сработает, только если все проверки выше не вышли */
}

function getSecretMessage(name) {
  if (!name) return; /* пустой return досрочно вернёт undefined */
  return `Секрет для ${name}`;
}

/* Ловушка ASI: после return перенос строки вернёт undefined! Если переносим итог, */
/* открывающую скобку ставят на той же строке: return ( ... ); */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Указать параметры по умолчанию в начале списка (придётся передавать undefined для пропуска) или забыть передать нужный аргумент (параметр станет undefined).

2. Забыть return (функция вернёт undefined) или написать инструкции после return (после возврата функция останавливается, и нижний код мёртв).

3. Пытаться прочитать переменную, объявленную внутри {}, снаружи функции, либо перезаписывать входной параметр напрямую вместо новой локальной переменной.

# Урок 09. Виды функций, стрелочные функции, колбэки и именование

Суть урока: В JS 3 вида функций — Function Declaration (всплывает и перезаписывается), Function Expression (в переменной) и Arrow Function (короткая, без arguments и своего this); функции передают без () как колбэки, возвращают из функций и называют с глагола.

## 1. Виды функций: Declaration, Expression и стрелочные (00:17–07:05)

[+] Function Declaration всплывает наверх области видимости (можно вызывать раньше, но дубликат имени молча перезапишет первую функцию). Expression и стрелки нельзя вызвать до объявления; у стрелок нет arguments и своего this (берётся из внешнего кода).

```js
/* 1) Function Declaration — всплывает (hoisting), есть arguments и свой this: */
console.log(sum(2, 3)); /* 5 — работает даже ДО строки объявления! */
function sum(a, b) { return a + b; }
/* В строгом режиме ("use strict") Function Declaration внутри блока if видна лишь в нём! */

/* 2) Function Expression — в const, до объявления недоступна, нельзя перезаписать: */
const logHello = function() { console.log('Привет'); };
/* NFE (с внутренним именем): const fn = function self() { /* self видно лишь внутри */ }; */

/* 3) Arrow Function (стрелочная) — в 1 строку без {} делает НЕЯВНЫЙ return: */
const multiply = (a, b) => a * b; /* короткий возврат a * b */
const double = x => x * 2;        /* 1 параметр можно писать без скобок (x) */
const makeObj = id => ({ id });   /* возврат объекта из 1 строки ОБЯЗАТЕЛЬНО в ({ ... })! */
```

## 2. Функция как значение, колбэки и возврат функции (07:06–11:48)

[!] Имя функции без () возвращает саму функцию (её можно скопировать в другую переменную или передать аргументом — это колбэк). Ставить () при передаче колбэка нельзя: иначе он выполнится сразу и передаст внутрь undefined.

```js
const logMessage = (actionBefore, actionAfter) => {
  actionBefore();
  console.log('Привет');
  actionAfter();
};
logMessage(() => console.log('before'), () => console.log('after')); /* без () */
/* ОШИБКА: logMessage(console.log('before'), ...) -> actionBefore is not a function! */

/* Функция может возвращать другую функцию: */
const validate = (hasAccess) => hasAccess
  ? () => console.log('Доступ разрешён')
  : () => console.log('Доступ запрещён');
const showStatus = validate(true); /* сохранили вернувшуюся функцию */
showStatus();                      /* "Доступ разрешён" */
```

## 3. Как правильно называть функции и принцип 1 действия (11:49–14:21)

[+] Функции нужны не только для повтора кода, но и для простого чтения (спрятать пачку инструкций под именем showMenu). Имя — почти всегда глагол + существительное: get..., set..., create..., update..., delete..., show..., hide..., check..., calc....

```js
/* Правило «1 функция = 1 сценарий» (без скрытых побочных эффектов): */
const getPi = () => 3.14; /* getPi должна ТОЛЬКО вернуть число, не вызывать alert()! */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Вызывать Function Expression или стрелочную функцию до строки объявления — они не поднимаются готовыми как Function Declaration (будет ошибка TDZ).

2. Передать колбэк со скобками () внутри аргументов — функция сработает мгновенно, а вместо колбэка внутрь попадёт undefined (ошибка is not a function).

3. Ждать объект arguments внутри стрелочной функции (у стрелок его нет) или смешивать несколько несвязанных действий внутри одной функции.

# Урок 10. Объекты (Часть 1): свойства, методы, delete, in и for..in

Суть урока: Объект { key: value } хранит данные под строковыми ключами; читают свойства через точку или [...], содержимое const-объекта можно менять и удалять через delete, наличие проверяют оператором in, а ключи перебирают циклом for..in.

## 1. Создание объекта, доступ к свойствам и методы (00:23–04:14)

[+] Ключ объекта — всегда строка (если в имени пробел или дефис, нужны кавычки и доступ через ["..."]). Функции внутри объекта называются методами. Обращение к несуществующему ключу возвращает undefined без ошибки.

```js
const user = {
  name: 'Александр',
  age: 28,
  'registration date': '01.01.2024', /* имя с пробелом — обязательно в кавычках */
  sayHi: () => console.log('Привет'), /* метод объекта (висячая запятая допустима) */
};

console.log(user.name);                  /* "Александр" */
console.log(user['registration date']);  /* доступ через [] из-за пробела */
user.sayHi();                            /* вызов метода */
console.log(user.missingProp);           /* undefined */
console.log(user.address?.street);       /* ?. защитит от TypeError, если address нет */
```

## 2. Добавление, изменение, удаление delete и const-объект (04:15–07:03)

[!] const защищает лишь саму переменную от перезаписи (=), но не содержимое объекта: свойства внутри можно добавлять, менять и удалять оператором delete.

```js
const profile = {};
profile.name = 'Александр';        /* добавили свойство */
profile['is developer'] = true;    /* добавили свойство с пробелом */
profile.name = 'Максим';           /* изменили существующее */

delete profile.name;               /* удалили свойство (несуществующее ошибки не даст) */
delete profile['is developer'];
/* profile = {}; -> ОШИБКА: Assignment to constant variable (саму переменную менять нельзя) */
```

## 3. Короткая запись, вычисляемые свойства [key] и имена ключей (07:04–10:42)

[+] Если имя ключа и переменной совпадают — пишут { name, age }. В ключах объекта можно брать зарезервированные слова (let, return), а числа становятся строками. Имя свойства из переменной берётся в квадратные скобки [propName].

```js
const name = 'Александр', age = 28;
const shortUser = { name, age }; /* короткая запись вместо { name: name, age: age } */

const propName = 'city';
const propValue = 'Москва';
const obj = { [propName]: propValue }; /* вычисляемое имя -> { city: "Москва" } */
/* Без [] получилось бы буквальное имя ключа "propName"! */
/* Ключ __proto__ особый: obj.__proto__ = 5 не станет числом 5 (проигнорируется!). */
```

## 4. Оператор in, перебор for..in и порядок свойств (10:43–15:16)

[+] Оператор "key" in obj надёжнее сравнения с undefined (если в самом свойстве лежит undefined). В цикле for..in перебираются ключи; причём целочисленные ключи всегда идут первыми по возрастанию, а остальные — в порядке добавления.

```js
const testObj = { status: undefined };
console.log('status' in testObj);        /* true — ключ реально есть в объекте! */
console.log(testObj.status !== undefined); /* false — обманет, если значение undefined */
console.log('toString' in testObj);      /* true! видит и методы прототипа объекта */
console.log(Object.hasOwn(testObj, 'toString')); /* false — проверяет ТОЛЬКО свои ключи */

const nums = { 2: 'второй', 1: 'первый', 3: 'третий', name: 'Алекс' };
for (const key in nums) {
  /* ВНИМАНИЕ: значение берут через nums[key], а НЕ nums.key! */

/* Трюк порядка: ключи "+49", "+41" нецелочисленные и сохранят порядок добавления! */
```

# Урок 11. Объекты (Часть 2): ссылки, копирование, ?. и деструктуризация

Суть урока: Объекты хранятся по ссылке (даже {} === {} даёт false); поверхностно их копируют и объединяют через { ...obj } или Object.assign, от падения на вложенных свойствах спасает ?. + ??, а поля извлекают деструктуризацией с ...rest в конце.

## 1. Ссылочный тип и рекурсивное сравнение объектов (00:24–08:50)

[!] Переменная хранит не сам объект, а ссылку на место в памяти. Сравнение {} === {} всегда false, а const b = a копирует лишь ссылку. Чтобы сравнить содержимое вглубь, проверяют число ключей (Object.keys) и рекурсивно обходят вложенные объекты.

```js
console.log({} === {}); /* false — два разных участка памяти */
const obj1 = { name: "Alex" }; const obj2 = obj1; /* одна ссылка! */

const areObjectsEqual = (object1, object2) => {
  const keys1 = Object.keys(object1);
  const keys2 = Object.keys(object2);
  if (keys1.length !== keys2.length) return false;

  for (const key in object1) {
    const value1 = object1[key];
    const value2 = object2[key];
    const areObjects = value1 !== null && value2 !== null
      && typeof value1 === 'object' && typeof value2 === 'object';
    if (areObjects) {
      if (!areObjectsEqual(value1, value2)) return false; /* не прерывать на 1-м true! */
      continue;
    }
    if (value1 !== value2) return false;
  }
  return true;
};
```

## 2. Копирование, объединение и опциональная цепочка ?. (08:51–19:05)

[+] Поверхностную копию и слияние делают через Object.assign({}, ...) или спред { ...obj1, ...obj2 } (одинаковые поля перезапишет последний). Вложенные объекты при этом НЕ клонируются! Оператор ?. в связке с ?? защищает от падения на undefined/null.

```js
const a = { name: 'Alex', addr: { city: 'Москва' } };
const b = { age: 28 };
const copy = { ...a };                  /* поверхностная копия (addr общий по ссылке!) */
const merged = Object.assign({}, a, b); /* или { ...a, ...b }; дубли затрёт правый */
const deepCopy = structuredClone(a);    /* нативное ГЛУБОКОЕ клонирование (без функций) */

/* Безопасное чтение вложенных данных (например, пришедших с сервера): */
const dateTo = guest.orderInfo?.stayDates?.to ?? 'Не указана'; /* вместо TypeError */
```

## 3. Деструктуризация, переименование, дефолт и ...rest (19:06–29:10)

[+] Деструктуризация извлекает нужные свойства в переменные (удобно и в параметрах функции, когда аргументов больше 2–3). Если нужно переименование И значение по умолчанию — сначала : новоеИмя, потом = дефолт. Остаточный ...rest всегда последний!

```js
const user = { name: 'Alex', age: 28, company: 'VK', role: 'Front' };

/* Переименование (name -> userName), дефолт для city и сбор остатка в ...otherInfo: */
const { name: userName, city: userCity = 'Не указано', ...otherInfo } = user;
/* otherInfo === { company: "VK", role: "Front" }; ...rest ОБЯЗАН быть последним! */

/* Деструктуризация в параметрах (= {} защитит от вызова без аргумента) и вложенная: */
/* const { addr: { city } = {} } = a; -> достанет city, а переменная addr не создастся */
const logAddress = ({ city, street, house = 1 } = {}) => console.log(city, street, house);
logAddress({ street: 'Пушкина', city: 'Москва', house: 10 });
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Написать const copy = obj и менять свойства в copy — так вы скопировали ссылку, и исходный obj тоже изменится.

2. Ждать от { ...obj } или Object.assign({}, obj) глубокого копирования — вложенные объекты и массивы остаются общими ссылками.

3. Перепутать порядок в { city: userCity = "Нет" } (сначала двоеточие, затем =) или поставить ...rest не в самый конец (ошибка Rest element must be last element).

# Урок 12. Ключевое слово this в объектах и функциях, чейнинг методов

Суть урока: Значение this зависит от способа вызова (объект слева от точки); обычный и сокращённый методы берут контекст этого объекта, стрелочная функция своего this не имеет (берёт внешний), а return this в методах открывает цепочку вызовов (chaining).

## 1. Контекст this глобально, в объекте и вложенных объектах (00:22–02:41)

[+] В браузере вне объекта (без use strict) this ссылается на window. В методе объекта this — сам объект перед точкой: для вложенного address.fn() это именно address.

```js
console.log(this); /* глобально -> Window; а в обычной функции с "use strict" -> undefined! */

const user = {
  name: 'Александр',
  logThis() { console.log(this, this.name); }, /* this === user */
  address: {
    city: 'Москва',
    logInnerThis() { console.log(this); },     /* this === user.address (не user!) */
  },
};
user.logThis();              /* { name: "Александр", ... }, "Александр" */
user.address.logInnerThis(); /* { city: "Москва", ... } */
```

## 2. Стрелочные функции и динамический this (02:42–06:25)

[!] У стрелочной функции нет своего this — она берёт внешний контекст (в методе объекта даст Window!). Обычная же функция вычисляет this в момент вызова: кто слева от точки, тот и this.

```js
const arrowObj = {
  name: 'Alex',
  logThis: () => console.log(this), /* ВНИМАНИЕ: Window вместо arrowObj! */
};

function logInfo() { console.log(this.name); }
const user1 = { name: 'Миша', logName: logInfo };
const user2 = { name: 'Вася', logName: logInfo };

logInfo();       /* '' (window.name по умолчанию пустой) */
user1.logName(); /* 'Миша' — слева от точки user1 */
user2.logName(); /* 'Вася' — слева от точки user2 */

/* Зато ВНУТРИ обычного метода стрелка спасает this в колбэках (forEach / setTimeout): */
/* setTimeout(() => this.logName(), 1000); -> this берётся из родительского метода! */

/* Потеря контекста и явная привязка (call / apply / bind): */
const detached = user1.logName; /* оторвали от user1: detached() потеряет this! */
logInfo.call(user1);            /* вызывает СРАЗУ с this = user1 (аргументы через ,) */
logInfo.apply(user1, []);       /* вызывает СРАЗУ с this = user1 (аргументы массивом) */
const boundFn = user1.logName.bind(user1); /* НЕ вызывает — возвращает копию с this */
```

## 3. Практика: calculator и цепочка вызовов ladder (06:26–14:11)

[+] Методы могут динамически добавлять поля в this (this.a = ...), а если каждый метод завершать return this;, то вызовы можно выстраивать в одну цепочку (chaining).

```js
const calculator = {
  read() {
    this.a = Number(prompt('Первое число:', 0));
    this.b = Number(prompt('Второе число:', 0));
  },
  sum() { return this.a + this.b; },
  mul() { return this.a * this.b; },
};

const ladder = {
  step: 0,
  up()       { this.step++; return this; }, /* return this возвращает сам ladder */
  down()     { this.step--; return this; },
  showStep() { console.log(`Ступенька: ${this.step}`); return this; },
};
ladder.up().up().down().showStep(); /* Ступенька: 1 (без return this упало бы!) */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Писать метод объекта через стрелку () => this.name — у стрелки нет своего this, и она уйдёт наружу в window (правильно: method() {} или function() {}).

2. Ждать во вложенном методе user.address.log() доступ к user через this — контекст всегда равен объекту непосредственно перед точкой (address).

3. Вызывать методы цепочкой ladder.up().down() без return this; — по умолчанию метод вернёт undefined, и следующий вызов через точку упадёт с TypeError.

# Урок 13. Методы примитивов, числа, Math, округление и парсинг строк

Суть урока: Примитивы получают методы через временный объект-обёртку; toFixed() и toPrecision() возвращают строку, объект Math даёт random, min/max (...arr) и 4 способа округления (round, floor, ceil, trunc), а "100.5px" парсят через parseInt / parseFloat.

## 1. Методы примитивов и чисел: toFixed, toPrecision, toString (00:26–05:24)

[+] При вызове метода у числа JS на миг создаёт временный объект-обёртку, выполняет метод и сразу удаляет её. У целых чисел напрямую метод вызывают через две точки (..), у дробных — в скобках.

```js
const price = 99.984;
console.log(price.toFixed(2));     /* '99.98' (СТРОКА! без аргумента -> 0 знаков) */
console.log((100).toFixed(2));     /* '100.00' или 100..toFixed(2) — допишет нули */
console.log(price.toPrecision(4)); /* '99.98' — 4 значащих цифры с начала числа */

const num = 255;
console.log(num.toString());       /* '255' */
console.log(num.toString(2));      /* '11111111' — система счисления от 2 до 36 */
/* У null и undefined НЕТ обёрток/методов (TypeError). НЕ пишите new Number(0) — в if */
/* объект всегда true! Подвох IEEE 754: (6.35).toFixed(1) === "6.3" (лечат Math.round). */
```

## 2. Объект Math и 4 способа округления чисел (05:25–08:36)

[+] Math хранит математические константы (Math.PI) и методы. В Math.min / Math.max массив передают только со спредом (...nums), иначе будет NaN.

```js
console.log(Math.random());          /* случайная дробь от 0 (вкл.) до 1 (не вкл.) */
const randInt = (min, max) => Math.floor(min + Math.random() * (max + 1 - min));
/* Случайное целое [min..max] с равной вероятностью (Math.round сбивает края в 2 раза!) */
console.log(Math.abs(-5));           /* 5 (модуль числа), Math.pow(2, 10) === 1024 */
console.log(Math.sqrt(16), Math.cbrt(27)); /* 4 (кв. корень) и 3 (куб. корень) */
const nums = [10, -5, 42];
console.log(Math.max(...nums));      /* 42 (без ... будет NaN!) */

/* 4 округления (пример на положительном 3.6 и отрицательном -3.6): */
Math.round(3.6);  /* 4  — к ближайшему целому (0.5 вверх) */
Math.floor(-3.6); /* -4 — всегда ВНИЗ ("пол") */
Math.ceil(-3.6);  /* -3 — всегда ВВЕРХ ("потолок") */
Math.trunc(-3.6); /* -3 — просто отрезает дробную часть без учёта знака */
```

## 3. Парсинг чисел из строк: parseInt и parseFloat (08:37–10:48)

[+] Обычный Number("100px") даст NaN, а parseInt / parseFloat считывают число слева направо до первого нечислового символа (пробелы в начале игнорируются).

```js
console.log(parseInt('100px'));     /* 100 — отбросил 'px' (2-й арг. — основание 2..36) */
console.log(parseInt('100.5px'));   /* 100 — точку считает остановкой */
console.log(parseFloat('100.5px')); /* 100.5 — читает и дробную часть */
console.log(parseInt('a100px'));    /* NaN — нечисловой символ стоит в самом начале! */

/* Строгие проверки чисел (НЕ приводят аргумент к числу, в отличие от глобальных!): */
console.log(Number.isNaN('str'));    /* false (глобальный isNaN('str') вернёт true!) */
console.log(Number.isFinite('123')); /* false (глобальный isFinite('123') вернёт true!) */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Ждать от price.toFixed(2) число для дальнейшей математики — метод возвращает строку (при сложении "10.00" + 5 выйдет строка "10.005").

2. Передать массив в Math.max(nums) без спреда ...nums (вернёт NaN) или путать Math.floor(-3.1) (-4) с Math.trunc(-3.1) (-3).

3. Ждать число от parseInt("$100") или parseFloat("px100") — если нецифровой символ идёт перед цифрами, парсинг сразу вернёт NaN.

# Урок 14. Строки и методы работы со строками

Суть урока: строки в JS неизменяемы (иммутабельны) — ни один метод не меняет исходную строку, а всегда возвращает новую строку (или число / boolean / массив).

## 1. Длина строки (length) и доступ к символам ([], at) (00:25 – 02:19)

```js
const word = 'Привет';
/* length — СВОЙСТВО (скобки () не ставим!). Пробелы тоже считаются за символы ('' -> 0). */
word.length;           // 6  |  '😀'.length -> 2 (эмодзи в UTF-16 занимает 2 единицы!)
[...'😀'].length;      // 1  (способ узнать реальное число символов со смайлами)
word[0];               // 'П' (индексы начинаются с 0)
word[-1];              // undefined (минус в [] НЕ работает!)
word[word.length - 1]; // 'т' (старый способ взять последний символ)
/* .at(индекс) — современный способ: понимает отрицательные индексы (считает с конца): */
word.at(-1);           // 'т' (последний символ)  |  word.at(-2) -> 'е'
/* Оба способа ТОЛЬКО для чтения: word[0] = 'Б' не сработает, а word.at(0) = 'Б' -> ошибка! */
```

## 2. Изменение регистра и обрезка пробелов (03:29 – 03:44)

## 3. Поиск в строке и 2-й аргумент (04:34 – 06:13)

```js

/* ВСЕ методы поиска чувствительны к регистру ('Мир' !== 'мир')! */

text.indexOf('мир') !== -1; // true (классическая проверка наличия через indexOf)
text.includes('мир');       // true (более удобная проверка есть/нет в современном JS)
text.startsWith('При');     // true (начинается ли строка с этого фрагмента)
text.endsWith('мир!');      // true (заканчивается ли строка этим фрагментом)
/* 2-й аргумент — стартовый индекс (indexOf/includes/startsWith) или длина (endsWith): */
text.includes('Привет', 1);    // false (ищем с 1-го индекса — буква 'П' на 0 позади)
text.startsWith('фронтенд', 8); // true (с индекса 8 начинается 'фронтенд')
text.endsWith('фронтенд', 16); // true  (обрезаем конец поиска до первых 16 символов)

/* Поиск ВСЕХ вхождений подстроки с помощью 2-го аргумента indexOf в цикле while: */

while (true) {
  const found = 'иа и иа'.indexOf('иа', pos);
  if (found === -1) break;
  console.log(found);  // Выведет: 0, затем 5

}
```

## 4. Получение подстроки: slice и substring (08:08 – 11:19)

## 7. Спецсимволы, перебор посимвольно и алфавитное сравнение

```js
/* 1. Спецсимволы (экранирование \): \n — перенос строки, \' и \" — кавычки. */
```

## 2. Доступ к элементам, разные типы, изменение, пустые ячейки и length (02:14 – 08:01)

```js
const mixed = [
  'Привет',                       // [0] строка
  100,                            // [1] число
  true,                           // [2] boolean
  { name: 'Александр' },          // [3] объект
  () => console.log('Хаха'),      // [4] функция
  [true, true, true],             // [5] вложенный массив
];
/* Как обращаться к разным типам внутри массива: */
mixed[0];      // 'Привет' (индексы всегда начинаются с 0)
mixed[3].name; // 'Александр' (достали объект по индексу [3], дальше через точку)
mixed[4]();    // Вызовет функцию -> 'Хаха' (достали функцию [4] и вызвали через ())
mixed[5][0];   // true (взяли 0-й элемент из вложенного массива на индексе [5])
/* Когда приходит undefined: если обратиться к несуществующему индексу или пустой ячейке: */
mixed[99];     // undefined (ошибки НЕ будет, как и при чтении лишнего ключа в объекте)

/* Изменение и добавление по большому индексу: */
/* const запрещает менять саму переменную (mixed = []), но элементы менять МОЖНО: */
mixed[1] = 200;     // Изменили существующий элемент на индексе 1
mixed[100] = 'Bay'; // Записали далеко за пределы длины -> length станет 101!
/* Ячейки с [6] по [99] останутся пустыми (<94 empty items>); при чтении дадут undefined.
   Так добавлять в конец НЕ надо — используй .push(). */

/* Длина и последний элемент: */
mixed[mixed.length - 1]; // Старый способ взять последний элемент
mixed.at(-1);            // Современный короткий способ (считает с конца!)
mixed.length = 0;        // [] — самый быстрый способ полностью очистить массив
```

## 3. Добавление и удаление: push, pop, unshift, shift — МУТИРУЮТ массив (09:36 – 11:27)

```js

```

## 4. Массив <-> Строка: toString, join, split — НЕ мутируют (12:51 – 14:19)


## 5. Копирование, slice и объединение — НЕ мутируют (15:32 – 18:42)

## 6. Сравнение массивов, перебор и проверка Array.isArray (19:29 – 22:34)

# Урок 17. Перебор объектов (keys/values/entries) и коллекции Map, Set

Суть урока: Object.keys/values/entries превращают объект в массив для удобной обработки методами массивов; Map — продвинутый словарь с ключами любого типа; Set — коллекция только уникальных значений.

## 1. Перебор объекта: for..in, Object.keys, Object.values, Object.entries (00:26 – 01:37)

```js
const user = { name: 'Александр', age: 28, city: 'Москва' };
/* Классический for..in перебирает имена ключей (значение получаем через user[key]): */
for (const key in user) { console.log(key, user[key]); }

/* Чтобы работать с объектом методами массивов (forEach, map, filter), получаем массивы: */

Object.values(user);  // ['Александр', 28, 'Москва']    — массив значений
Object.entries(user); // [['name','Александр'], ['age',28], ['city','Москва']] — массив пар

Object.entries(user).forEach(([key, value]) => console.log(key, value));
/* Все 3 метода возвращают НАСТОЯЩИЕ массивы и игнорируют скрытые ключи типа Symbol. */
```

## 3. Коллекция Map: зачем нужна и базовые методы (03:51 – 06:55)

```js
/* В обычном объекте {} все ключи становятся строками ({ 1: 'a', '1': 'b' } -> останется 'b').
   В Map ключом может быть ЛЮБОЙ тип (число 1 !== строка '1', boolean, даже целый объект!). */
const data = new Map([
  [1, 'Один как число'],     // Начальные пары можно передать массивом массивов (как entries)
  ['1', 'Один как строка'],
]);

/* Основные операции с Map (через [] напрямую к Map НЕ обращаются!): */
data.set('name', undefined); // Добавляет или перезаписывает пару (ключ, значение)
data.get(1);                 // 'Один как число' | data.get('1') -> 'Один как строка'
data.has('name');            // true — проверяет наличие САМОГО КЛЮЧА (даже если там undefined!)
data.size;                   // 3 — СВОЙСТВО (без скобок ()!), количество пар в коллекции
data.delete('name');         // Удаляет пару по ключу  |  data.clear() — полностью очищает Map

/* Объект в роли ключа + цепочка вызовов + сохранение порядка вставки + NaN: */
const john = { name: 'John' };
data.set(john, 123).set(NaN, 'не число'); // set возвращает сам Map -> можно писать цепочкой!
data.get(john); // 123 (ищет по ссылке на объект) | data.get(NaN) -> 'не число' (NaN === NaN!)
```

## 4. Перебор Map и преобразование Object <-> Map (07:11 – 08:30)

```js
/* Методы keys(), values(), entries() возвращают перебираемые объекты (итераторы, НЕ массивы!).
   Перебираем через for..of (или делаем массив через [...data.keys()]): */
for (const key of data.keys()) { console.log(key); }
for (const val of data.values()) { console.log(val); }
for (const [key, val] of data.entries()) { console.log(key, val); } // Или сразу: of data

/* ВАЖНО: в собственном data.forEach порядок параметров ИНОЙ, чем у массива и entries: */
data.forEach((value, key, map) => console.log(key, value)); // Сначала VALUE, потом KEY!

/* Преобразование Object <-> Map: */
const mapFromObj = new Map(Object.entries(user)); // Объект -> Map
const objFromMap = Object.fromEntries(data);      // Map -> Объект
/* Подвох: объект не хранит разные типы ключей (1 и '1' сольются, выживет последний!). */
```

## 5. Коллекция Set: уникальные значения, методы и перебор (09:05 – 10:41)

```js

   Дубликаты при передаче массива или добавлении через add() молча игнорируются! */

for (const val of set) { console.log(val); }
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Порядок параметров в map.forEach — первым аргументом идёт value, вторым key (не перепутай с [key, value] из entries!).

2. map.size — свойство, а не метод, и Map не читается через [] — пиши map.size без скобок (), а значения бери строго через map.get(key).

# Урок 19. Классы в JavaScript: constructor, get/set, #, static, extends и super

Суть урока: класс — это шаблон (чертёж) для создания однотипных объектов (экземпляров) через new и удобной организации кода (слайдеры, модалки, валидаторы).

## 1. Синтаксис class, constructor, свойства, методы и экземпляры (00:56 – 06:42)

```js
class Student {
  /* 1. Свойства в теле класса (без let/const!): если значение известно заранее для всех: */
  planet = 'Земля';
  region; // Без присвоения будет undefined

  /* 2. constructor — запускается АВТОМАТИЧЕСКИ при каждом вызове new Student(...): */
  constructor(name, age) {
    /* this указывает на конкретный создаваемый экземпляр (firstStudent или secondStudent): */
    this.name = name;
    this.age = age;
  }

  /* 3. Методы класса (пишутся без слова function): */
  logAge() {
    /* Внутри методов к свойствам экземпляра ОБЯЗАТЕЛЬНО обращаемся через this: */
    console.log(this.age); // Просто age даст ошибку: age is not defined!
  }

  /* 4. Потеря this в колбэках (setTimeout/клик): обычный метод потеряет this (undefined!).
     Стрелка в теле класса НАМЕРТВО привязывает this к экземпляру: */
  logAgeBound = () => console.log(this.age);
}

/* Под капотом: typeof Student === 'function'; класс не всплывает (TDZ), без new не вызвать,
   а внутри класса ВСЕГДА автоматически включён строгий режим ('use strict'). */
const firstStudent = new Student('Вася', 20);
const secondStudent = new Student('Петя', 22);
firstStudent.logAge(); // 20  |  secondStudent.name -> 'Петя'
```

## 2. Геттеры/сеттеры (get / set) и приватность: _ против # (06:43 – 13:57)

```js
/* Геттер (get) перехватывает чтение, сеттер (set) — запись, чтобы добавить свою логику.
   Внутри класса данные хранят в приватном поле, а снаружи работают через имя геттера/сеттера.
   - Префикс '_' (_city) — просто старое соглашение ('не трогай снаружи', но доступ открыт).
   - Префикс '#' (#city) — ЖЁСТКАЯ приватность: JS запретит доступ снаружи (выбросит ошибку)! */
class Profile {
  #city = null; // Приватное поле с # ОБЯЗАТЕЛЬНО объявить в теле класса заранее!

  constructor(city) {
    this.city = city;        // Вызовет сеттер set city()
    this.#someSecretAction(); // Вызвать приватный метод # внутри класса — можно
  }

  set city(value) { // Срабатывает при присвоении: profile.city = 'москва'
    const firstLetter = value[0].toUpperCase();
    const restLetters = value.slice(1).toLowerCase();
    this.#city = `${firstLetter}${restLetters}`; // 'Москва'
  }

  get city() {      // Срабатывает при чтении: profile.city (вызывается БЕЗ скобок ()!)
    return `г. ${this.#city}`;
  }

  #someSecretAction() { /* Скрытый внутренний метод */ }
}
const p = new Profile('москва');
p.city; // 'г. Москва'  |  p.#city или p.#someSecretAction() снаружи -> SyntaxError!
/* Важно: #поля и #методы скрыты даже от дочерних классов-наследников (доступ лишь в Profile). */
```

## 4. Наследование (extends), переопределение методов и super (15:19 – 21:11)

```js
class Person {
  constructor(name, age) { this.name = name; this.age = age; }
  eat()   { console.log(`${this.name} кушает`); }
  sleep() { console.log(`${this.name} спит`); }
}

/* extends наследует ВСЕ свойства и методы родителя Person (можно строить цепочки A -> B -> C): */
class Developer extends Person {
  /* Если переопределяем constructor у наследника — ПЕРВОЙ строкой ОБЯЗАТЕЛЕН super(...)! */
  constructor(name, age, experience) {
    super(name, age); // Вызывает constructor родителя Person (БЕЗ него this выдаст ошибку!)
    this.experience = experience;
  }

  writeCode() { console.log(`${this.name} пишет код`); } // Новый метод (у Person его нет)
  sleep()     { console.log('Не спит, кодит!'); }         // Полное переопределение sleep()

  eat() { // Расширение родительского метода без копирования его кода:
    super.eat(); // Вызывает eat() из Person
    console.log('...и смотрит уроки по JS');
  }
}
const dev = new Developer('Саша', 28, 5);
dev.eat(); // 'Саша кушает' -> '...и смотрит уроки по JS'
/* Оператор instanceof проверяет, принадлежит ли объект классу (и любому его родителю!): */
dev instanceof Developer; // true  |  dev instanceof Person -> тоже true!
```

# Урок 20. Таймеры в JavaScript: setTimeout, setInterval, clear и вложенный вызов

Суть урока: setTimeout запускает функцию один раз с задержкой в миллисекундах, setInterval повторяет её регулярно; для точной паузы после выполнения используют вложенный setTimeout.

## 1. Отложенный запуск (setTimeout), аргументы и отмена (clearTimeout) (00:24 – 04:01)

```js
/* 1-й аргумент — функция (стрелка или ссылка БЕЗ скобок ()!),
   2-й — задержка в миллисекундах (2000 мс = 2 сек; без 2-го аргумента по умолчанию 0),
   3-й и далее — аргументы, которые передадутся внутрь этой функции при срабатывании: */
function logMessage(name, age) {
  alert(`Привет, ${name}! Возраст: ${age}`);
}

/* Передаём logMessage по ссылке (если написать logMessage(), сработает сразу и без задержки!): */
const timerId = setTimeout(logMessage, 2000, 'Вася', 21);

/* setTimeout возвращает ID таймера. Чтобы отменить его ДО срабатывания -> clearTimeout: */
clearTimeout(timerId); // Отменили: окно alert через 2 секунды НЕ появится

/* Важно: 1) Не передавай код строкой: setTimeout('alert(1)', 1000) — устарело и опасно.
   2) Потеря this у методов: setTimeout(user.sayHi, 1000) потеряет объект user!
      Исправление: setTimeout(() => user.sayHi(), 1000) или user.sayHi.bind(user). */
```

## 2. Регулярный запуск — setInterval и clearInterval (04:04 – 05:50)

```js
/* Вывод в консоли будет: '1', '3', и ТОЛЬКО ПОТОМ '2'!
   1) Любой setTimeout сначала ждёт, пока выполнится весь текущий синхронный код ниже.
   2) По стандарту после 5 вложенных таймеров минимальная задержка браузера — не менее 4 мс.
   3) На свёрнутой (неактивной) вкладке браузер замедляет таймеры примерно до 1 сек (1000 мс). */
```

## 5. Как движок JS и браузер работают с таймером (под капотом)

1. Передача браузеру: сам JS время не считает и работает в 1 поток. Дойдя до setTimeout(fn, 2000), JS отдаёт fn и задержку браузеру и сразу идёт к следующим строкам.

2. Отсчёт на фоне: браузер отдельно отсчитывает 2000 мс, пока JS выполняет весь обычный код ниже.

3. Очередь ожидания: когда время вышло, браузер НЕ прерывает JS, а кладёт fn в очередь задач.

4. Запуск (Event Loop): только когда весь обычный код полностью закончился, Event Loop берёт fn из очереди и запускает её. Поэтому задержка в 2000 мс — минимальная, а не точная.

## 3 главные ловушки урока (чек-лист для повторения)

1. Круглые скобки в первом аргументе: setTimeout(fn(), 1000) — функция вызовется мгновенно без ожидания, а в таймер передастся undefined.

2. Ожидание, что setTimeout(..., 0) выполнится «тут же» — колбэк всё равно выполнится только ПОСЛЕ всех обычных строк кода ниже.

3. Наложение вызовов в setInterval — если операция внутри занимает больше времени, чем интервал (например, запрос на сервер), используй вложенный setTimeout.

# Урок 21. Обработка ошибок в JS: try, catch, finally и throw

Суть урока: try...catch ловит ошибки времени выполнения и не даёт скрипту упасть целиком; throw new Error() создаёт свою ошибку вручную, а finally выполняется всегда.

## 1. Конструкция try...catch: перехват ошибок (00:22 – 03:04)

```js
/* Без try...catch любая ошибка обрушит скрипт и код после неё не выполнится.
   В try пишем опасный код; в catch (error) — что делать, если возникла ошибка: */
console.log('Начало кода');

try {
  const names = undefined;
  names.forEach((n) => console.log(n)); // Здесь возникнет TypeError!
  console.log('Эта строка НЕ выполнится'); // При ошибке try сразу прерывается!
} catch (error) { // Параметр (error) опционален — если детали не нужны, можно просто catch {}
  console.log('Возникла ошибка:', error);
}

console.log('Конец кода'); // Выполнится в ЛЮБОМ случае — скрипт не упал!
```

## 2. Что try...catch НЕ ловит: синтаксис и асинхронный код (03:05 – 04:43)

```js
/* 1. ОШИБКИ ПАРСИНГА (SyntaxError в самом JS-коде):
   Если в файле есть невалидный JS (например, сломанная скобка), движок не сможет даже
   прочитать файл до запуска — весь скрипт не выполнится, try...catch не спасёт! */

/* 2. АСИНХРОННЫЙ КОД (например, setTimeout):
   Снаружи НЕ поймает, т.к. к срабатыванию таймера через 3 сек try...catch уже завершится: */
// try { setTimeout(() => noSuchFn(), 3000); } catch (e) {}  <- НЕ СРАБОТАЕТ!

/* ПРАВИЛЬНО — поместить try...catch ВНУТРЬ колбэка асинхронной функции: */
setTimeout(() => {
  try {
    noSuchFn();
  } catch (error) {
    console.log('Поймали ошибку внутри таймера!');
  }
}, 3000);
```

## 3. Объект ошибки error: свойства name, message и stack (04:44 – 06:02)

```js
try {
  JSON.parse('{ "age": 28, }'); // Ошибка JSON (висячая запятая)
} catch (error) {
  /* error — это объект с 3 главными свойствами: */
  console.log(error.name);    // Имя/тип ошибки: 'SyntaxError' (или TypeError, ReferenceError)
  console.log(error.message); // Пояснение: причина ошибки текстом
  console.log(error.stack);   // Стек вызовов: файл, строка, колонка и цепочка вызовов
}
```

## 4. Свои ошибки через throw и классы Error (06:03 – 09:47)

```js
/* Бывают ситуации, когда синтаксически всё чисто, но данных нет (логическая ошибка).
   Оператор throw ('бросить') вручную перебрасывает выполнение в catch: */
const userJson = '{ "age": 28 }'; // С сервера пришло без обязательного поля name!

try {
  const user = JSON.parse(userJson);
  if (!user.name) {
    /* Можно throw 'строка', но ПРАВИЛЬНО бросать экземпляр класса Error (или TypeError,
       SyntaxError, RangeError) — тогда у ошибки будут все 3 поля: name, message, stack! */
    throw new Error('Имя пользователя не заполнено');
  }
} catch (error) {
  console.log(error.name, error.message); // 'Error' 'Имя пользователя не заполнено'
}

/* Свой класс ошибки + Проброс неизвестной ошибки (Rethrowing): */
class ValidationError extends Error {
  constructor(message) { super(message); this.name = 'ValidationError'; }
}
try {
  throw new ValidationError('Неверный email');
} catch (err) {
  if (err instanceof ValidationError) { console.log(err.message); }
  else { throw err; } // Чужую/неизвестную ошибку (напр. опечатку) пробрасываем дальше!
}
```

## 5. Блок finally — выполняется при любом раскладе (09:48 – 10:30)

```js
try {
  console.log('Пробуем выполнить код...');
} catch (error) {
  console.log('Обработали ошибку:', error.message);
} finally {
  /* Опциональный блок: выполнится ВСЕГДА самым последним (даже перед return внутри try!).
     Можно писать и try...finally (без catch), если ошибку ловить не нужно, а уборку — надо. */
  console.log('Блок finally выполнился');
}

/* Глобальный перехват всех непойманных ошибок в браузере (для логов на сервер): */
window.onerror = (message, url, line, col, error) => console.log('Глобально:', message);
```

## 6. Смысл отлова ошибок: когда нужен, когда вреден и как всплывает

• Зачем нужен: это подушка безопасности, чтобы из-за сбоя (например, сервер прислал битый JSON) сайт не умер намертво, а показал понятное сообщение и продолжил работать.

• Когда применять: всегда на границе с «внешним миром» — fetch (сеть), JSON.parse, localStorage, доступ к камере/буферу обмена.

• Когда НЕЛЬЗЯ: не прячь в try...catch свои же ошибки в логике (опечатки, undefined) и не пиши пустой catch {} — свои баги чинят через if, ?. и ??.

• Всплытие по функциям: если funcA() вызвала funcB(), а ошибка упала внутри funcB(), она сама поднимется вверх к ближайшему try...catch вокруг funcA().

## 3 главные ловушки урока (чек-лист для повторения)

1. Оборачивать в try...catch сам setTimeout снаружи — ошибка внутри таймера возникнет позже, когда try...catch уже закончил работу (ставь try...catch внутри колбэка).

2. Ожидание, что try продолжится после ошибки или спасёт от опечатки — после ошибки внутри try строки ниже не выполнятся, а синтаксический брак не даст файлу даже запуститься.

3. Бросать строку throw "текст" вместо throw new Error("текст") — без new Error(...) в catch не будет свойств name, message и стека вызовов stack.

# Урок 22. Асинхронный JS: Event Loop, колбэки, Promise, async / await

Суть урока: Асинхронность позволяет запускать долгие задачи (таймеры, запросы на сервер) без заморозки остального кода; вместо вложенных колбэков (Callback Hell) используют Promise и синтаксис async / await.

## 1. Синхронный и асинхронный код (00:24–03:26)

[+] Движок V8 выполняет код в одном потоке (последовательно сверху вниз). Если задача занимает много времени синхронно, программа «зависает» до её завершения.

```js
/* Синхронный код: каждая строка ждёт завершения предыдущей */
console.log('Сообщение 1');
console.log('Сообщение 2');
console.log('Сообщение 3');

/* Асинхронная обёртка wait через setTimeout: основной код не блокируется */
const wait = (ms, callback) => {
  setTimeout(callback, ms);
};

console.log('Сообщение 1');
wait(5000, () => console.log('Сообщение 2')); /* выполнится через 5 секунд */
console.log('Сообщение 3');                  /* выведется сразу после 1 */

/* Вывод в консоли: "Сообщение 1" -> "Сообщение 3" -> (через 5 сек) "Сообщение 2" */
```

## 2. Событийный цикл (Event Loop) и очередь задач (03:29–05:40)

[+] Механизм событийного цикла позволяет JavaScript с одним потоком выполнения обрабатывать асинхронные операции: долгая задача уходит из основного потока, а её колбэк попадает в очередь задач и ждёт, пока основной поток освободится.

```js
console.log('Начало программы');

/* setTimeout регистрирует таймер вне основного потока и не тормозит код ниже */
setTimeout(() => {
  console.log('Асинхронная задача выполнена');
}, 2000);

console.log('Конец программы');

/* Порядок: 1) "Начало программы", 2) "Конец программы" — основной поток пуст,
   3) через 2 сек колбэк из очереди задач попадает в поток -> "Асинхронная задача..." */
```

[!] В Event Loop есть две разные очереди: микрозадачи (.then/.catch/.finally, код после await) и макрозадачи (setTimeout, клики). После синхронного кода движок сначала полностью очищает очередь микрозадач и только потом берёт 1 макрозадачу.

```js
console.log('1. Синхронный старт');
setTimeout(() => console.log('4. Макрозадача (таймер 0 мс)'), 0);
Promise.resolve().then(() => console.log('3. Микрозадача (Promise)'));
console.log('2. Синхронный финиш');

/* Итог: 1 -> 2 -> 3 (микрозадача обгоняет таймер!) -> 4 (макрозадача) */
```

## 3. Колбэки и «ад колбэков» — Callback Hell (05:43–09:57)

[!] Когда асинхронные запросы зависят друг от друга (данные второго запроса приходят из результата первого), вложенные колбэки быстро растут вправо и превращаются в нечитаемую «пирамиду» — Callback Hell.

```js
const makeRequest = (url, onSuccess) => { /* имитация запроса на сервер */ };
const sellerId = 154;

/* Задача: продавец -> его первый товар -> первый отзыв -> имя автора отзыва */
makeRequest(`/api/sellers/${sellerId}`, (seller) => {
  const firstProductId = seller.productIds[0];

  makeRequest(`/api/products/${firstProductId}`, (product) => {
    const firstReviewId = product.reviewsIds[0];

    makeRequest(`/api/reviews/${firstReviewId}`, (review) => {
      const authorName = review.author.name;
      console.log(authorName);
    });
  });
});
```

## 4. Промисы (Promise): 3 состояния, then, catch, finally (09:58–15:59)

[+] Promise — специальный объект-обёртка для асинхронного кода. У него всегда одно из 3 состояний, и перейти из pending в итог можно только 1 раз:

- pending (ожидание): исходное состояние в момент создания промиса;
- fulfilled (выполнено успешно): вызывается переданный колбэк fulfill / resolve;
- rejected (выполнено с ошибкой): вызывается переданный колбэк reject.

```js
/* В конструктор Promise передаётся функция-исполнитель с двумя колбэками */
const promise = new Promise((fulfill, reject) => {
  console.log('Начало, состояние pending...');

  setTimeout(() => {
    if (Math.random() > 0.5) {
      fulfill('Ура, состояние fulfilled!'); /* переводит промис в успех */
    } else {
      reject('Увы, состояние rejected!');   /* переводит промис в ошибку */
    }
  }, 3000);
});

/* Обработка результата: then (успех), catch (ошибка), finally (в любом случае) */
promise
  .then((successData) => {
    console.log('Успех:', successData);
  })
  .catch((errorData) => {
    console.log('Ошибка:', errorData);
  })
  .finally(() => {
    console.log('Выполняется всегда: и при успехе, и при ошибке');
  });

/* Альтернатива (менее наглядная): 2 аргумента в then — (onFulfilled, onRejected) */
promise.then(
  (successData) => console.log(successData),
  (errorData) => console.log(errorData)
);
```

[!] Вокруг функции-исполнителя new Promise(...) и внутри .then() работает невидимый try..catch: обычный throw сразу переводит промис в rejected. Но на отложенный throw внутри setTimeout он не действует — там нужен именно вызов reject(...).

```js
/* Синхронный throw ловится автоматически, как reject */
new Promise(() => {
  throw new Error('Синхронный сбой');
}).catch((err) => console.log(err.message)); /* "Синхронный сбой" */

/* ОШИБКА: throw внутри setTimeout вылетит мимо .catch в глобальную ошибку! */
new Promise((fulfill, reject) => {
  setTimeout(() => {
    reject(new Error('Правильный способ для таймера')); /* вместо throw */
  }, 500);
}).catch((err) => console.log(err.message));

/* Если у отклонённого промиса нет .catch(), в браузере сработает unhandledrejection */
```

## 5. Избавляемся от Callback Hell цепочкой .then().catch() (16:00–17:11)

[+] Если makeRequest возвращает Promise, вместо вложенной пирамиды пишем плоскую цепочку вызовов .then() с одним общим .catch() для отлова ошибок на любом шаге.

```js
const makeRequest = (url) => new Promise((fulfill) => {
  fulfill('результат с сервера');
});

makeRequest(`/api/sellers/${sellerId}`)
  .then((seller) => {
    const firstProductId = seller.productIds[0];
    return makeRequest(`/api/products/${firstProductId}`); /* возвращаем новый Promise */
  })
  .then((product) => {
    const firstReviewId = product.reviewsIds[0];
    return makeRequest(`/api/reviews/${firstReviewId}`);
  })
  .then((review) => {
    console.log(review.author.name);
  })
  .catch((error) => {
    console.log(error); /* поймает ошибку любого из запросов выше */
  });
```

[!] Подвох цепочки: каждый .then() возвращает новый промис. Если внутри .then() забыть слово return перед следующим промисом, цепочка разорвётся.

```js
makeRequest(`/api/sellers/${sellerId}`)
  .then((seller) => {
    makeRequest(`/api/products/${seller.productIds[0]}`); /* ЗАБЫЛИ return! */
  })
  .then((product) => {
    console.log(product); /* выведет undefined, не дожидаясь загрузки товара */
  });
```

## 6. async / await, top-level await и try / catch (17:12–23:50)

[+] Ключевое слово async перед функцией гарантирует, что она всегда вернёт Promise (даже если внутри return обычного значения). Оператор await ждёт завершения промиса и сразу достаёт из него результат.

```js
/* Обычное объявление и стрелочная функция (async пишется перед круглыми скобками) */
async function getSomething() {
  return 'Привет!'; /* JS автоматически обернёт строку в fulfilled Promise */
}
const getAsyncArrow = async () => {
  return new Promise((fulfill) => setTimeout(() => fulfill('Привет!'), 3000));
};

/* Не забываем скобки вызова getSomething(), иначе получим ошибку отсутствия .then */
getSomething().then((value) => console.log(value));

/* await без async снаружи даст SyntaxError (кроме <script type="module">) */
async function run() {
  console.log('Начало');
  const result = await getAsyncArrow(); /* ждёт 3 сек и достаёт строку, а не Promise */
  console.log(result);                  /* выведет "Привет!" только после ожидания */
  console.log('Конец');
}
run();
```

[+] Переписываем пример с маркетплейсом на async / await: код выглядит как обычный синхронный, а ошибки ловятся через try / catch.

```js
async function showFirstReviewAuthor(sellerId) {
  try {
    const seller = await makeRequest(`/api/sellers/${sellerId}`);
    const firstProductId = seller.productIds[0];

    const product = await makeRequest(`/api/products/${firstProductId}`);
    const firstReviewId = product.reviewsIds[0];

    const review = await makeRequest(`/api/reviews/${firstReviewId}`);
    console.log(review.author.name);
  } catch (error) {
    console.log(error);
  }
}
```

[!] Что делает await под капотом: он НЕ замораживает весь JavaScript и браузер. На паузу ставится только тело самой async-функции — внешний код сразу идёт дальше, а строки после await попадут в очередь микрозадач, когда промис завершится.

```js
async function testAwait() {
  console.log('2. Внутри функции до await'); /* выполнится синхронно */
  await Promise.resolve();                  /* пауза функции, хвост -> в микрозадачи */
  console.log('4. После await');             /* продолжение из очереди микрозадач */
}

console.log('1. До вызова');
testAwait();
console.log('3. Код снаружи не ждёт!');
/* Вывод строго: 1 -> 2 -> 3 -> 4 */
```

## 7. Параллельный запуск: Promise.all, Promise.allSettled, Promise.race

[+] Если запросы не зависят друг от друга, писать await подряд невыгодно — запросы будут ждать друг друга. Статические методы Promise запускают их одновременно:

```js
/* Promise.all: ждёт ВСЕ промисы. Если упадёт хотя бы один — весь all уйдёт в catch */
const [user, orders] = await Promise.all([
  makeRequest('/api/user'),
  makeRequest('/api/orders'),
]);

/* Promise.allSettled: ждёт ВСЕ, НЕ падает при ошибке, даёт статус каждого */
const results = await Promise.allSettled([
  Promise.resolve('ОК'),
  Promise.reject('Сбой'),
]);
/* results[0] -> { status: "fulfilled", value: "ОК" }
   results[1] -> { status: "rejected", reason: "Сбой" } */

/* Promise.race: возвращает результат (или ошибку) того, кто финишировал ПЕРВЫМ */
const fastest = await Promise.race([makeRequest('/mirror1'), makeRequest('/mirror2')]);
```

## 8. Связка с практикой: готовые промисы (fetch), циклы и шпаргалка выбора

[+] В реальной работе new Promise пишут редко — в 95% случаев ты получаешь уже готовый Promise от браузера или библиотеки (например, fetch). Конструктор new Promise нужен, чтобы обернуть старый callback-API (вроде setTimeout) под удобный await.

```js
/* Ручной new Promise нужен для обёртки колбэков ("промисификация" таймера) */
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

/* Готовый Promise от браузера (fetch): await распаковывает ответ и JSON */
async function loadPost(id) {
  await delay(500); /* пауза на полсекунды без блокировки интерфейса */
  const response = await fetch(`https://example.com/posts/${id}`);
  const data = await response.json(); /* response.json() тоже возвращает Promise */
  return data;
}
```

[!] Частый баг в циклах: forEach НЕ ждёт await — он запускает все колбэки сразу и уходит дальше. Для ожидания в цикле бери for..of (по очереди) или Promise.all + map.

```js
const ids = [1, 2, 3];

/* НЕПРАВИЛЬНО: forEach игнорирует async/await и не ждёт завершения запросов */
ids.forEach(async (id) => { await loadPost(id); });

/* ПРАВИЛЬНО (строго по очереди, один за другим): */
for (const id of ids) { await loadPost(id); }

/* ПРАВИЛЬНО (все 3 одновременно и ждём общий результат): */
const posts = await Promise.all(ids.map((id) => loadPost(id)));
```

[+] Короткая шпаргалка выбора инструмента:
- Пауза / отложенный код -> setTimeout или delay(ms) через new Promise.
- Запросы зависят друг от друга -> async / await + try / catch.
- Запросы независимы и важен каждый -> await Promise.all([...]).
- Запросы независимы, но сбой одного не должен ломать всё -> Promise.allSettled([...]).

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть await перед асинхронной функцией: в переменную запишется объект Promise {`<pending>`}, а не сами данные.

2. Использовать await в обычном `<script>` вне async-функции: движок выдаст SyntaxError (верхнеуровневый await работает только в `<script type="module">`).

3. Поставить await без try / catch или вызвать async-функцию без скобок (): отклонённый промис выбросит необработанное исключение, а без () у функции нет .then.

# Урок 23. Модули в JavaScript: декомпозиция, import и export

Суть урока: Модуль — это отдельный JS-файл со своей изолированной областью видимости; связи между такими файлами строят явно через export и import, а в HTML подключают один главный файл с атрибутом type="module".

## 1. Декомпозиция, рефакторинг и включение type="module" (00:26–06:55)

[+] Декомпозиция — разделение большого файла (например, script.js с табами, модалками и слайдерами) на отдельные файлы по задачам. Рефакторинг — улучшение структуры кода без изменения его поведения.

[!] Просто разрезать код на `<script src="...">` — ещё НЕ модули: все файлы сидят в одной глобальной области видимости, перезаписывают чужие переменные и падают с ReferenceError, если порядок тегов `<script>` перепутан. Атрибут type="module" изолирует каждый файл.

```html
<!-- Без type="module": общая область видимости, критичен порядок подключения -->
<script src="tabs.js"></script>
<script src="modals.js"></script>

<!-- С type="module": у каждого файла своя область видимости -->
<script src="tabs.js" type="module"></script>
<script src="modals.js" type="module"></script>
```

## 2. Именованный export и import, правила путей (06:55–10:52)

[+] Чтобы переменную или функцию модуля увидели другие файлы, её помечают ключевым словом export (сразу при объявлении или общим списком в конце файла) и подключают через import { ... } строго вверху принимающего файла.

```js
/* --- Файл tabs.js: способ 1 — export сразу при объявлении --- */
export const tabsSelectors = { root: '.tabs' };

/* --- Файл tabs.js: способ 2 — единый список в конце файла (чаще удобнее) --- */
const tabsSelectors = { root: '.tabs' };
const tabsData = [1, 2, 3];
export { tabsSelectors, tabsData };

/* --- Файл modals.js: импорт в самом начале файла --- */
import { tabsSelectors, tabsData } from './tabs.js';
/* Для браузерных JS-модулей обязательны "./" в начале и расширение ".js" в конце */
```

[!] Импортированная сущность — не копия, а «живая ссылка» (live binding) только для чтения. Если переменная поменяется внутри исходного файла, она обновится и у получателя, но напрямую перезаписать импорт снаружи нельзя (будет TypeError).

## 3. Конфликт имён и переименование через as (10:52–13:05)

[!] Если в двух модулях есть одинаковые имена (например, selectors и там, и там), при импорте возникнет конфликт. Сущность можно переименовать через as при экспорте или при импорте (при импорте — удобнее).

```js
/* Вариант 1: переименование при экспорте (только в списке в конце файла!) */
const selectors = {};
export { selectors as tabsSelectors }; /* нельзя: export const selectors as ... */

/* Вариант 2 (лучше): переименование при импорте в файле-получателе */
import { selectors as tabsSelectors } from './tabs.js';
const selectors = {}; /* локальная переменная этого файла больше не конфликтует */
```

## 4. Точка входа script.js и export default (13:05–18:38)

[+] Модули не должны запускать себя сами — вызовы init-функций переносят в общую точку входа (script.js). Если в модуле одна главная сущность, её можно экспортировать через export default.

```js
/* --- Файл tabs.js --- */
export const tabsSelectors = { root: '.tabs' }; /* именованный экспорт */
export default function initTabs() {            /* экспорт по умолчанию (1 на файл) */
  console.log('Табы запущены');
}

/* Особенность со стрелочной функцией: export default const fn = ... даст ошибку! */
const initSliders = () => {};
export default initSliders;   /* выносим отдельно или пишем: export default () => {} */

/* --- Файл script.js (главная точка входа) --- */
/* default импортируется БЕЗ фигурных скобок и под ЛЮБЫМ именем */
import anyTabsName, { tabsSelectors } from './tabs.js';
anyTabsName();
```

[!] Совет по практике: с export default лучше быть осторожнее — произвольные имена при импорте путают читаемость и мешают автоимпорту в IDE. Именованный export предпочтительнее.

## 5. Импорт всего (import * as) и реэкспорт через index.js (18:38–23:52)

[+] Звёздочка собирает все экспорты модуля в один объект. А индексный файл index.js внутри папки собирает экспорты из глубоких подпапок через реэкспорт (export * from), чтобы не писать длинные пути.

```js
/* --- Файл constants.js --- */
export const a = 1;
export const b = 2;
const hiddenD = 4;               /* без export НЕ попадёт в объект импорта * */
export default function logCat() { console.log("Кот"); }

/* --- Импорт всего файла в объект --- */
import * as constants from './constants.js';
console.log(constants.a);        /* 1 */
constants.default();             /* default-экспорт лежит в свойстве .default */

/* --- Реэкспорт в файле constants/index.js --- */
export * from './folder1/folder2/constants.js';
export { default as logCat } from './folder1/folder2/constants.js'; /* явный реэкспорт */
/* Звёздочка забирает только именованные экспорты; default пробрасывают строкой выше */
/* В сборщиках (Vite/Webpack) путь сокращается до "./constants", но в чистом браузере
   без сборщика короткий путь даст 404 — нужно явно писать "./constants/index.js" */
```

## 6. Неочевидные особенности модулей в браузере (23:52–31:40)

1. Код модуля выполняется ровно 1 раз: сколько бы раз файл ни импортировали в разных местах (или ни подключали в HTML), браузер выполнит его тело только при первом обращении (обычный `<script>` без type="module" выполнится столько раз, сколько тегов написано). Благодаря этому модуль удобно использовать как общее хранилище данных в памяти без глобальных переменных в window.

```js
/* --- Файл store.js (создаётся в памяти ровно один раз) --- */
export const cart = [];

/* header.js и catalog.js импортируют ОДИН И ТОТ ЖЕ массив cart */
import { cart } from './store.js';
cart.push('Товар 1'); /* изменение сразу увидят все остальные модули */
```

2. В модуле только объявляем, но не запускаем: на верхнем уровне файла модуля не вызывают функции, не крутят циклы и не меняют данные — всё запускается в точке входа (script.js), чтобы контролировать порядок работы приложения.

3. В HTML остаётся только один `<script type="module" src="./script.js">`: браузер сам догрузит все зависимости по import. При этом модули всегда выполняются ПОСЛЕ обычных `<script>`, поэтому в модуле уже видно DOM-дерево, даже если он подключён внутри `<head>`.

```html
<!-- Порядок в браузере при подключении скриптов -->
<script src="before.js"></script>                <!-- 1. Выполнится первым -->
<script src="script.js" type="module"></script>  <!-- 3. Модуль выполнится ПОСЛЕДНИМ! -->
<script src="after.js"></script>                 <!-- 2. Выполнится вторым -->
```

4. Не работают через file:// (CORS) и всегда в use strict: если открыть HTML двойным кликом с диска, браузер заблокирует import ошибкой CORS (нужен локальный сервер, например Live Server). Внутри любого модуля автоматически включён строгий режим.

## 7. Динамический import() по условию или клику

[+] Обычный import статичен — его нельзя спрятать внутрь if или склеить путь из переменной. Когда тяжёлый модуль нужно загрузить не сразу, а только при клике или по условию, используют функцию import(путь) — она возвращает Promise.

```js
/* Модуль подгрузится только в момент вызова функции (ленивая загрузка) */
async function openModal() {
  const modalModule = await import('./modals.js');
  modalModule.default(); /* если в файле был export default */
}
```

## 8. Архитектура: избегай «круга из импортов» (цикличных зависимостей)

[!] Если файл A импортирует B, а B импортирует обратно A, в момент старта одна из сущностей окажется ещё не создана (ошибка ReferenceError или undefined). Связи модулей должны идти деревом сверху вниз, а всё общее выносят в отдельный файл.

```js
/* ПЛОХО (круг):   tabs.js <-> modals.js (модули тянут друг друга напрямую) */
/* ХОРОШО (дерево): script.js -> tabs.js, modals.js -> оба импортируют utils.js */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть "./" или расширение ".js" в пути import, либо забыть атрибут type="module" у корневого `<script>` (ошибка Cannot use import statement outside a module).

2. Написать "export default const fn = () => {}" (SyntaxError) или пытаться пробросить default-экспорт через реэкспорт "export * from ..." (звёздочка переносит только именованные экспорты).

3. Ожидать повторного выполнения файла при втором import или смешивать порядок с обычными `<script>`: модуль всегда вычисляется 1 раз и запускается после всех обычных не-модульных скриптов.

# Урок 24. JavaScript в браузере: окружение, DOM и BOM

Суть урока: В браузере весь JS работает через главный глобальный объект window, который делится на сам язык JS, BOM (данные о браузере) и DOM (HTML-страница в виде дерева объектов).

## 1. Браузерное окружение и объект window (00:26–02:35)

[+] Среда запуска (браузер, сервер, микроконтроллер) даёт JS свои инструменты — окружение. В браузере всё лежит в глобальном объекте window и делится на 3 части:

- Основной JS: базовые сущности языка (Math, Object.keys/values, Number, Boolean).
- BOM (Browser Object Model): объектная модель самого браузера.
- DOM (Document Object Model): объектная модель HTML-документа (страницы).

[!] У window двойная роль: это и глобальный объект JS, и управление окном браузера (innerWidth, innerHeight). В кроссплатформенном коде (браузер + сервер Node.js) для обращения к глобальному объекту используют единое имя globalThis.

## 2. BOM — Browser Object Model (02:36–03:24)

[+] BOM даёт доступ к информации о браузере и возможностям вне самой вёрстки:

```js
window.navigator;                  /* сведения о браузере и системе */
window.screen;                     /* параметры экрана */
window.location.href;              /* текущий URL-адрес страницы */
window.history;                    /* история переходов текущей сессии */
window.localStorage;               /* хранилище данных браузера (и sessionStorage) */
window.fetch('https://...');       /* отправка сетевых запросов на сервер */
```

## 3. DOM — Document Object Model, children vs childNodes (03:24–07:50)

[+] Свойство window.document содержит представление всей HTML-страницы в виде DOM-дерева: каждый тег и даже вложенный текст — это JS-объект.

```js
console.log(document); /* выводит дерево тегов как во вкладке DevTools -> Elements */
console.dir(document); /* показывает document как JS-объект со свойствами */

/* У document.children -> [html], у html.children -> [head, body] */
console.dir(document.body.children);
/* children — ТОЛЬКО обычные HTML-элементы (теги: div, p, script и т.д.) */

console.dir(document.body.childNodes);
/* childNodes — ВСЕ узлы (ноды), ВКЛЮЧАЯ текстовые узлы! */
/* Переносы строк и пробелы между тегами в HTML тоже становятся текстовыми узлами */
/* У текстового узла нет children, но есть свойство .data с самим текстом строки */
```

[!] В childNodes попадают также HTML-комментарии <!-- ... -->: всё, что написано в разметке, становится узлом DOM. Узнать тип узла можно через свойство nodeType:

```js
/* Главные типы узлов в DOM (nodeType): */
/* 1 — элемент-тег (ELEMENT_NODE: div, body, p)   */
/* 3 — текстовый узел (TEXT_NODE: текст, пробелы) */
/* 8 — HTML-комментарий (COMMENT_NODE: <!-- -->)  */
/* 9 — сам документ (DOCUMENT_NODE: document)     */

/* Быстрые точки входа в DOM: */
document.documentElement; /* корневой тег <html> */
document.head;            /* тег <head> */
document.body;            /* тег <body> (будет null, если скрипт в <head> без module!) */
```

[!] Автоисправление HTML: при чтении битого файла браузер сам достраивает отсутствующие `<html>` и `<body>`, а внутрь любой `<table>` автоматически вставляет обёртку `<tbody>` — даже если вы не писали её в HTML.

[+] HTML vs DOM: HTML-файл — это статичный чертёж с диска, а DOM — уже построенный живой дом из объектов в памяти браузера. Когда JS добавляет кнопку или меняет текст, исходный файл на сервере не трогается, но вкладка DevTools -> Elements сразу показывает обновлённый живой DOM.

## 4. Свойства window без приставки и конфликты имён (07:52–12:56)

[+] К любому свойству window можно обращаться напрямую без "window." в начале (document, navigator, location, innerWidth, Math).

[!] Но глобальные имена могут конфликтовать с твоими переменными. В обычном `<script>` без type="module" часть имён (например, location) жёстко зарезервирована на глобальном уровне.

```js
/* Обычный глобальный <script> (без type="module"): */
console.log(innerWidth); /* ReferenceError, если ниже в файле объявить const innerWidth! */
const innerWidth = 100;  /* но window.innerWidth по-прежнему работает без ошибки */

const location = 'home'; /* сразу SyntaxError: 'location' has already been declared */

/* В <script type="module"> или внутри функции своя область видимости — ошибки нет: */
function test() {
  const location = 'home';     /* допустимо, но ПЕРЕКРЫВАЕТ глобальный location! */
  console.log(location.href);  /* undefined (ищет .href у строки "home") */
  console.log(window.location.href); /* правильно: явное обращение к браузеру */
}
```

[!] Советы: 1) не называй глобальные переменные именами из window; 2) при обращении к BOM (location, navigator) пиши window.location для ясности; 3) переменную с именем document вообще никогда не создавай.

```js
/* Почему старый JS засорял window (вне type="module"): */
var oldVar = 1;       /* записывается в window.oldVar (может перетереть чужое) */
const modernVar = 2;  /* window.modernVar === undefined (остаётся отдельной) */
```

## 5. Быстрый ориентир: когда нужен DOM, а когда BOM

- Нужно поменять или прочитать содержимое самой страницы (текст, кнопки, стили, добавить элемент) -> это DOM (window.document / document).
- Нужно узнать данные о браузере, поменять URL, сохранить состояние в память после F5 или сходить в сеть -> это BOM (location, history, localStorage, navigator, fetch).

## 3 главные ловушки урока (чек-лист для повторения)

1. Путать children и childNodes: в childNodes попадают текстовые узлы — в том числе невидимые переносы строк и пробелы между тегами в HTML.

2. Объявлять на глобальном уровне переменные с именами из window (location, innerWidth, document) — в обычном скрипте это приводит к ошибке или перекрытию.

3. Создав внутри функции/модуля свою переменную (например, location), обращаться к браузеру без "window." — JS возьмёт твою локальную переменную и вернёт undefined.

# Урок 25. Навигация по DOM-дереву, атрибуты async и defer

Суть урока: От любого DOM-элемента можно шагать к родителю, соседям и детям через свойства вроде parentElement и children, а чтобы при запуске скрипта в `<head>` элементы страницы уже существовали, используют атрибут defer.

## 1. Где подключать `<script>`: document.body === null, defer и async (00:24–04:25)

[!] У document есть быстрые свойства: documentElement (`<html>`), head (`<head>`) и body (`<body>`). Если обычный `<script>` поставить внутри `<head>`, скрипт запустится до чтения `<body>`, и document.body вернёт null.

```html
<!-- Способ 1: поставить <script> в самом конце <body> перед </body> -->
<script src="script.js"></script>

<!-- Способ 2: оставить в <head>, но добавить defer (ждёт готовности всей разметки) -->
<script src="script.js" defer></script>

<!-- Атрибут async: качается и запускается в случайный момент (до или после DOM) -->
<!-- Не подходит для работы с DOM; ставят для метрик и аналитики -->
<script src="analytics.js" async></script>
```

[!] Важно: defer и async работают ТОЛЬКО у внешних скриптов с атрибутом src. Несколько defer-скриптов выполняются строго по порядку в HTML (прямо перед событием DOMContentLoaded), даже если второй файл скачался быстрее первого. А скрипты с async запускаются по принципу «кто первый скачался, тот первый сработал». При этом у модулей (`<script type="module">`) поведение defer встроено по умолчанию.

## 2. Навигация от элемента к элементу (04:26–09:16)

[+] Свойства со словом Element (и children) работают ТОЛЬКО с HTML-тегами, игнорируя пробелы, переносы строк и текст:

```js
const body = document.body;

/* Вверх (к родителю) и в стороны (к соседям на одном уровне) */
body.parentElement;          /* <html> */
body.previousElementSibling; /* <head> (предыдущий соседний тег) */
body.nextElementSibling;     /* null (после <body> на том же уровне никого нет) */

/* Вниз (к прямым дочерним тегам) */
body.children;               /* живая коллекция HTMLCollection всех прямых детей-тегов */
body.firstElementChild;      /* первый дочерний тег (например, <div>) */
body.lastElementChild;       /* последний дочерний тег */

/* У таблиц <table> есть отдельные быстрые свойства (в обход скрытого <tbody>): */
table.rows;                  /* все строки <tr> таблицы */
table.rows[0].cells;         /* все ячейки <td> и <th> в первой строке */
```

[+] Зачем нужны шаги: когда пользователь нажал кнопку внутри карточки товара, не нужно искать всю страницу заново — от самой кнопки через parentElement или previousElementSibling сразу выходят на нужное поле этой же карточки.

## 3. Живая коллекция HTMLCollection (children) и массив (06:27–08:40)

[!] Свойство children возвращает не массив, а живую коллекцию HTMLCollection: она сама обновляется при изменении DOM, но не имеет методов массива (forEach и др.).

```js
const bodyChildren = document.body.children;
console.log(bodyChildren.length); /* 1 (например, только один <div>) */
console.log(bodyChildren[0]);     /* по индексу обращаться можно */

/* Если добавить новый тег в DOM, старая переменная bodyChildren САМА обновится! */
const btn = document.createElement('button');
document.body.append(btn);
console.log(bodyChildren.length); /* уже 2! */

/* bodyChildren.forEach(...) -> TypeError! Сначала превращаем в обычный массив: */
const arr1 = Array.from(bodyChildren);
const arr2 = [...bodyChildren];
arr2.forEach((el) => console.log(el));

/* Но цикл for..of перебирает коллекцию и БЕЗ превращения в массив: */
for (const el of bodyChildren) { console.log(el); }
```

[!] Не используйте for..in для перебора коллекций (он захватит лишние свойства length и item) и не пытайтесь менять коллекцию напрямую (children[0] = ... не сработает, она только для чтения).

```js
/* Ловушка удаления из живой коллекции: при удалении индексы съезжают прямо в цикле! */
/* ПЛОХО: удалить всё не выйдет — половина элементов пропустится из-за сдвига */
for (let i = 0; i < parent.children.length; i++) { parent.children[i].remove(); }

/* ХОРОШО: делаем неподвижную копию-массив [...parent.children] и удаляем спокойно */
for (const child of [...parent.children]) { child.remove(); }
```

## 4. Навигация по узлам (Node) против элементов (09:17–12:03)

[+] Свойства без слова Element смотрят на ВСЕ узлы подряд (включая текстовые узлы с текстом, пробелами и переносами строк между тегами). В практике нужны редко, но важно понимать разницу:

```js
const div = document.body.firstElementChild;

/* Родитель: разница видна только на корневом теге <html> (documentElement) */
document.documentElement.parentElement; /* null (над <html> нет HTML-тега) */
document.documentElement.parentNode;    /* объект document (корень всего DOM) */

/* Соседи, первый/последний и все дети: */
div.previousElementSibling; /* null (тега перед <div> нет) */
div.previousSibling;        /* #text "\n  " (перенос строки и пробелы до <div>!) */

div.nextElementSibling;     /* следующий соседний тег (или null) */
div.nextSibling;            /* следующий узел (часто #text с переносом строки) */

div.firstElementChild;      /* vs div.firstChild (первый узел, часто #text) */
div.lastElementChild;       /* vs div.lastChild (последний узел) */
div.children;               /* HTMLCollection (теги) vs div.childNodes (NodeList: всё) */
/* У NodeList (childNodes) метод .forEach() есть сразу, а у HTMLCollection — нет */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Подключить обычный `<script>` в `<head>` без defer (или поставить async вместо defer): на момент запуска `<body>` ещё не прочитан, и document.body вернёт null.

2. Пытаться вызвать .forEach() прямо на elem.children: у HTMLCollection нет методов массива — сперва оберни в [...elem.children] или Array.from(...).

3. Использовать firstChild / nextSibling вместо firstElementChild / nextElementSibling и вместо кнопки или блока получить текстовый узел #text с пробелами разметки.

## Вопросы для закрепления

**1. Почему при подключении обычного `<script src="app.js">` внутри `<head>` выражение `document.body` вернёт `null`, а `defer` это исправляет?**

<details>
<summary>Показать ответ</summary>

Обычный `<script>` останавливает парсинг HTML сразу внутри `<head>`, когда браузер ещё не дошёл до тега `<body>`. Скрипт с `defer` скачивается параллельно и запускается только после полного построения DOM, перед `DOMContentLoaded`.

</details>

**2. В чём разница между `elem.children` и `elem.childNodes`, и сработает ли `elem.children.forEach(...)`?**

<details>
<summary>Показать ответ</summary>

`children` возвращает живую коллекцию `HTMLCollection` только из HTML-тегов (метода `.forEach()` у неё нет — нужно `[...elem.children]`). `childNodes` возвращает `NodeList` со всеми узлами подряд, включая текстовые узлы `#text` с пробелами и переносами строк.

</details>

**3. Что вернёт `document.documentElement.parentElement` против `document.documentElement.parentNode`?**

<details>
<summary>Показать ответ</summary>

`parentElement` вернёт `null` (над тегом `<html>` нет другого HTML-элемента), а `parentNode` вернёт объект `document`.

</details>

# Урок 26. Поиск элементов в DOM: getElement* и querySelector*

Суть урока: В 99% задач элементы ищут по любому CSS-селектору через querySelector (один элемент) и querySelectorAll (все элементы), вверх к предку шагают через closest, а в реальной разметке JS-элементы лучше помечать атрибутами data-js-*.

## 1. Поиск по id: document.getElementById и ловушка глобального id (01:08–03:13)

[+] Если у тега задан уникальный id, к нему быстро обращаются через document.getElementById (работает только у document, а не у вложенных элементов).

```js
const buttonElement = document.getElementById('myButton');
/* Найдёт первый элемент с таким id; если не найден — вернёт null */

/* АНТИПАТТЕРН: браузер создаёт глобальную переменную с именем id (если без дефиса) */
console.log(myButton); /* сработает, но сломается при id='my-button' или своей myButton */
```

## 2. Универсальный поиск: querySelector и querySelectorAll (03:14–07:30, 08:48)

[+] Оба метода принимают любой CSS-селектор и вызываются как у document, так и у любого уже найденного элемента (чтобы сузить область поиска).

```js
/* querySelector — возвращает ПЕРВЫЙ подходящий элемент (или null) */
const btnElement = document.querySelector('button');
const byId = document.querySelector('#myButton');
const byClass = document.querySelector('.my-button');

/* querySelectorAll — возвращает ВСЕ подходящие элементы в виде NodeList */
const listItemElements = document.querySelectorAll('.list-item');
listItemElements.forEach((el) => console.log(el)); /* у NodeList есть forEach! */

/* Сужение контекста (ищем не по всей странице, а только внутри wrapperElement) */
const wrapperElement = document.querySelector('#wrapper');
const listElement = wrapperElement.querySelector('.list');

/* Несколько селекторов за раз — одной строкой через запятую */
const mixedElements = document.querySelectorAll('.box-1, .box-3');

/* Псевдоклассы тоже работают; querySelector быстрее querySelectorAll[0] (стоп на 1-м) */
const activeField = document.querySelector(':focus'); /* кто в фокусе прямо сейчас */
```

## 3. Поиск предка и проверка: closest, matches, contains (07:31–08:47)

[+] Если querySelector ищет сверху вниз (внутрь), то closest ищет снизу вверх — начиная с САМОГО элемента и выше по родителям (или вернёт null).

```js
const thirdBoxElement = document.querySelector('.box-3');
const firstBoxElement = thirdBoxElement.closest('.box-1'); /* поднимется до .box-1 */
thirdBoxElement.closest('.box-3'); /* вернёт сам thirdBoxElement, т.к. он подходит */

/* Похожие полезные проверки (возвращают true / false): */
thirdBoxElement.matches('.box-3:hover'); /* подходит ли САМ элемент под CSS-селектор */
firstBoxElement.contains(thirdBoxElement); /* лежит ли thirdBoxElement внутри firstBox */
```

## 4. Живые getElementsBy* против статического querySelectorAll (09:12–11:15)

[!] Старые методы getElementsBy* сейчас почти не используют, но у них есть важная особенность — они возвращают живую HTMLCollection, которая сама подтягивает новые элементы при изменении DOM.

```js
const formElements = document.getElementsByTagName('form');    /* по тегу */
const groupElements = document.getElementsByClassName('group'); /* по классу */
const inputElements = document.getElementsByName('email');      /* по атрибуту name */

/* Статический аналог через querySelectorAll с селектором атрибута name: */
const staticInputs = document.querySelectorAll('[name="email"]');

/* Живая HTMLCollection сама обновится после добавления нового тега в DOM, */
/* но для forEach её надо перевести в массив: [...formElements].forEach(...) */
/* Статический NodeList от querySelectorAll НЕ меняется при правках DOM */
```

## 5. Нейминг переменных и разделение CSS / JS через data-js-* (11:16–15:30)

[+] Правило именования: не сокращайте слова (linkElement вместо link) и всегда добавляйте суффикс Element (для 1 элемента) или Elements (для коллекции).

[+] Правило выбора селектора: class — только для CSS-стилей, id — должен быть уникальным. Чтобы изменение стилей не ломало скрипты, для JS в HTML добавляют специальные атрибуты с префиксом data-js-*.

```js
<!-- В HTML отделяем стилизацию (class) от логики (data-js-*) -->
<div class="slider" data-js-slider>
  <ul class="slider__list" data-js-slider-list>
    <li class="slider__item" data-js-slider-slide>Слайд 1</li>
  </ul>
</div>

/* В JS ищем через квадратные скобки (селектор по атрибуту): */
const sliderElement = document.querySelector('[data-js-slider]');
const sliderSlideElements = sliderElement.querySelectorAll('[data-js-slider-slide]');
```

## 6. Защита от null, проверка пустого NodeList и шпаргалка выбора

[!] Ловушка проверки: querySelector при неудаче вернёт null, а querySelectorAll — пустой объект NodeList [], который в if (...) всё равно считается true! Поэтому наличие элементов проверяют через .length, а от падения на null спасает ранний выход.

```js
const sliderElement = document.querySelector('[data-js-slider]');
if (!sliderElement) return; /* защита: если блока нет на странице, не упадём ниже */

/* Или через опциональную цепочку (?.) при поиске внутри найденного блока: */
const slides = sliderElement?.querySelectorAll('[data-js-slider-slide]');

/* ВАЖНО: пустой NodeList [] в if (slides) даст true! Проверяем длину .length: */
if (!slides.length) {
  console.log('Слайды не найдены');
}
```

[+] Шпаргалка выбора метода поиска:
- Нужен 1 элемент (или первый подходящий) -> querySelector (либо getElementById).
- Нужен список всех подходящих элементов -> querySelectorAll.
- Нужно найти родителя вверх от кликнутой кнопки -> closest.
- Нужна самообновляемая коллекция при правках DOM -> getElementsBy* / elem.children.

## 3 главные ловушки урока (чек-лист для повторения)

1. Перепутать querySelector (один элемент или null) и querySelectorAll (всегда возвращает список NodeList — даже пустой список правдив в условии if!).

2. Ждать, что переменная от querySelectorAll сама обновится после добавления тегов в DOM (она статическая), либо вызывать .forEach() прямо на живой HTMLCollection от getElementsBy* без [...coll].

3. Искать элементы напрямую по глобальной переменной от id или привязывать JS к CSS-классам стилей вместо отдельных data-js-* атрибутов.

# Урок 27. Свойства и атрибуты DOM-элементов, value, data-*

Суть урока: Стандартные HTML-атрибуты читают и меняют через свойства DOM-объекта (например, input.value), нестандартные — через методы *Attribute(), а data-* атрибуты доступны через dataset и умеют передавать готовый JSON-конфиг из HTML.

## 1. Стандартные HTML-атрибуты как свойства DOM-объекта (00:19–03:18)

[+] У каждого DOM-элемента есть только те стандартные свойства, которые валидны для его тега (action есть у `<form>`, checked — у `<input>`). Они работают как геттеры/сеттеры и сразу обновляют HTML в DevTools -> Elements.

```js
const formElement = document.querySelector('form');
const inputElement = document.querySelector('input');

console.log(formElement.action);   /* геттер: вернёт полный URL (домен + "/login") */
formElement.action = '/new-login'; /* сеттер: сразу обновит атрибут action в DOM */
console.log(inputElement.checked); /* true/false для чекбокса (у form этого нет) */

/* Атрибуты через дефис в JS пишутся в camelCase: */
formElement.ariaLabel = 'Форма входа'; /* в HTML будет aria-label="Форма входа" */

/* Типы и особые имена DOM-свойств (в отличие от строковых HTML-атрибутов): */
inputElement.checked;  /* boolean (true/false), а getAttribute("checked") -> "" */
formElement.style;     /* объект CSSStyleDeclaration, а не строка стилей */
linkElement.href;      /* полный URL, а getAttribute("href") -> "#top" как в HTML */
formElement.className; /* вместо "class" (class и for — зарезервированы в JS!) */
labelElement.htmlFor;  /* вместо "for" */
```

## 2. Нестандартные атрибуты: get/set/remove/hasAttribute (03:19–06:40, 09:45)

[!] Кастомные атрибуты (например, qty или data-value) НЕ превращаются в свойства объекта (elem.qty === undefined). Для работы с ними нужны 4 метода (значения атрибутов в HTML всегда хранятся как строки!).

```js
console.log(formElement.getAttribute('qty'));       /* читает значение как строку */
formElement.setAttribute('data-value', '10');       /* ставит (число 10 тоже -> '10') */
formElement.hasAttribute('data-value');             /* true / false — есть ли атрибут */
formElement.removeAttribute('qty');                 /* полностью удаляет атрибут */

/* ОШИБКА: setAttribute("qty", "") НЕ удаляет атрибут, а оставляет пустую строку! */
/* Коллекция formElement.attributes показывает все атрибуты, но только для чтения */
/* Регистр: getAttribute("QTY") найдёт qty (HTML не различает регистр атрибутов),
   а DOM-свойства в JS строго чувствительны к регистру (elem.id работает, ID — нет) */
```

## 3. Синхронизация и односторонняя ловушка с value (06:41–09:45)

[!] Большинство стандартных атрибутов синхронизируются в обе стороны. Но атрибут value у `<input>` — исключение: при изменении свойства input.value сам HTML-атрибут в разметке НЕ меняется!

```js
/* <input id="login"> (атрибут value в HTML изначально не задан) */
inputElement.value = 'Admin';                  /* меняет текст в поле на экране */
console.log(inputElement.value);               /* 'Admin' — всегда актуально */
console.log(inputElement.getAttribute('value')); /* null! В HTML атрибут не появился */

inputElement.setAttribute('value', 'Guest');   /* меняет и атрибут, и свойство, */
/* НО если пользователь уже вводил текст, setAttribute не обновит поле на экране! */

/* Правило: для value и всех стандартных атрибутов используй свойства (elem.value) */
```

[+] Зачем так устроено: HTML-атрибут value (как и checked у чекбокса) специально хранит исходное значение по умолчанию — именно к нему форма откатывается при нажатии кнопки сброса (`<button type="reset">`), а input.value — текущее значение.

```js
/* Ловушка boolean-атрибутов (disabled, hidden, required): */
btn.setAttribute('disabled', 'false'); /* ОШИБКА: кнопка ВСЁ РАВНО заблокирована! */
btn.disabled = false;                  /* ПРАВИЛЬНО: разблокирует и уберёт атрибут */
```

## 4. Атрибуты data-*, свойство dataset и передача JSON (10:03–13:20)

[+] Все атрибуты вида data-* автоматически собираются в объект elem.dataset (префикс data- отрезается, а дефисы переходят в camelCase). Также в data-* можно передать готовый объект настроек в формате JSON.

```js
<!-- В HTML: внешние кавычки ОДИНАРНЫЕ, внутри валидный JSON с двойными кавычками -->
<div data-js-slider='{ "autoplay": true, "speed": 500 }'></div>

const sliderElement = document.querySelector('[data-js-slider]');

/* Способ 1: через dataset (без "data-", в camelCase) — подходит для чтения и записи */
console.log(sliderElement.dataset.jsSlider);
delete sliderElement.dataset.jsSlider; /* удаление data-* атрибута через dataset */

/* Способ 2: getAttribute + безопасный JSON.parse (защита от пустого атрибута) */
const rawConfig = sliderElement.getAttribute('data-js-slider');
const config = rawConfig ? JSON.parse(rawConfig) : {};
```

## 5. Шпаргалка выбора: свойство, dataset или *Attribute

- Стандартные поля и флаги (value, checked, disabled, href) -> DOM-свойство.
- Свои данные и селекторы компонентов (data-*) -> dataset (или getAttribute).
- Редкие нестандартные атрибуты и точечное удаление -> *Attribute.

## 3 главные ловушки урока (чек-лист для повторения)

1. Читать текст поля через input.getAttribute("value") вместо input.value — получите старое значение из разметки (или null), а не то, что ввели.

2. Пытаться удалить атрибут через setAttribute("attr", "") вместо removeAttribute("attr") или менять кастомный атрибут через elem.customAttr = ...

3. Забыть, что getAttribute и dataset всегда отдают строки: объект из HTML нужно распарсить через JSON.parse(...), а в HTML обернуть атрибут в одинарные кавычки.

# Урок 28. Стили и CSS-классы в DOM: style, getComputedStyle, classList

Суть урока: Оптимальнее управлять внешним видом через CSS-классы с помощью elem.classList; инлайновые стили задают через elem.style (и CSS-переменные через setProperty), а реальные стили из CSS-файлов читают через getComputedStyle(elem).

## 1. Инлайновые стили: elem.style и style.cssText (00:21–03:04)

[+] Свойство elem.style позволяет точечно менять CSS-свойства прямо в атрибуте style элемента (в camelCase). А style.cssText задаёт сразу несколько свойств строкой в обычном CSS-формате.

```js
const boxElement = document.querySelector('.box');

/* Точечное изменение (добавляется в атрибут style="...") */
boxElement.style.position = 'absolute';
boxElement.style.top = '10px'; /* число 10 без 'px' проигнорируется! */
boxElement.style.top = '';     /* пустая строка СБРАСЫВАЕТ стиль обратно к CSS-файлу */

/* Перезапись сразу группой свойств (СТИРАЕТ прошлые инлайн-стили, например height!) */
boxElement.style.cssText = `
  position: absolute;
  top: 20px;
`;

/* Чтобы ДОПИСАТЬ к текущим инлайн-стилям, используют += */
boxElement.style.cssText += 'left: 30px;';
```

## 2. Чтение реальных стилей: getComputedStyle (03:05–05:20)

[!] Свойство elem.style видит ТОЛЬКО инлайновые стили из атрибута style="...". Если ширина задана в отдельном CSS-файле, boxElement.style.width вернёт пустую строку "". Реальные итоговые стили читают через getComputedStyle().

```js
console.log(boxElement.style.width); /* "" если ширина задана в .css файле */

/* getComputedStyle(elem) — итоговые стили со всех CSS (как DevTools -> Computed) */
const boxStyles = getComputedStyle(boxElement); /* объект ТОЛЬКО для чтения */
console.log(boxStyles.width);     /* например, "200px" */
console.log(boxStyles.marginTop); /* просите ПОЛНЫЕ свойства, а не просто "margin"! */

/* Для расчётов снимаем "px" через parseFloat, потом доклеиваем "px" обратно: */
const newWidth = parseFloat(boxStyles.width) + 50;
boxElement.style.width = `${newWidth}px`;

/* 2-й аргумент читает стили псевдоэлемента (обязательно с двумя двоеточиями "::") */
const afterStyles = getComputedStyle(boxElement, '::after');
console.log(afterStyles.textDecoration);
```

## 3. CSS-классы: className против classList (05:21–10:27)

[+] Свойства elem.class нет (зарезервированное слово JS). Вместо него есть строка className (перезаписывает все классы сразу, неудобно) и главный инструмент — объект classList с четырьмя методами.

```js
boxElement.className = 'red'; /* ПЛОХО: сотрёт исходный класс 'box'! */

/* ПРАВИЛЬНО — через classList: */
boxElement.classList.add('red', 'big');    /* добавит 1 или несколько классов */
boxElement.classList.remove('red', 'big'); /* удалит 1 или несколько классов */

/* toggle: если класса нет — добавит; если есть — удалит */
boxElement.classList.toggle('red');

/* Супер-фишка toggle: 2-й аргумент-условие (boolean) для принудительного состояния */
const hasError = true;
boxElement.classList.toggle('is-invalid', hasError); /* true -> добавит, false -> уберёт */

/* contains: проверяет наличие класса (true / false) */
console.log(boxElement.classList.contains('box'));
boxElement.classList.replace('old', 'new'); /* заменяет старый класс на новый */
for (const cls of boxElement.classList) { console.log(cls); } /* перебор классов */
```

## 4. Управление CSS-переменными в JS: setProperty (10:28–11:50)

[+] Кастомные CSS-переменные (например, --border-color) меняют через метод elem.style.setProperty(). Приоритет important указывается только 3-м аргументом.

```js
boxElement.style.setProperty('--border-color', 'blue');

/* Если нужен !important — передаём ТОЛЬКО 3-м аргументом без "!" */
boxElement.style.setProperty('--border-color', 'blue', 'important');
/* setProperty("--border-color", "blue !important") — НЕ сработает! */

/* Чтение CSS-переменной (включая заданные во внешнем CSS-файле): */
const color = getComputedStyle(boxElement).getPropertyValue('--border-color').trim();
```

## 5. Правило каскада и шпаргалка выбора: classList vs style

[!] Инлайновые стили из elem.style имеют максимальный вес в CSS — они перебивают любой класс и даже #id. Если задать box.style.display = "none", то класс .is-open его не покажет, пока не сбросите инлайн через "".

[+] Шпаргалка выбора:
- Вкл/выкл состояния (активность, ошибка, открытие) -> всегда classList.
- Динамические числа (координаты мыши, прогресс 0..100%) -> elem.style или style.setProperty("--var", ...), если от числа зависят сразу несколько стилей.
- Прочитать реальные размеры/цвета из CSS -> getComputedStyle(elem).

## 3 главные ловушки урока (чек-лист для повторения)

1. Искать стили из CSS-файла в elem.style.width — там лежат только инлайновые стили; реальные вычисленные значения даёт только getComputedStyle(elem).

2. Менять классы через elem.className = "new" (или стили через style.cssText = "...") — это стирает все прежние классы и инлайн-стили; для классов нужен classList.

3. Дописывать "!important" в строку значения внутри setProperty("--var", "blue !important") — инструкция просто проигнорируется (important — 3-й аргумент).

# Урок 29. Размеры и координаты DOM-элементов

Суть урока: Размеры элемента в JS читают готовыми числовыми свойствами (offset*, client*, scroll*) вместо getComputedStyle, а точные координаты получают через getBoundingClientRect() (+ window.scrollX/scrollY для всей страницы).

## 1. Полные размеры: offsetWidth / offsetHeight и рамка clientLeft / Top (00:46–04:39)

[+] Все метрики возвращают чистые числа в CSS-пикселях (без "px"). Полные внешние размеры зависят от box-sizing: при content-box они складывают width + padding + border.

```js
const box = document.querySelector('.box');

/* Полные внешние габариты (контент + padding + border + scrollbar) */
console.log(box.offsetWidth, box.offsetHeight);
/* Координаты относительно ближайшего позиционированного предка (offsetParent): */
console.log(box.offsetParent, box.offsetLeft, box.offsetTop);

/* Отступ от левого/верхнего внешнего края до контентной зоны (padding) */
console.log(box.clientLeft, box.clientTop); /* обычно ширина левого и верхнего border */
/* При direction: rtl скроллбар уезжает влево и добавляется к clientLeft! */
```

[!] Если элемент (или его предок) скрыт через display: none, все его размеры равны 0, а offsetParent === null. Поэтому по box.offsetWidth проверяют, видим ли блок на экране.

## 2. Внутренние размеры без рамки: clientWidth и clientHeight (04:40–05:50)

[+] clientWidth / clientHeight дают видимую внутреннюю область (контент + padding), вычитая border и толщину видимого скроллбара (при overflow: hidden не вычитается).

```js
/* Например: offsetHeight 200, border по 20 сверху/снизу, scrollbar 15 */
console.log(box.clientHeight); /* 200 - 20 - 20 - 15 = 145 (без scroll -> 160) */
console.log(box.clientWidth);
```

## 3. Прокрутка: scrollWidth, scrollHeight, scrollLeft, scrollTop (05:51–08:52)

[!] scrollWidth / scrollHeight — полная внутренняя ширина/высота ВМЕСТЕ со скрытой прокручиваемой частью (без border). Из ВСЕХ метрик только scrollLeft и scrollTop можно менять (остальные только для чтения!).

```js
/* Сколько пикселей ещё осталось проскроллить вниз: */
const hiddenPart = box.scrollHeight - box.clientHeight;

/* Программный скролл относительно (0, 0) — не суммируется при повторе! */
box.scroll(10, 50); /* вправо на 10px, вниз на 50px */
box.scroll({ left: 10, top: 50, behavior: 'smooth' }); /* плавный вариант */

/* scrollLeft / scrollTop — единственные метрики, куда можно ЗАПИСЫВАТЬ значения: */
box.scrollLeft = 10;
box.scrollTop = 50;
console.log(box.scrollLeft, box.scrollTop); /* сколько уже прокручено */
```

## 4. Почему метрики лучше getComputedStyle для размеров (08:53–11:10)

[!] Для расчётов размеров лучше метрики, чем getComputedStyle(box), по 3 причинам: 1) строчные элементы (display: inline / `<span>`) вернут "auto"; 2) размеры приходят строкой с "px" и их надо парсить; 3) Chrome и Firefox по-разному считают скроллбар.

## 5. Координаты относительно окна и относительно страницы (11:11–14:58)

[+] Метод elem.getBoundingClientRect() даёт актуальные координаты углов элемента относительно ВИДИМОГО ОКНА браузера (при скролле страницы они меняются).

```js
const rect = box.getBoundingClientRect();

/* Координаты левого верхнего угла и всех сторон относительно ОКНА: */
console.log(rect.x, rect.y);          /* левый верхний угол (как left и top) */
console.log(rect.width, rect.height); /* точные (дробные) с учётом CSS transform: scale */
/* offsetWidth всегда целое и ИГНОРИРУЕТ CSS-масштабирование transform: scale(...) */
console.log(rect.top, rect.right, rect.bottom, rect.left);

/* Координаты относительно НАЧАЛА ВСЕЙ СТРАНИЦЫ (постоянны при скролле): */
const pageX = rect.left + window.scrollX; /* подходят для position: absolute */
const pageY = rect.top + window.scrollY;  /* rect.top/left — для position: fixed */

/* Обратная задача: какой самый глубокий элемент лежит в окне в точке (x, y)? */
const elAtPoint = document.elementFromPoint(100, 200); /* или null за экраном */
```

## 6. Шпаргалка-матрёшка размеров и 2 главные формулы практики

[+] Как мгновенно отличить 3 семейства:
- offset* -> снаружи с рамкой (border + scrollbar + видимое).
- client* -> внутри видимое окно (без border и без скроллбара).
- scroll* -> вся простыня целиком (видимое + всё спрятанное за скроллом).

```js
/* Формула 1: пользователь доскроллил блок до самого низа? (-1 от дробного зума) */
const isAtBottom = box.scrollTop + box.clientHeight >= box.scrollHeight - 1;

/* Формула 2: элемент сейчас виден хотя бы частично в окне браузера? */
const isVisible = rect.top < window.innerHeight && rect.bottom > 0;
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Пытаться менять offsetWidth или clientHeight напрямую — почти все метрики только для чтения; записывать числа можно только в scrollLeft и scrollTop.

2. Путать координаты getBoundingClientRect() (от окна, меняются при скролле) с координатами на странице (к ним нужно прибавить window.scrollX и window.scrollY).

3. Ждать, что второй вызов box.scroll(10, 50) докрутит ещё 50px — scroll() задаёт абсолютную точку от (0, 0), а не относительный сдвиг.

# Урок 30. Размеры окна и страницы, скролл: scroll, scrollBy, scrollIntoView

Суть урока: Размеры доступного окна берут из documentElement.clientWidth/Height, точную высоту всей страницы — через Math.max, а прокручивают страницу к точке (scroll), на сдвиг (scrollBy) или прямо к элементу (scrollIntoView).

## 1. Размеры окна (viewport): documentElement vs window (00:26–02:45)

[+] Для позиционирования элементов нужна ширина/высота БЕЗ полос прокрутки — её дают clientWidth и clientHeight на document.documentElement (теге `<html>`).

```js
const htmlElement = document.documentElement;

/* ПРАВИЛЬНО: чистое доступное пространство без полос прокрутки */
console.log(htmlElement.clientWidth, htmlElement.clientHeight);

/* ОШИБКА ДЛЯ ПОЗИЦИОНИРОВАНИЯ: учитывают ширину скроллбара */
console.log(window.innerWidth, window.innerHeight);
/* Условие: в HTML обязательно должен быть <!DOCTYPE html>, иначе метрики врут */
```

## 2. Полная высота всей страницы и позиция скролла (02:46–05:00)

[!] У documentElement.scrollHeight бывает баг — иногда он возвращает значение меньше высоты окна. Для надёжности берут максимум из 6 свойств у body и html.

```js
const fullPageHeight = Math.max(
  document.body.scrollHeight, document.documentElement.scrollHeight,
  document.body.offsetHeight, document.documentElement.offsetHeight,
  document.body.clientHeight, document.documentElement.clientHeight,
);

/* Текущая позиция скролла страницы (актуальный способ, без deprecated): */
console.log(window.scrollX, window.scrollY);
/* Надёжнее, чем body.scrollTop / htmlElement.scrollTop (в браузерах они расходились) */
/* window.pageXOffset / pageYOffset — устарели (deprecated) */
```

## 3. Прокрутка страницы: scroll() / scrollTo() против scrollBy() (05:01–07:09)

[+] Методы работают и у window, и у любого элемента. scroll() и scrollTo() делают одно и то же — крутят к абсолютной точке от (0, 0), а scrollBy() сдвигает от текущего места.

```js
/* Абсолютный скролл до точки y = 200 (от самого верха страницы): */
window.scroll({ top: 200, behavior: 'smooth' }); /* или window.scrollTo(...) */
/* ВАЖНО: smooth-скролл идёт во времени — сразу на строке ниже window.scrollY ещё 0! */
/* Повторный вызов window.scroll({ top: 100 }) прокрутит ОБРАТНО ВВЕРХ до 100! */

/* Относительный сдвиг от текущей позиции (scrollBy): */
window.scrollBy({ top: 200, behavior: 'smooth' });
setTimeout(() => {
  window.scrollBy({ top: 100, behavior: 'smooth' }); /* итого спустимся на 300px */
}, 2000);

/* Блокировка скролла страницы (например, для открытой модалки): */
const scrollbarWidth = window.innerWidth - document.documentElement.clientWidth;
document.body.style.overflow = 'hidden'; /* запретить скролл (+ paddingRight = scrollbar) */
document.body.style.overflow = '';       /* вернуть скролл при закрытии модалки */
```

## 4. Прокрутка прямо к элементу: elem.scrollIntoView() (07:10–10:19)

[+] Удобный метод, который сам вычисляет координаты и скроллит страницу так, чтобы элемент оказался в окне. На слабых устройствах при старте страницы его иногда оборачивают в небольшой setTimeout(..., 300), чтобы вёрстка успела отрисоваться.

```js
const reviewsSectionElement = document.querySelector('#reviews');

/* Выравнивание по вертикали (block) и горизонтали (inline):
   "start" (по умолчанию, к верхнему краю) | "center" | "end" | "nearest" */
reviewsSectionElement.scrollIntoView({
  behavior: 'smooth',
  block: 'start',
  inline: 'nearest',
});

/* Короткий старый синтаксис: true = block: "start" (верх), false = block: "end" (низ) */
reviewsSectionElement.scrollIntoView(false);

/* Если у сайта фиксированная шапка (fixed), добавьте секции в CSS: */
/* #reviews { scroll-margin-top: 80px; } — и заголовок не уедет под шапку! */
```

## 5. Шпаргалка по сценариям скролла

- Кнопка «Наверх» -> window.scroll({ top: 0, behavior: "smooth" }).
- Переход к нужному разделу сайта -> section.scrollIntoView({ behavior: "smooth" }).
- Пролистать карусель / ленту на 1 шаг вперёд -> slider.scrollBy({ left: 300 }).
- Запретить скролл под модалкой без «прыжка» -> overflow = "hidden" + paddingRight.

## 3 главные ловушки урока (чек-лист для повторения)

1. Брать ширину окна из window.innerWidth вместо documentElement.clientWidth — лишние пиксели полосы прокрутки испортят расчёты.

2. Ждать от window.scroll({ top: 100 }) сдвига «ещё на 100px вниз» — scroll() и scrollTo() работают от (0, 0); для сдвига «от текущего места» нужен scrollBy().

3. Брать высоту всей страницы одним documentElement.scrollHeight (надёжнее Math.max из 6 метрик body/html) или забыть block: "center" / "nearest" у scrollIntoView.

# Урок 31. Манипуляции с DOM: создание, вставка, удаление, клонирование

Суть урока: Текст меняют через textContent, HTML-разметку — через innerHTML или insertAdjacentHTML, а новые теги создают через createElement() и вставляют в DOM методами append / prepend / before / after / replaceWith.

## 1. Содержимое элементов: textContent, innerHTML, outerHTML (00:31–05:31)

[+] textContent работает только с чистым текстом (теги из строки не парсит, а старых детей стирает). innerHTML читает/пишет HTML внутри элемента, а outerHTML захватывает и сам тег элемента.

```js
const box = document.querySelector('.box');

/* textContent: склеивает текст всех детей; при записи сотрёт все вложенные теги! */
box.textContent = '<p>Текст</p>'; /* на экране выведет буквы '<p>Текст</p>', а не тег */
/* БЕЗОПАСНОСТЬ (XSS): чужой текст от пользователя вставляй ТОЛЬКО через textContent! */

/* innerHTML: парсит теги; "+=" не только медленный, но и СТИРАЕТ фокус и обработчики */
box.innerHTML = '<p>Обновлённый абзац</p>';
box.innerHTML += '<p>Ещё один в конец</p>';

/* outerHTML: включает сам тег .box; в старой переменной box останется УДАЛЁННЫЙ тег! */
box.outerHTML = '<section>Вместо box</section>';
```

## 2. Создание createElement и 5 методов вставки в DOM (05:32–11:08)

[+] Самый правильный способ добавления элементов: создать узел в памяти через document.createElement(tag), настроить его и вставить одним из 5 методов.

```js
const getNewParagraph = () => {
  const p = document.createElement('p'); /* создан в памяти, в DOM пока отсутствует */
  p.textContent = 'Новый параграф';
  p.classList.add('paragraph-4');
  return p;
};

/* 5 методов вставки относительно опорного элемента box: */
box.append(getNewParagraph(), "просто текст"); /* внутрь в КОНЕЦ (+ строки как текст) */
box.prepend(getNewParagraph());                /* внутрь в НАЧАЛО */
box.before(getNewParagraph());                 /* снаружи ДО открывающего тега box */
box.after(getNewParagraph());                  /* снаружи ПОСЛЕ закрывающего тега box */
box.replaceWith(getNewParagraph());            /* ЗАМЕНЯЕТ сам элемент box */

/* Пакетная вставка 100 элементов без 100 перерисовок: DocumentFragment или ...массив */
const fragment = document.createDocumentFragment(); /* виртуальный контейнер */
for (let i = 0; i < 3; i++) { fragment.append(getNewParagraph()); }
box.append(fragment); /* сам fragment растворится, внутри box окажутся только 3 <p> */

/* ВАЖНО: один и тот же созданный объект нельзя вставить дважды — он ПЕРЕМЕСТИТСЯ! */
/* И помни: box.append(p) всегда возвращает undefined, а НЕ вставленный элемент p */
```

## 3. Точная вставка HTML-строки: insertAdjacentHTML / Element (11:09–14:06)

[+] insertAdjacentHTML хирургически вставляет строку с HTML-разметкой в нужное место БЕЗ медленной перезаписи соседей (как при innerHTML +=). Аналог для готового элемента — insertAdjacentElement (принимает ровно 1 элемент).

```js
/* 4 позиции вставки (1-й аргумент): */
box.insertAdjacentHTML('beforebegin', '<p>До box снаружи</p>');
box.insertAdjacentHTML('afterbegin',  '<p>Внутрь в начало</p>');
box.insertAdjacentHTML('beforeend',   '<p>Внутрь в конец</p>');
box.insertAdjacentHTML('afterend',    '<p>После box снаружи</p>');

/* Для готового DOM-элемента (только 1 элемент) и безопасного текста: */
box.insertAdjacentElement('beforeend', getNewParagraph());
box.insertAdjacentText('beforeend', 'Безопасный текст (как textContent)');
```

## 4. Удаление, клонирование и перемещение элементов (14:07–16:43)

[+] Все методы вставки (append, after и др.) автоматически ПЕРЕМЕЩАЮТ уже существующие на странице элементы — удалять их перед переносом не нужно.

```js
const box1 = document.querySelector('.box-1');
const box3 = document.querySelector('.box-3');

/* Удаление элемента из DOM (в переменной box1 он остаётся живым — можно вставить снова): */
box1.remove();

/* Клонирование элемента: */
const shallowClone = box1.cloneNode();     /* ПОВЕРХНОСТНОЕ: тег пустой, без детей! */
const deepClone = box1.cloneNode(true);    /* ГЛУБОКОЕ (но НЕ копирует addEventListener!) */
box1.after(deepClone);

/* Перемещение существующего элемента (box1 исчезнет со старого места и встанет за box3): */
box3.after(box1);
```

## 5. Быстрая очистка replaceChildren() и шпаргалка выбора

[+] Чтобы полностью очистить всё содержимое внутри контейнера без innerHTML = "", вызывают box.replaceChildren() (без аргументов — удалит всех детей).

[+] Шпаргалка выбора инструмента:
- Поменять или вставить только текст -> textContent (или insertAdjacentText).
- Вставить готовую HTML-строку без перезаписи соседей -> insertAdjacentHTML.
- Собрать пачку элементов в цикле -> createElement + DocumentFragment + append.
- Очистить всё внутри контейнера -> box.replaceChildren().

## 3 главные ловушки урока (чек-лист для повторения)

1. Вызвать elem.cloneNode() без аргумента true — получится пустая оболочка элемента без внутреннего текста и дочерних тегов.

2. Пытаться вставить одну и ту же переменную в 2 места сразу (она просто переедет в последнее место) или передавать HTML-строку "`<p>`...`</p>`" в append / textContent.

3. Дописывать множество новых элементов в цикле через box.innerHTML += ... (тормозит браузер полной перестройкой внутренностей) вместо append() / insertAdjacentHTML.

# Урок 32. Браузерные события: обработчики, всплытие и погружение

Суть урока: События вешают через addEventListener (и снимают по ссылке на ту же функцию через removeEventListener), а проходят они 3 фазы: погружение сверху вниз, целевой элемент (event.target) и всплытие вверх к document.

## 1. Три способа обработки событий и addEventListener (01:30–08:12)

[+] HTML-атрибут onclick="..." (требует вызова со скобками ()) и свойство button.onclick = fn (без скобок, только в нижнем регистре) ограничены 1 функцией — вторая затрёт первую. Единственный правильный способ — addEventListener.

```js
<!-- Способ 1 (устаревший, в HTML): нужны скобки вызова () -->
<button onclick="logMessage()">Нажми</button>

/* Способ 2 (в JS через свойство): БЕЗ скобок () и перетирает прошлый обработчик! */
const btn = document.querySelector('button');
const logMessage = () => console.log("Клик!");
btn.onclick = logMessage;   /* btn.onclick = logMessage() вызовет функцию СРАЗУ и сломает! */

/* Способ 3 (правильный): имя события без "on", можно вешать много обработчиков */
btn.addEventListener('click', () => console.log('Обработчик 1'));
btn.addEventListener('click', () => console.log('Обработчик 2'));

/* Полезные опции 3-го аргумента: */
btn.addEventListener('click', logMessage, { once: true }); /* 1 раз и удалится сам */
window.addEventListener('scroll', onScroll, { passive: true }); /* плавность на мобилках */
```

## 2. Удаление обработчика: removeEventListener (08:13–10:48)

[!] Чтобы снять обработчик через removeEventListener, нужно передать во 2-й аргумент ТУ ЖЕ САМУЮ функцию по ссылке. Анонимную стрелочную функцию удалить не получится!

```js
const firstBtn = document.querySelector('.button-1');
const secondBtn = document.querySelector('.button-2');
const onFirstClick = () => console.log('Клик по 1-й кнопке');

/* Вешаем по ссылке и снимаем по той же самой ссылке: */
firstBtn.addEventListener('click', onFirstClick);
secondBtn.addEventListener('click', () => {
  firstBtn.removeEventListener('click', onFirstClick);
});

/* ЛОВУШКА с .bind(): obj.fn.bind(obj) создаёт НОВУЮ функцию каждый раз! */
/* const boundFn = obj.fn.bind(obj); — сначала сохрани ссылку, потом передавай */
```

## 3. Объект event: target, currentTarget и this (10:49–15:40)

[+] Браузер передаёт первым аргументом в обработчик объект события event (координаты, зажатые клавиши Alt/Ctrl и ссылку на элемент).

```js
/* Разница между target и currentTarget (box3 вложен в box2 -> в box1): */
box1.addEventListener('click', function (event) {
  console.log(event.target);        /* самый глубокий элемент, куда РЕАЛЬНО кликнули */
  console.log(event.currentTarget); /* элемент, на КОТОРОМ висит обработчик (box1) */
  console.log(this);                /* в обычной function равен event.currentTarget */
});
/* В стрелочной () => {} свой this НЕ работает! Всегда надёжнее event.currentTarget */
/* Если внутри <button> лежит <span> или <svg>, event.target вернёт именно <span>,
   а НЕ кнопку — используйте event.currentTarget или event.target.closest("button") */
```

## 4. Всплытие (Bubbling) и его отмена (12:12–18:15)

[+] Событие сначала срабатывает на самом глубоком элементе (box3), затем всплывает вверх по родителям (box2 -> box1 -> ... -> document). Остановить всплытие можно двумя методами:

```js
box3.addEventListener('click', (event) => {
  /* Остановит подъём к родителям box2/box1, но другие обработчики на box3 СРАБОТАЮТ */
  event.stopPropagation();

  /* Остановит И подъём вверх, И все остальные обработчики на самом box3: */
  event.stopImmediatePropagation();
});
```

[!] Осторожнее со stopPropagation(): он создаёт «мёртвые зоны» — например, клик внутри кнопки со stopPropagation не дойдёт до document, и открытое выпадающее меню не закроется. Также помни: события focus и blur НЕ всплывают (всплывают focusin и focusout).

## 5. Три фазы события и перехват на погружении (18:16–21:14)

[+] Полный жизненный цикл события: 1) Погружение (Capturing) сверху вниз от window до цели -> 2) Цель -> 3) Всплытие (Bubbling) снизу вверх. По умолчанию addEventListener слушает только всплытие.

```js
/* 3-й аргумент { capture: true } (или просто true) включает перехват на ПОГРУЖЕНИИ */
box2.addEventListener('click', (event) => {
  console.log('Поймали сверху вниз раньше дочернего box3!');
  event.stopPropagation(); /* отменит погружение глубже (полезно для чужих виджетов) */
}, { capture: true });

/* ВАЖНО: чтобы снять такой обработчик, в removeEventListener ТОЖЕ передают capture! */
/* box2.removeEventListener('click', fn, { capture: true }); */
```

## 6. Короткая шпаргалка по событиям

- Вешать обработчик -> только addEventListener (одноразовый -> { once: true }).
- На что реально кликнули (внутри может быть иконка/текст) -> event.target (+ closest).
- На ком висит сам обработчик -> event.currentTarget (надёжнее, чем this).

## 3 главные ловушки урока (чек-лист для повторения)

1. Написать btn.onclick = fn() со скобками — функция вызовется мгновенно при старте страницы, а при клике работать перестанет.

2. Передать в addEventListener анонимную функцию () => ... и потом пытаться снять её через removeEventListener — без сохранённой в переменную ссылки не удалится.

3. Путать event.target (где кликнули) и event.currentTarget (чей обработчик сработал), или stopPropagation (только вверх) и stopImmediatePropagation (и на этом же элементе тоже).

# Урок 33. Делегирование событий, preventDefault и свои события

Суть урока: Делегирование позволяет ловить события сразу от всех (и даже будущих!) элементов одним слушателем на родителе + closest(), стандартные действия браузера отменяет preventDefault(), а модули общаются через CustomEvent и dispatchEvent().

## 1. Делегирование событий: один слушатель + closest() (00:31–08:31)

[!] Вешать click в цикле на каждый .todo-item плохо: 1) перегружает память при 1000+ элементов; 2) элементы, добавленные через JS позже, вообще не будут кликаться. Делегирование решает обе проблемы через 1 обработчик на родителе или document.

```js
const onTodoItemClick = (todoItemElement) => {
  todoItemElement.classList.toggle('is-completed');
};

/* Плохо для вложенных тегов (если внутри лежит <span>, event.target вернёт <span>!): */
/* if (event.target.classList.contains('todo-item')) ... */

/* ПРАВИЛЬНО: ищем от event.target вверх по дереву нужный элемент через closest() */
document.addEventListener('click', (event) => {
  const todoItemElement = event.target.closest('.todo-item');

  if (todoItemElement) {
    onTodoItemClick(todoItemElement);
  }
});

/* Если слушатель висит не на document, а на конкретном list, проверяй .contains(),
   чтобы closest() при вложенности не выскочил за пределы нужного контейнера: */
/* if (!todoItemElement || !listElement.contains(todoItemElement)) return; */

/* Приём с data-action: 1 слушатель обрабатывает разные кнопки по dataset.action */
/* const btn = event.target.closest('[data-action]'); */
/* if (btn?.dataset.action === 'delete') deleteItem(); */
```

[+] В реальном проекте слушатель списка лучше вешать не на весь document, а на ближайший статичный контейнер (todoListElement), чтобы не проверять лишние клики по шапке и футеру сайта. На document вешают только глобальные события.

## 2. Отмена действий браузера: event.preventDefault() (08:32–10:12)

[+] По клику на ссылку браузер уводит на другой URL, а по submit формы — отправляет запрос и перезагружает страницу. Чтобы отменить стандартное поведение (например, ради своей валидации формы), вызывают event.preventDefault().

```js
const linkElement = document.querySelector('a');
const formElement = document.querySelector('form');

linkElement.addEventListener('click', (event) => {
  event.preventDefault(); /* отменим переход по ссылке */
});

formElement.addEventListener('submit', (event) => {
  event.preventDefault(); /* отменим отправку и перезагрузку страницы */
});

/* Другой обработчик может узнать, отменили ли уже действие: event.defaultPrevented */
/* ВАЖНО: return false внутри addEventListener действие браузера НЕ отменяет! */
```

[!] Не путай два разных рычага: preventDefault() отменяет действие браузера (переход по ссылке / отправку), но событие продолжает всплывать. А stopPropagation() останавливает всплытие, но ссылка всё равно откроется!

## 3. Свои события: Event, CustomEvent и dispatchEvent (10:13–20:00)

[+] Свои события помогают разделить модули, чтобы они не дёргали функции друг друга напрямую (например, preloader.js просто сообщает о закрытии, а animateSections.js слушает это событие).

```js
/* --- Модуль preloader.js: отправляем событие после конца CSS-анимации fade-out --- */
const preloader = document.querySelector('.preloader');

preloader.addEventListener('animationend', (event) => {
  if (event.animationName === 'fade-out') {
    /* new Event(...) — если данные не нужны; CustomEvent — чтобы передать detail */
    preloader.dispatchEvent(new CustomEvent('preloaderClose', {
      bubbles: true,    /* обязательно true, иначе событие НЕ всплывёт до document! */
      cancelable: true, /* позволяет слушателям вызвать event.preventDefault() */
      detail: { animationName: event.animationName, time: event.elapsedTime },
    }));
    /* dispatchEvent() работает СИНХРОННО и вернёт false, если кто-то вызвал
       preventDefault() на кастомном событии с cancelable: true */
  }
});

/* --- Модуль animateSections.js: подписываемся на своё событие --- */
document.addEventListener('preloaderClose', (event) => {
  console.log(event.detail); /* { animationName: "fade-out", time: ... } */
  animateSections();
});
/* Совет: в проектах свои события удобно называть через двоеточие ("preloader:close",
   "cart:add"), чтобы они не пересекались со стандартными событиями браузера */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Проверять делегирование через event.target.classList.contains(...) вместо event.target.closest(...) — любой вложенный `<span>` или иконка внутри сломают клик.

2. Вешать клик на форму вместо события submit — отправка по клавише Enter проскочит мимо, и preventDefault() на кнопке не сработает.

3. Забыть bubbles: true при отправке new CustomEvent(...) на дочернем элементе — слушатель на document или родителе такое событие просто не поймает.

# Урок 34. События мыши и указателя (Pointer Events), Drag and Drop

Суть урока: Для наведения чаще берут mouseenter/mouseleave (без лишних срабатываний на детях), клик состоит из mousedown + mouseup, а для поддержки и мыши, и тачскрина используют Pointer Events (pointerdown, pointermove, pointerup).

## 1. Движение и наведение: mousemove, mouseover/out vs enter/leave (00:45–07:50)

[+] mousemove стреляет при каждом сдвиге мыши. mouseover / mouseout реагируют на наведение и увод, но СРАБАТЫВАЮТ повторно при переходе на любой вложенный тег (а relatedTarget при быстром движении или уходе за край окна может дать null).

```js
/* У mouseover / mouseout есть relatedTarget (откуда ушёл / куда перешёл курсор): */
box.addEventListener('mouseover', (event) => {
  console.log(event.target, event.relatedTarget); /* может быть null! */
});

/* mouseenter / mouseleave НЕ реагируют на внутренние дочерние элементы — удобнее! */
box.addEventListener('mouseenter', () => console.log('Вошли на сам блок целиком'));
box.addEventListener('mouseleave', () => console.log('Вышли за границы блока'));
/* ВАЖНО: mouseenter/mouseleave НЕ всплывают — их нельзя делегировать на document */
```

## 2. Нажатия мыши: mousedown, mouseup, click, dblclick, contextmenu (07:51–11:55)

[+] Обычный клик состоит из двух фаз на ОДНОМ элементе: 1) mousedown (нажали) -> 2) mouseup (отпустили) -> 3) click. Если зажать на кнопке, увести мышь в сторону и отпустить там — click НЕ сработает.

```js
btn.addEventListener('dblclick', () => console.log('Двойной клик'));

/* contextmenu — правая кнопка мыши; preventDefault() отменит системное меню: */
btn.addEventListener('contextmenu', (event) => {
  event.preventDefault();
});

/* Какая кнопка (mousedown) и какие клавиши были зажаты при клике: */
btn.addEventListener('mousedown', (event) => {
  console.log(event.button); /* 0 — левая, 1 — колёсико, 2 — правая */
  if (event.shiftKey || event.ctrlKey || event.metaKey) console.log("С модификатором");
});
```

## 3. События указателя (Pointer Events) для мыши, тача и стилуса (11:56–16:40)

[+] Pointer Events (pointerdown, pointermove, pointerup) работают одинаково с мышкой, пальцами на телефоне и стилусом, добавляя свойства для мультитача.

```js
document.addEventListener('pointerdown', (event) => {
  console.log(event.pointerType); /* "mouse" | "touch" | "pen" */
  console.log(event.pointerId);   /* у мыши всегда 1; у каждого пальца свой ID */
  console.log(event.isPrimary);   /* true для 1-го пальца, false для 2-го и далее */
  /* Захват указателя: все pointermove/up полетят в target, даже за пределы окна! */
  /* event.target.setPointerCapture(event.pointerId); */
});
```

## 4. Компонент Drag and Drop на Pointer Events (16:41–32:10)

[+] В CSS элементу с [data-js-dnd] задают position: absolute и touch-action: none (чтобы браузер на телефоне не скроллил экран вместо перетаскивания элемента). В JS события делегируем на document и не теряем this при передаче методов.

```js
class DragAndDrop {
  selectors = { root: '[data-js-dnd]' };
  stateClasses = { isDragging: 'is-dragging' };
  initialState = {
    offsetX: null, offsetY: null, isDragging: false, currentDraggingElement: null,
  };
  constructor() { this.resetState(); this.bindEvents(); }
  resetState() { this.state = { ...this.initialState }; }

  onPointerDown({ target, x, y }) {
    if (!target.matches(this.selectors.root)) return;
    /* Если внутри лежат <img>/<span>, задай им CSS pointer-events: none (или closest) */
    target.classList.add(this.stateClasses.isDragging);
    const { left, top } = target.getBoundingClientRect();
    this.state = {
      offsetX: x - left, offsetY: y - top, /* смещение от угла элемента */
      isDragging: true, currentDraggingElement: target,
    };
  }
  onPointerMove(event) {
    if (!this.state.isDragging) return;
    const x = event.pageX - this.state.offsetX; /* pageX/Y для absolute; clientX/Y — fixed */
    const y = event.pageY - this.state.offsetY;
    this.state.currentDraggingElement.style.left = `${x}px`;
    this.state.currentDraggingElement.style.top = `${y}px`;
  }
  onPointerUp() {
    if (!this.state.isDragging) return;
    this.state.currentDraggingElement.classList.remove(this.stateClasses.isDragging);
    this.resetState();
  }
  bindEvents() {
    /* Стрелочная обёртка сохраняет this экземпляра DragAndDrop (не document!) */
    document.addEventListener('pointerdown', (e) => this.onPointerDown(e));
    document.addEventListener('pointermove', (e) => this.onPointerMove(e));
    document.addEventListener('pointerup',   () => this.onPointerUp());
    /* Если тащим саму <img> (без div), отменяем встроенный dragstart браузера: */
    /* document.addEventListener('dragstart', (e) => { */
    /*   if (e.target.matches(this.selectors.root)) e.preventDefault(); */
    /* }); */
  }
}
new DragAndDrop();

/* Как в onPointerUp(event) узнать, над какой зоной ("миской") отпустили элемент? */
/* el.hidden = true;                                                               */
/* const elemBelow = document.elementFromPoint(event.clientX, event.clientY);      */
/* el.hidden = false;                                                              */
/* const dropzone = elemBelow?.closest('[data-js-dropzone]');                      */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Вешать mouseover / mouseout на карточку с детьми внутри и получать ложные срабатывания (для блока целиком бери mouseenter / mouseleave), или считать, что relatedTarget никогда не равен null.

2. Забыть touch-action: none в CSS для Drag and Drop на телефоне или не учесть смещение offsetX/offsetY от левого верхнего угла элемента (тогда карточка прыгнет углом под палец).

3. Передать в addEventListener метод класса напрямую без стрелки или bind (this.onPointerDown вместо (e) => this.onPointerDown(e)) — this внутри превратится в document и state сломается.

# Урок 35. События клавиатуры, ввода и буфера обмена

Суть урока: Клавиатурные keydown/keyup служат для горячих клавиш (по event.code, независимому от раскладки), живой ввод в поля отслеживают через input, финальную проверку после потери фокуса — через change, а буфер обмена — через cut/copy/paste.

## 1. Клавиатура: keydown, keyup, key vs code и модификаторы (00:28–07:53)

[+] keydown срабатывает при нажатии (и повторяется при удержании клавиши), keyup — при отпускании. Для горячих клавиш ориентируйтесь на event.code, а не на event.key!

```js
document.addEventListener('keydown', (event) => {
  if (event.repeat) return; /* true при автоповторе, если клавишу держат зажатой */
  console.log(event.key);   /* символ с учётом раскладки: "q" (ENG) или "й" (RUS) */
  console.log(event.code);  /* физическая клавиша: всегда "KeyQ" в любой раскладке */

  /* Спецклавиши-модификаторы (true/false): altKey, ctrlKey, shiftKey, metaKey */
  if ((event.ctrlKey || event.metaKey) && event.code === 'KeyS') {
    console.log('Нажали Ctrl+S / Cmd+S на Mac в любой раскладке!');
  }
});
/* event.keyCode (например, 81 или 32 для Space) — устаревшее свойство */
```

## 2. Отмена действий браузера на keydown (07:54–15:52)

[+] В keydown вызов event.preventDefault() отменяет действие браузера (скролл по PageDown, переход по Tab или появление запрещённого символа в поле ввода). Но системные комбинации ОС (закрытие окна) отменить нельзя.

```js
const anyDigitRegExp = /\d/; /* регулярное выражение: любая цифра */

document.addEventListener('keydown', (event) => {
  if (!event.target.matches('input')) return; /* фильтр через делегирование */

  if (anyDigitRegExp.test(event.key)) {
    event.preventDefault(); /* запретим вводить цифры (в keyup отменять уже ПОЗДНО!) */
    console.log('Цифра заблокирована:', event.key);
  }
  /* Минус keydown: вставку мышкой ("Вставить") он не ловит; чистите в input! */
});
```

## 3. События ввода: почему не keydown/keyup, а input и change (15:53–22:12)

[!] В keydown новое значение input.value ещё не успело обновиться (отстаёт на 1 шаг), а keyup не ловит вставку/вырезание мышкой из меню. Для полей ввода используют input и change.

```js
const input = document.querySelector('input');
const output = document.querySelector('.name-output');

/* input: срабатывает МГНОВЕННО при любом изменении (клавиатура, мышь, вставка) */
input.addEventListener('input', () => {
  /* Надёжная чистка от цифр (работает и после вставки мышкой, и на телефоне): */
  input.value = input.value.replace(/\d/g, '');
  output.textContent = input.value; /* preventDefault() здесь уже не отменит ввод */
});

/* Живой поиск с паузой (debounce через setTimeout): не бьёт сервер на каждую букву */
let searchTimerId;
input.addEventListener('input', () => {
  clearTimeout(searchTimerId);
  searchTimerId = setTimeout(() => console.log("Запрос:", input.value), 300);
});

/* change: у текстового поля — при ПОТЕРЕ фокуса; у <select>/checkbox/radio — СРАЗУ! */
input.addEventListener('change', () => {
  const isInvalid = input.value.length < 5;
  input.classList.toggle('is-invalid', isInvalid);
  /* Идеально для валидации и тяжёлых запросов, чтобы не дёргать на каждую букву */
});
```

## 4. События буфера обмена: cut, copy и paste (22:13–23:55)

[+] Срабатывают и по Ctrl+X/C/V, и через правый клик мыши. Старый способ event.clipboardData.getData("text/plain") работает только в paste (в cut/copy даёт ""). Современный navigator.clipboard.readText() работает везде.

```js
document.addEventListener('paste', (event) => {
  console.log(event.clipboardData.getData('text/plain')); /* только в paste */
  /* event.preventDefault(); — можно запретить вставку/копирование/вырезание */
});

/* Асинхронный Clipboard API (работает в cut/copy/paste, нужен HTTPS и разрешение): */
document.addEventListener('copy', () => {
  navigator.clipboard.readText().then((text) => console.log(text));
});
```

## 5. Шпаргалка выбора события клавиатуры и ввода

- Горячие клавиши (Esc, Ctrl+S) -> keydown + event.code.
- Счётчик символов, очистка лишнего или поиск с таймером (debounce) -> input.
- Валидация по завершении ввода, а также `<select>`, checkbox, radio -> change.
- Перехват или запрет копирования / вставки -> cut, copy, paste.

## 3 главные ловушки урока (чек-лист для повторения)

1. Проверять хоткеи через event.key === "s" вместо event.code === "KeyS" — на русской раскладке горячая клавиша перестанет работать.

2. Читать input.value в keydown (получите старое значение) или в keyup (пропустит вставку текста мышкой) вместо события input.

3. Вешать тяжёлую проверку/валидацию на input вместо change (будет бить ошибкой с первой буквы) или читать event.clipboardData в copy (вернёт пустую строку).

# Урок 36. События фокуса: focus/blur, focusin/focusout, tabindex, activeElement

Суть урока: focus и blur ловят вход/выход фокуса на конкретном элементе (не всплывают!), focusin и focusout позволяют делегировать фокус на родителе, tabindex делает доступным любой тег, а document.activeElement показывает кто в фокусе.

## 1. События focus и blur, отличие blur от change (00:25–04:35)

[+] Фокус появляется по клику или клавише Tab (назад — Shift + Tab). В отличие от change, событие blur сработает при уходе из поля ДАЖЕ если текст внутри в итоге не изменился (ввели пару букв и сразу стёрли).

```js
const loginInput = document.querySelector('#login');

/* Убираем красную рамку, когда пользователь вернулся в поле: */
loginInput.addEventListener('focus', () => {
  loginInput.classList.remove('is-invalid');
});

/* Ставим ошибку при уходе с пустого поля (change тут бы промолчал, если не меняли): */
loginInput.addEventListener('blur', () => {
  /* event.preventDefault() в blur НЕ удержит фокус! */
  if (loginInput.value.length === 0) {
    loginInput.classList.add('is-invalid');
  }
});
```

## 2. Программный фокус: методы focus(), blur() и autofocus (04:36–06:11)

[+] Фокусом можно управлять из JS. Если автофокус нужен сразу при открытии страницы, чаще ставят HTML-атрибут autofocus (но учтите: при старте браузер ставит его до подписки в JS, поэтому первое событие focus не поймается).

```js
<!-- В HTML: сразу ставит фокус при загрузке страницы -->
<input id="login" autofocus />

/* Программно через JS: */
loginInput.focus(); /* поставить фокус (браузер сам прокрутит страницу к элементу) */
loginInput.focus({ preventScroll: true }); /* поставить фокус БЕЗ прокрутки экрана */
setTimeout(() => loginInput.blur(), 2000); /* принудительно снять фокус */
```

[!] Почему focus() молча не срабатывает: 1) элемент скрыт (display: none / visibility: hidden — сначала покажи, потом фокусируй); 2) у `<div>` нет tabindex; 3) поле disabled. В CSS для красивой рамки только с клавиатуры берите :focus-visible.

## 3. Делегирование фокуса: focusin и focusout (06:12–07:50)

[!] События focus и blur НЕ всплывают — повесить их на document или форму не получится. Для делегирования используют всплывающие аналоги focusin и focusout.

```js
document.addEventListener('focusin', (event) => {
  if (event.target.matches('input')) {
    console.log('В фокусе инпут:', event.target);
  }
});

document.addEventListener('focusout', (event) => {
  if (event.target.matches('input')) {
    console.log('Ушёл с:', event.target, 'На элемент:', event.relatedTarget);
  }
  /* Кейс с меню: if (!menu.contains(event.relatedTarget)) closeMenu(); */
});
/* focusin / focusout вешаются ТОЛЬКО через addEventListener (не onfocusin) */
```

## 4. Интерактивные элементы и атрибут tabindex (07:51–09:51)

[+] По умолчанию фокус берут только интерактивные элементы (input, button, a). Обычный `<div>` клавиша Tab пропускает, пока не задан атрибут tabindex:

```html
<!-- В 99% используют только два значения: 0 или -1 -->
<div tabindex="0">Можно дойти по Tab (в порядке разметки) и кликом</div>
<div tabindex="-1">Tab пропустит, но можно вызвать div.focus() из JS</div>
<!-- Положительные tabindex="1", "2" ломают естественный порядок — не используйте -->
/* В JavaScript это свойство пишется в camelCase с заглавной I: elem.tabIndex = 0; */
```

## 5. Кто сейчас в фокусе: document.activeElement (09:52–12:18)

[+] Свойство document.activeElement хранит DOM-элемент, который прямо сейчас в фокусе. Если скрытая через transform: scale(0) модалка ворует Tab, в DevTools Console можно включить Live Expression (иконка глаза) и вписать туда document.activeElement.

```js
console.log(document.activeElement); /* текущий элемент в фокусе (или body) */

/* Паттерн модалки: запомнить где был фокус и вернуть его при закрытии */
let lastActiveElement = null;
function openModal(modal, closeBtn) {
  lastActiveElement = document.activeElement; /* сохраняем кнопку открытия */
  modal.classList.add('is-open');
  closeBtn.focus();
}
function closeModal(modal) {
  modal.classList.remove('is-open');
  lastActiveElement?.focus(); /* возвращаем фокус обратно на кнопку */
}
```

## 6. Короткая шпаргалка по событиям фокуса

- Один конкретный элемент -> focus / blur.
- Делегирование на форме/списке -> focusin / focusout.
- Закрыть меню при уходе фокуса -> focusout + !menu.contains(event.relatedTarget).

## 3 главные ловушки урока (чек-лист для повторения)

1. Вешать focus или blur на document / родительскую форму для делегирования — они не всплывают; бери focusin и focusout.

2. Проверять пустое обязательное поле через change вместо blur — если зайти в поле и уйти ничего не введя, change не сработает.

3. Прятать модалку или дропдаун через transform: scale(0) / opacity: 0 — их кнопки остаются в очереди Tab и незаметно крадут фокус (прячьте display: none / visibility: hidden).

# Урок 37. Формы в JS: доступ к полям, чтение/запись и атрибут form

Суть урока: Доступ к формам и полям берут через document.forms и form.elements (по name), внешние поля привязывают к форме атрибутом form="id", а значения читают через .value (input, textarea, select, radio), .checked (checkbox) и .selectedOptions.

## 1. Навигация: document.forms, form.elements и доступ по name (00:49–03:57)

[+] document.forms — живая HTMLCollection всех форм на странице. У самой формы свойство elements хранит живую коллекцию всех её полей (input, textarea, select, fieldset, button), куда можно обращаться по атрибуту name.

```js
const formElement = document.forms.regForm; /* форма по её id / name (или [0]) */

/* Два одинаковых способа получить поле по атрибуту name="login": */
const loginInput1 = formElement.elements.login;
const loginInput2 = formElement.login; /* короткая запись без .elements */

/* Для радиокнопок с одним name="gender" вернёт коллекцию RadioNodeList: */
const genderRadios = formElement.gender;

/* Совет: form.elements.login надёжнее короткого form.login (после смены .name */
/* старое имя исчезает из elements, но остаётся в form). Не называйте поля */
/* name="submit" или "reset" — иначе перетрёте методы formElement.submit() / reset()! */
/* <fieldset> тоже имеет своё .elements, а fieldset.disabled = true отключит всё внутри */
formElement.reset();  /* сбросит все поля к исходным значениям из HTML */
formElement.submit(); /* отправит форму сразу, НЕ вызывая JS-событие submit! */
/* readonly — запрет правки, но фокус работает и поле уходит при отправке; */
/* disabled — нет ни фокуса, ни клика, и поле вообще НЕ попадает в отправку! */
```

## 2. Поле за пределами формы: свойство и атрибут form (03:58–06:32)

[+] У каждого поля есть свойство field.form со ссылкой на его форму (или null). Если по дизайну элемент лежит в HTML за пределами тега `<form>`, просто укажите ему атрибут form="idФормы" — он сразу попадёт в form.elements и уйдёт при отправке!

```html
<!-- В HTML <select> стоит отдельно, но привязан к форме id="regForm": -->
<form id="regForm">...</form>
<select name="city" form="regForm">...</select>

const citySelect = document.querySelector('[name="city"]');
console.log(citySelect.form); /* теперь ссылается на <form id="regForm">! */
```

## 3. Поля ввода: `<input>` и `<textarea>` (06:33–08:16)

[!] Несмотря на то, что в HTML у `<textarea>` текст лежит между тегами, в JS у обоих полей читают и меняют ТОЛЬКО свойство .value (не textContent и не innerHTML!).

```js
const aboutTextarea = formElement.about;
aboutTextarea.value = 'Новое описание';
console.log(aboutTextarea.value);       /* "Новое описание" — верно */
console.log(aboutTextarea.textContent); /* ОШИБКА: старый текст из HTML-разметки! */

/* Запись из JS не запускает события input/change — они только от действий юзера! */
/* HTML-атрибут value (input.defaultValue / defaultChecked) хранит стартовое значение: */
console.log(loginInput1.getAttribute('value')); /* старт из HTML (к нему вернёт reset) */
```

## 4. Радиокнопки (type="radio") и чекбоксы (type="checkbox") (08:17–14:24)

[!] В HTML всегда задавайте радиокнопкам value="..." (иначе вернётся слово "on"). А состояние чекбокса проверяют ТОЛЬКО через .checked (его value всегда "on", даже если галочка не стоит!).

```js

formElement.gender.value = 'мужской';  /* программно переключит нужную радиокнопку */
/* Если указать несуществующее value — ничего не изменится; либо radios[0].checked = true */

/* Чекбокс (например, согласие с правилами name="agreement"): */
const agreementCheckbox = formElement.agreement;
console.log(agreementCheckbox.value);   /* ОПАСНО: "on", даже когда НЕ отмечен! */
console.log(agreementCheckbox.checked); /* ПРАВИЛЬНО: true или false */
agreementCheckbox.checked = true;       /* поставить галку (НЕ вызовет событие change!) */
```

## 5. Выпадающий список `<select>` и `<select multiple>` (14:25–19:22)

[+] У обычного `<select>` браузер по умолчанию выбирает первый `<option>`. Менять и читать выбор удобнее через select.value. А при атрибуте multiple обычный .value покажет только 1-й пункт — нужно брать коллекцию select.selectedOptions.

```js
/* Альтернатива через options и индекс: */
console.log(citySelect.options[citySelect.selectedIndex].value);

/* Множественный выбор (<select multiple>): читаем все через selectedOptions: */
const selectedCities = [...citySelect.selectedOptions].map((opt) => opt.value).join(", ");

/* Быстро создать новый пункт <option> без createElement: new Option(text, value, ...) */
citySelect.append(new Option('Казань', 'kazan', true, true)); /* defaultSelected, selected */
```

# Урок 38. Формы в JS: событие submit и сбор данных через FormData

Суть урока: Отправку формы перехватывают через событие submit и event.preventDefault(), а данные со всех полей собирают одной строкой через new FormData(formElement) — эта коллекция устроена как Map и читается через forEach или Object.fromEntries(formData).

## 1. Событие submit и отмена стандартной отправки (01:08–02:23)

[+] По умолчанию отправка формы перезагружает страницу (браузер шлёт запрос на адрес из атрибута action методом из атрибута method — GET или POST). Событие submit срабатывает как при клике по кнопке отправки (`<button>` без type="button" — это submit!), так и по нажатию Enter в любом `<input>` (при этом браузер сам генерирует click по кнопке). Чтобы собрать данные в JS, отменяем стандартное поведение браузера.

```js
const formElement = document.forms.regForm;

formElement.addEventListener('submit', (event) => {
  event.preventDefault(); /* отменяет перезагрузку страницы при клике на отправку */
  /* дальше здесь собираем данные и отправляем на сервер через JS */
});
```

## 2. Ручной обход formElement.elements и его проблемы (02:24–07:21)

[!] Если просто перебирать formElement.elements циклом for..of, приходится вручную фильтровать пустые элементы, чекбоксы, радиокнопки, select multiple и файлы.

```js
const formData = {};

for (const element of formElement.elements) {
  /* 1. У <fieldset> и <button> нет name — без проверки появится ключ "" */
  if (!element.name) continue;

  /* 2. У checkbox свойство .value всегда "on", даже когда галочка не стоит! */
  if (element.type === 'checkbox') {
    formData[element.name] = element.checked; /* берём true или false */
    continue;
  }

  /* 3. Радиокнопок с одним name несколько — невыбранные перезапишут ключ! */
  if (element.type === 'radio' && !element.checked) continue;

  formData[element.name] = element.value;
}
```

## 3. Сбор данных через new FormData и чтение значений (07:22–10:13)

[+] Класс FormData сам собирает значения всех полей формы (включая select и file) без ручных проверок. Внутри он похож на коллекцию Map, поэтому console.log(formData) в консоли выглядит пустым — пары ключ/значение смотрят через цикл, forEach или Object.

```js
formElement.addEventListener('submit', (event) => {
  event.preventDefault();

  /* Передаём DOM-элемент формы — FormData сам соберёт все поля по атрибуту name: */
  const formData = new FormData(formElement);
  console.log(formData); /* в консоли будет пустой объект {}, но данные внутри есть! */

  /* Способ 1 — встроенный forEach (ВНИМАНИЕ: 1-й аргумент value, 2-й name!): */
  formData.forEach((value, name) => {
    console.log(`${name}: ${value}`);
  });

  /* Способ 2 — перебрать пары через цикл for..of: */
  for (const [name, value] of formData) {
    console.log(name, value);
  }

  /* Способ 3 (самый наглядный для отладки) — превратить в обычный JS-объект: */
  console.log(Object.fromEntries(formData)); /* на сервер шлём сам formData, не его! */
  /* ВНИМАНИЕ: если у ключа несколько значений, Object.fromEntries оставит лишь последнее! */
  /* FormData НЕ собирает поля без name, disabled и неотмеченные checkbox/radio! */

  /* Можно создать пустую коллекцию new FormData() без формы и слать через fetch: */
  /* fetch('/api', { method: 'POST', body: formData }) — Content-Type ставить НЕ нужно */
  /* Если бэкенд ждёт JSON (без файлов): JSON.stringify(Object.fromEntries(formData)) */
});
```

## 4. Методы FormData: append, set, get, getAll, has, delete (10:14–11:15)

[+] Готовую коллекцию FormData можно дополнять своими данными, перезаписывать ключи, проверять наличие полей или удалять лишние записи перед отправкой на сервер.

```js
/* append(name, value[, filename]) — ДОБАВЛЯЕТ значение (не затирает старое!): */
formData.append('tag', 'js');
formData.append('tag', 'dom'); /* теперь у ключа 'tag' сразу два значения */

/* set(name, value) — ЗАМЕНЯЕТ: удаляет все старые записи с этим ключом и пишет новую: */
formData.set('tag', 'forms');

/* get(name) вернёт только 1-е значение (или null), getAll(name) — массив всех значений: */
console.log(formData.get('tag'));    /* 'forms' */
console.log(formData.getAll('tag')); /* ['forms'] */

/* has(name) — проверить наличие записи (true или false): */
console.log(formData.has('tag')); /* true */

/* delete(name) — удалить запись (все значения по этому имени) из коллекции: */
formData.delete('tag');
console.log(formData.has('tag')); /* false */

/* Все значения внутри FormData — строки (или File): даже число станет строкой! */
formData.append('age', 25); console.log(typeof formData.get('age')); /* 'string' */
/* Пустой <input type="file"> без файла даст объект File с size === 0 и name: "" */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть event.preventDefault() внутри обработчика submit — браузер перезагрузит страницу по атрибуту action, и JS не успеет обработать или отправить данные.

2. Увидеть пустой объект {} в console.log(formData) и решить, что поля не собрались: проверять содержимое нужно через Object.fromEntries(formData) или formData.forEach.

3. Перепутать порядок аргументов в formData.forEach((value, name) => ...) — как и в Map, первым параметром всегда приходит значение (value), а вторым имя поля (name).

# Урок 39. Валидация форм: свойство validity и компонент FormsValidation

Суть урока: Нативные правила задают в HTML (required, minlength, maxlength, pattern, title), стандартные тултипы отключают атрибутом novalidate и проверяют поля в JS через field.validity (объект ValidityState) на событиях blur (с capture: true), change и submit.

## 1. Нативная валидация HTML и разметка под кастомные ошибки (00:36–06:35)

[+] Браузер умеет проверять поля по HTML-атрибутам и CSS-псевдоклассам :user-valid / :user-invalid, но стандартные тултипы нельзя стилизовать. Поэтому на `<form>` ставят novalidate, а правила из HTML читают в JS и связывают поля с `<span>` ошибок для a11y.

```html
<!-- novalidate отключает браузерные тултипы; data-js-form — метка для JS: -->
<form id="regForm" novalidate data-js-form>
  <p class="field">
    <input id="login" name="login" required minlength="3" maxlength="12"
           aria-errormessage="login-errors" /> <!-- связь для скринридера -->
    <!-- Для пароля задают pattern="..." (регулярка) и title="Пояснение формата" -->
    <span class="field__errors" id="login-errors" data-js-form-field-errors></span>
  </p>
</form>
```

## 2. Класс FormsValidation: поля класса и перехват blur (06:41–12:03, 14:15–22:25)

[!] Событие blur (уход фокуса с поля), как и событие invalid при нативной проверке, НЕ всплывает вверх по DOM-дереву, поэтому на document его перехватывают на фазе погружения через третий аргумент { capture: true }.

```js
class FormsValidation {
  selectors = {
    form: '[data-js-form]',
    fieldErrors: '[data-js-form-field-errors]',
  };

  /* Ключи совпадают со свойствами ValidityState; функции получают DOM-элемент поля: */
  errorMessages = {
    valueMissing: () => 'Пожалуйста, заполните это поле',
    patternMismatch: ({ title }) => title || 'Данные не соответствуют формату',
    /* В HTML атрибут minlength/maxlength, а в JS-свойстве — camelCase minLength/maxLength! */
    tooShort: ({ minLength }) => `Слишком короткое значение, минимум символов — ${minLength}`,
    tooLong: ({ maxLength }) => `Слишком длинное значение, максимум символов — ${maxLength}`,
  };

  constructor() {
    this.bindEvents();
  }

  bindEvents() {
    document.addEventListener('blur', (event) => this.onBlur(event), { capture: true });
    document.addEventListener('change', (event) => this.onChange(event));
    document.addEventListener('submit', (event) => this.onSubmit(event));
  }

  onBlur({ target }) {
    const isFormField = target.closest(this.selectors.form);
    const isRequired = target.required;
    if (isFormField && isRequired) this.validateField(target);
  }
```

## 3. Свойство field.validity (ValidityState) и вывод ошибок (12:04–28:35)

[+] Свойство fieldControlElement.validity хранит объект ValidityState, где каждому типу ошибки соответствует true/false. На основании флагов собираем массив сообщений, выводим их в `<span>` через innerHTML и обновляем ariaInvalid для доступности.

```js
  validateField(fieldControlElement) {
    const errors = fieldControlElement.validity; /* объект ValidityState с true/false */
    const errorMessages = [];
```

```js
  onChange({ target }) {

    });

      event.preventDefault(); /* останавливаем отправку формы */
      firstInvalidFieldControl.focus(); /* удобный UX: фокус в 1-е поле с ошибкой */
    }
  }
```

# Урок 41. Браузерные хранилища: cookie, localStorage, sessionStorage и IndexedDB

Суть урока: Все браузерные хранилища привязаны к домену и переживают перезагрузку страницы: cookies (~4 КБ) нужны для работы с сервером, sessionStorage живёт до закрытия вкладки, localStorage хранится вечно (5+ МБ), а IndexedDB — сложная БД для оффлайн-PWA.

## 1. Работа с document.cookie: запись, чтение и удаление (00:22–10:35)

[+] Свойство document.cookie работает как сеттер (добавляет/обновляет 1 запись по ключу, не затирая остальные) и геттер (возвращает все куки одной строкой через "; "). Лимит: до ~20 записей на домен и ~4 КБ на одну куку; главное назначение — токены и сессии.

```js
/* Запись, опции (path, max-age, secure, samesite) и кодирование пробелов/символов: */
/* Серверные куки с httpOnly полностью скрыты от JS (защита от кражи через XSS)! */
const setCookie = (name, value, options = {}) => {
  const fullOptions = { path: '/', ...options }; /* без path=/ кука видна лишь на URL */
  let newEntryBody = `${encodeURIComponent(name)}=${encodeURIComponent(value)}`;
  const optionsString = Object.entries(fullOptions)
    .map(([key, val]) => `${key}=${val}`)
    .join('; ');
  if (optionsString) newEntryBody += `; ${optionsString}`;
  document.cookie = newEntryBody;
};

/* Удаление куки в коде — ставим отрицательный срок жизни max-age: -1 */
const deleteCookie = (name) => setCookie(name, '', { 'max-age': -1 });

/* Чтение нужной куки по имени (парсим строку вида "a=1; b=2"): */
const getCookie = (name) => {
  for (const entryStr of document.cookie.split('; ')) {
    const [entryName, entryValue] = entryStr.split('=');
    if (decodeURIComponent(entryName) === name) return decodeURIComponent(entryValue);
  }
};
```
