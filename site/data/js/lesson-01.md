# Урок 01. Введение: подключение JS, console.log, синтаксис и ошибки

Суть урока:

- **Подключение:** `<script src="script.js"></script>` ставят перед `</body>` (или в `<head>` с атрибутом `defer`).
- **Отладка и синтаксис:** вывод смотрят в DevTools -> Console, а `;` обязательно ставят перед `[` и `(` из-за авто-подстановки ASI.
- **Ошибки:** любая ошибка останавливает выполнение всего дальнейшего кода файла.

## 1. Подключение JS к странице и атрибуты defer / async (01:46–02:44)

[+] Браузер читает HTML сверху вниз: обычный `<script>` в `<head>` блокирует отрисовку страницы и не видит разметку ниже. Поэтому ставят в конце `<body>` или с defer в `<head>`.

```html
<!-- 1. В конце разметки (код внутри тега с атрибутом src игнорируется) -->
<script src="script.js"></script>
</body>

<!-- 2. В <head>: defer ждёт DOM и порядок; async (аналитика) — нет -->
<script src="script.js" defer></script>

<!-- Два РАЗНЫХ тега работают вместе: внешний файл + отдельный <script> -->
<script src="script.js" defer></script>
<script>console.log('Готово', 2026);</script>
```

### Что будет, если подключить один скрипт дважды

[!] Если оставить и `<script src="script.js" defer>` в `<head>`, и `<script src="script.js">` внизу страницы, обычный скрипт выполнится **два раза** (в отличие от `type="module"`):

1. **Обратный порядок запуска:** сначала сразу выполнится нижний тег без `defer`, а после разбора всего HTML — верхний тег с `defer`.
2. **Сеть:** повторно файл не скачивается — браузер берёт его из кэша.
3. **Ошибки и дубли:** если в файле есть `let` или `const` на верхнем уровне, второй запуск упадёт с `SyntaxError: Identifier '...' has already been declared`; а `console.log` и `addEventListener` сработают дважды.
4. **А как с `type="module"`:** у ES-модулей есть дедупликация по URL — браузер запоминает выполненный модуль и второй тег `<script type="module" src="...">` просто игнорирует (но дублировать тег в HTML всё равно не нужно).

## 2. Вывод данных в DevTools -> Console (02:45–03:43)

[+] console.log(...) выводит неограниченное число значений через запятую в консоль браузера (клавиша F12). Для наглядности таблиц и ошибок есть table, warn и error.

```js
console.log('Привет', 555, true); /* аргументы перечисляют через запятую */
console.table([10, 20, 30]);      /* таблица для массивов и объектов */
console.error('Ошибка!');         /* красное сообщение с трассировкой стека */
```

## 3. Инструкции, ловушка ; (ASI) и комментарии (03:44–06:09)

[!] Каждую инструкцию пишут с новой строки. Движок сам подставляет `;` (механизм ASI), но перед строкой с `[` или `(` точку с запятой ставить ОБЯЗАТЕЛЬНО, иначе строки склеятся! Для комментариев есть однострочный `//` (горячая клавиша `Ctrl + /`) и блочный `/* ... */` (вкладывать `/*` внутрь другого `/* ... */` нельзя — будет `SyntaxError`).

```js
console.log('Привет 1');
/* Без ";" выше JS склеил бы вызов в console.log('Привет 1')[1, 2]! */
[1, 2];

/*
  Многострочный блочный комментарий:
  вкладывать один блочный комментарий внутрь другого НЕЛЬЗЯ (SyntaxError)!
*/
```

## 4. Обнаружение и чтение ошибок в консоли (06:10–07:25)

[+] При ошибке выполнение файла сразу прерывается. Справа от красной плашки ошибки указана кликабельная ссылка вида `script.js:2:9` — клик по ней открывает точную строку во вкладке `Sources`.

4 главные ошибки в консоли, с которыми сталкиваешься каждый день:

- **`SyntaxError`** — ошибка грамматики (не закрыта кавычка/скобка, вложенный `/* /* */ */`). Ломает файл ещё до старта: **не выполнится ни одна строчка**, даже самая первая.
- **`ReferenceError`** — обращение к несуществующей переменной (`console.log(userName)`). Код **до** этой строки успеет выполниться, дальше остановится.
- **`TypeError`** — неверное действие со значением: опечатка в методе (`console.lg(...)`), чтение свойства у `undefined` или попытка перезаписать `const`.
- **`RangeError`** — выход за допустимые границы (бесконечная рекурсия `Maximum call stack size exceeded` или слишком большой аргумент вроде `(10).toFixed(200)`).

```js
/* SyntaxError: если забыть скобку, не выполнится даже первая строка файла */

/* ReferenceError: переменная userAge нигде не объявлена */
console.log(userAge);

/* TypeError: у console нет метода lg (опечатка вместо log) */
console.lg('Тест');

/* RangeError: у toFixed разрешено от 0 до 100 знаков после запятой */
(10).toFixed(200);
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Подключить `<script src="...">` в `<head>` без defer (не найдёт HTML-элементы) или написать JS внутрь тега, у которого уже есть атрибут src (внутренний код проигнорируется).

2. Отказаться от ; и начать следующую строку с [ или ( — механизм ASI не поставит точку с запятой, и код упадёт.

3. Вложить многострочный комментарий /* /* */ */ внутрь другого (SyntaxError) или ждать, что код после ошибки в консоли продолжит выполняться.

**1. Что выведется в консоль и когда загрузится скрипт, если написать в `<head>` такой тег: `<script src="app.js">console.log('Внутри тега');</script>`?**

<details>
<summary>Показать ответ</summary>

Строка `'Внутри тега'` вообще не выполнится: если у тега `<script>` указан атрибут `src`, браузер полностью игнорирует всё, что написано между открывающим и закрывающим тегами. При этом сам `app.js` без `defer` или `async` заблокирует разбор HTML в `<head>` и запустится до создания `<body>`.

</details>

**2. Почему этот код падает с ошибкой, хотя две команды стоят на разных строках?**

```js
console.log('Старт')
[10, 20]
```

<details>
<summary>Показать ответ</summary>

Механизм автоматической вставки точки с запятой (ASI) не ставит `;` перед строкой, начинающейся с квадратной `[` или круглой `(` скобки. Движок склеивает две строки в одну: `console.log('Старт')[10, 20]`, пытается обратиться к индексу у результата `console.log` (`undefined`) и падает с `TypeError`.

</details>

**3. Чем отличается падение скрипта из-за вложенного комментария `/* /* */ */` от падения из-за опечатки `console.lg('Тест')`?**

<details>
<summary>Показать ответ</summary>

Вложенный комментарий `/* /* */ */` ломает код на этапе чтения (парсинга) — браузер выдаст `SyntaxError`, и в файле не выполнится ни одна строчка, даже самая первая. Опечатка `console.lg(...)` — ошибка времени выполнения (`TypeError`): весь код до неё успеет отработать, а всё, что написано ниже строки с ошибкой, будет остановлено.

</details>

## Задачи

**Задача 1. Почини подключение скриптов в `<head>`**

В разметке внутри `<head>` допущены три ошибки подключения скриптов. Исправь их:

1. Основной скрипт `app.js` должен качаться параллельно и запускаться строго после построения всего HTML.
2. Независимый счётчик `analytics.js` должен загружаться и выполняться сразу по готовности, не блокируя страницу и не ожидая другие файлы.
3. Вызов `console.log('Аналитика старт')` сейчас игнорируется браузером — вынеси его так, чтобы он реально сработал.

```html
<head>
  <meta charset="UTF-8">
  <!-- Твоё решение: -->
  <script src="app.js"></script>
  <script src="analytics.js">
    console.log('Аналитика старт');
  </script>
</head>
```

<details>
<summary>Подсказка и решение</summary>

```html
<head>
  <meta charset="UTF-8">
  <!--
    defer: скрипт качается параллельно HTML, не блокирует рендер
    и запускается строго после построения DOM (в порядке подключения)
  -->
  <script src="app.js" defer></script>

  <!--
    async: независимый скрипт для аналитики — качается и запускается
    сразу по готовности, не дожидаясь DOM и других скриптов
  -->
  <script src="analytics.js" async></script>

  <!--
    Отдельный <script> без src: браузер игнорирует внутренний код,
    если у тега есть атрибут src, поэтому выносим вызов отдельно

  <script>

  </script>
</head>
```

</details>

## Всё, что прошли

- **Подключение `<script>`:** ставим перед `</body>` или в `<head>` с `defer` (ждёт HTML и соблюдает порядок); `async` — только для независимых скриптов вроде аналитики; код внутри `<script src="...">...</script>` браузер игнорирует.

- **Вывод в консоль (`F12`):** `console.log(...)` (через запятую), `console.table(...)` (таблицы), `console.warn(...)` и `console.error(...)`.

- **Точка с запятой и ASI:** JS сам ставит `;` при переносе строки, но перед строкой с `[` или `(` точку с запятой ставить **обязательно**.

- **Комментарии:** `//` (однострочный) и `/* ... */` (многострочный, но вкладывать `/* /* */ */` друг в друга нельзя — `SyntaxError`).

- **Ошибки в консоли:** при ошибке выполнение файла ниже этой строки останавливается (`SyntaxError` — ломает весь файл до старта; `ReferenceError` — переменная не найдена; `TypeError` — опечатка в методе / неверный тип; `RangeError` — выход за пределы); ссылка справа (`script.js:2:9`) открывает точную строку во вкладке `Sources`.
