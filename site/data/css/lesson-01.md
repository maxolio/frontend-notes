# Урок 01. Введение в CSS: подключение, каскад, специфичность и наследование

Суть урока: CSS (Cascading Style Sheets) отвечает за внешний вид HTML-скелета; подключать его лучше внешним файлом через `<link rel="stylesheet">`, а итоговый стиль элемента вычисляется через каскад источников, вес правил (специфичность) и наследование.

## 1. Что такое CSS и 3 способа подключения (00:28–03:12)

[+] HTML — это скелет страницы, CSS — визуальный слой (цвета, шрифты, размеры, позиционирование), JS — логика поведения. Стили подключают тремя способами, но в реальных проектах используют внешний файл .css (не смешивая разметку и оформление).

```html
<!-- 1. Инлайн-стиль (в атрибуте style, свойства через ; — плохая практика): -->
<p style="color: green; font-weight: 700;">Текст</p>

<!-- 2. Тег <style> в <head> (допустимо, но мешает HTML и CSS в одном файле): -->
<head>
  <style>
    p { color: red; }
  </style>
</head>

<!-- 3. Внешний файл (лучший способ — одиночный <link> в <head>): -->
<head>
  <link rel="stylesheet" href="styles.css" />
  <!-- Если подключить несколько <link>/<style>, при равном весе победит НИЖНИЙ -->
</head>
```

## 2. Анатомия CSS-правила (03:13–05:10)

[+] Любой CSS состоит из правил: селектора (к каким элементам применяем) и блока в фигурных скобках { свойство: значение; }. Селектор по тегу (p, a) затрагивает буквально каждый такой тег на странице.

```css
/* Селектор по тегу -> применяет стили ко всем <p> на странице: */
p {
  color: red;       /* двоеточие после свойства, ; в конце ОБЯЗАТЕЛЬНА */
  font-weight: 700; /* каждое новое свойство — с новой строки для читаемости */
}

a {
  color: green;
}
```

## 3. Каскад и источники стилей (05:11–06:45)

[+] Каскад — механизм разрешения конфликтов, когда к одному элементу подходит несколько правил. Он учитывает источник правила, его специфичность и порядок. Источники стилей идут по возрастанию приоритета (от слабого к сильному):

```css
/* Приоритет источников (снизу вверх — побеждает более сильный источник): */
/* 1. Браузерные стили (User-Agent: отступы у h1, p, списков и т.д.) */
/* 2. Пользовательские стили (например, расширения вроде AdBlock) */
/* 3. Авторские стили (код разработчика в .css и <style>) */
/* 4. Стили CSS-анимаций (animation) */
/* 5. Авторские стили с !important (использовать крайне редко!) */
/* 6. Пользовательские стили с !important */
/* 7. Браузерные стили с !important */
/* 8. Стили во время CSS-переходов (transition) */
```

## 4. Специфичность (вес правила) (06:46–08:28)

[+] Специфичность — это «вес» правила: более тяжёлое правило перебивает более лёгкое. Инлайн-атрибут style="..." тяжелее правил из `<style>` и внешнего CSS. Флаг !important перебивает даже style="...", но злоупотреблять им нельзя.

<!-- demo-html:
<p>Первый абзац (без style — сработает каскад CSS)</p>
<p style="color: green;">Второй абзац (инлайн style="color: green;")</p>
-->
```css
/* Обычный вес (0-0-1): при равном весе победит НИЖНЕЕ правило (blue) */
p {
  color: red;
}

p {
  color: blue;
}

/* !important перебьёт даже инлайн style="color: green;" (использовать редко!) */
/* p { color: red !important; } */
```

## 5. Наследование и комментарии в CSS (08:29–10:33)

[+] Наследование — передача свойств от родителя ко всем вложенным потомкам (например, от header к nav -> ul -> li). Наследуются в основном текстовые свойства (color, font-*, text-shadow), оформление списков, cursor и visibility.

[!] Большинство свойств (рамки, фоны, отступы, размеры) НЕ наследуются. Ссылки `<a>` и кнопки `<button>`/`<input>` кажутся «упрямыми» при наследовании color/font от body только из-за собственных браузерных стилей — им явно пишут inherit.

```css
/* Наследуется потомками (кроме <a> и <button>/<input> с их браузерными стилями) */
body {
  color: #222;
  font-family: sans-serif;
}

/* Принудительно забираем цвет у родителя */
a {
  color: inherit;
}

/* Забираем шрифт и размер у родителя */
button {
  font: inherit;
}

/* Комментарии // в CSS запрещены — они сломают следующее правило! */
```

## 3 главные ловушки урока (чек-лист для повторения)

1. Писать комментарии через // (как в JS) или забывать ; в конце свойства — браузер отбросит сломанную строку и может пропустить следующее правило.

2. Думать, что `<a>` и `<button>` не наследуют color или font-family от body — наследуют, просто их перебивают встроенные стили браузера (исправляется через inherit).

3. Лечить конфликты стилей добавлением !important или инлайнового style="..." — потом такие правила почти невозможно переопределить в проекте.

## Вопросы для закрепления

**1. В `<head>` сначала подключён `<link rel="stylesheet" href="theme.css">` (где `p { color: blue; }`), а строкой ниже — тег `<style>p { color: red; }</style>`. Какого цвета станет текст `<p>` и почему?**

<details>
<summary>Показать ответ</summary>

Текст станет **красным (`red`)**. И внешний файл `<link>`, и тег `<style>` относятся к одному источнику (авторские стили) и имеют одинаковый селектор (`p`) с равной специфичностью. При равном весе и одном источнике каскад выбирает правило, которое расположено **ниже** в документе.

</details>

**2. Мы задали `body { color: #333; font-family: Arial, sans-serif; }`, но ссылка `<a href="#">Открыть</a>` осталась синей, а текст внутри `<button>Отправить</button>` остался со стандартным мелким шрифтом. Разве `color` и `font-family` не наследуются?**

<details>
<summary>Показать ответ</summary>

Оба свойства **наследуемые**, и они передаются потомкам. Проблема в том, что у `<a>` и `<button>` есть **собственные браузерные (User-Agent) стили** цвета и шрифта. Любое прямое правило на самом элементе всегда сильнее унаследованного значения от предка. Чтобы вернуть наследование, им явно пишут `a { color: inherit; }` и `button { font: inherit; }`.

</details>

**3. Что случится с правилом `p { color: green; }`, если прямо перед ним в файле `.css` написать комментарий в стиле JS: `// временный цвет`?**

<details>
<summary>Показать ответ</summary>

В чистом CSS **нет** однострочных комментариев `//`. Браузер воспримет `// временный цвет` как часть селектора перед `p` (`// временный цвет p { ... }`), такой селектор окажется синтаксически некорректным, и **всё правило `p` будет полностью проигнорировано**. Комментарии в CSS пишутся только через `/* ... */`.

</details>

## Задачи

**Задача 1. Подключение внешнего CSS и проверка приоритета каскада**

Есть HTML-файл с двумя абзацами `<p>`. Подключи внешний файл `styles.css` в `<head>` (способом №3) и проверь на практике, какой цвет победит:
1) В `styles.css` задай для `p` красный цвет текста и жирный шрифт (`font-weight: 700`), а правилом ниже в этом же файле переопредели только цвет `p` на синий (`blue`).
2) В HTML на втором `<p>` добавь инлайн-атрибут `style="color: green;"`.
3) В комментариях прямо в `styles.css` объясни, почему первый `<p>` стал синим и жирным, а второй — зелёным и жирным.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8" />
  <title>Урок 01 — Каскад</title>
  <!-- Подключи styles.css здесь -->
</head>
<body>
  <p>Первый абзац</p>
  <p style="color: green;">Второй абзац</p>
</body>
</html>
```

<details>
<summary>Подсказка и решение</summary>

```html
<!-- index.html: -->
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8" />
  <title>Урок 01 — Каскад</title>
  <!-- Одиночный тег link в head подключает внешний файл стилей без смешивания с HTML: -->
  <link rel="stylesheet" href="styles.css" />
</head>
<body>
  <p>Первый абзац</p>
  <p style="color: green;">Второй абзац</p>
</body>
</html>
```

```css
/* styles.css: */
p {
  color: red;
  font-weight: 700; /* Это свойство не переопределяется ниже, поэтому применится к обоим <p> */
}

p {
  /* У обоих правил одинаковый вес (селектор тега p), поэтому побеждает НИЖНЕЕ правило: */
  color: blue;
}

/* Итог для первого <p>: цвет blue (победил порядком в каскаде) и font-weight: 700.
   Итог для второго <p>: цвет green (инлайн-атрибут style="..." имеет более высокий вес,
   чем селектор тега в .css), но font-weight: 700 сохранится из styles.css. */
```

</details>

**Задача 2. Наследование шрифта и цвета от `<body>` без «упрямых» ссылок и кнопок**

На странице есть текст в `<body>`, список `<ul>` с элементами `<li>`, ссылка `<a>` и кнопка `<button>`:
1) Задай на `body` цвет текста `#222222`, семейство шрифта `Verdana, sans-serif` и размер `16px`.
2) Сделай так, чтобы ссылка `<a>` унаследовала цвет `#222222` (вместо стандартного синего), а кнопка `<button>` — шрифт `Verdana, sans-serif` и размер `16px` (вместо системного мелкого шрифта).
3) Добавь для `ul` рамку `border: 1px solid #cccccc;` — и в комментарии в CSS объясни, почему рамка появилась только вокруг списка, а не вокруг каждого `<li>` внутри него.

```html
<body>
  <p>Обычный текст на странице</p>
  <ul>
    <li>Пункт списка</li>
    <li><a href="#">Ссылка внутри списка</a></li>
  </ul>
  <button type="button">Нажать</button>
</body>
```

<details>
<summary>Подсказка и решение</summary>

```css
body {
  /* Текстовые свойства (color и font-*) наследуются вложенными элементами автоматически: */
  color: #222222;
  font-family: Verdana, sans-serif;
  font-size: 16px;
}

a {
  /* У тега <a> есть собственный браузерный цвет — inherit принудительно забирает цвет родителя: */
  color: inherit;
}

button {
  /* У <button> собственный браузерный шрифт и размер — font: inherit копирует все параметры шрифта: */
  font: inherit;
}

ul {
  /* border относится к ненаследуемым свойствам: рамка рисуется только на самом <ul>,
     а дочерние <li> её не перенимают, чтобы не плодить лишние границы на каждом потомке: */
  border: 1px solid #cccccc;
}
```

</details>

**Задача 3. Найди и исправь 3 ошибки (синтаксис, комментарии и `!important`)**

Коллега пытался покрасить `<header>` и все абзацы `<p>`, но код ниже работает со сбоями: второй цвет вообще не применился, а заголовок невозможно переопределить без новых костылей. Найди **3 ошибки** и исправь файл CSS, не меняя HTML-разметку.

```html
<header>
  <h1>Заголовок</h1>
  <p>Первый абзац</p>
</header>
```

```css
/* Проблемный CSS: */
header {
  color: navy !important;
  font-size: 18px
  // задаём шрифт для шапки
  font-family: Arial, sans-serif;
}

p {
  color: teal;
}
```

<details>
<summary>Подсказка и решение</summary>

```css
header {
  /* Ошибка 1: убрали лишний !important, иначе потомкам (<p>) сложно переопределить цвет */
  color: navy;
  /* Ошибка 2: поставили ';' в конце 18px — без неё строка слилась со следующей и сломалась */
  font-size: 18px;
  /* Ошибка 3: заменили '//' на блочный комментарий CSS — однострочные '//' запрещены */
  font-family: Arial, sans-serif;
}

p {
  /* Теперь селектор p (прямое правило на элементе) легко перебивает унаследованный от header цвет: */
  color: teal;
}
```

</details>
