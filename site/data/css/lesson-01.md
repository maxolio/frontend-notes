# Урок 01. Введение в CSS: подключение, каскад, специфичность и наследование

Суть урока: CSS (Cascading Style Sheets) отвечает за внешний вид HTML-скелета; подключать его лучше внешним файлом через `<link rel="stylesheet">`, а итоговый стиль элемента вычисляется через каскад источников, вес правил (специфичность) и наследование.

## 1. Что такое CSS и 3 способа подключения (00:28–03:12)

[+] HTML — это скелет страницы, CSS — визуальный слой (цвета, шрифты, размеры, расположение), JS — логика поведения. Стили подключают тремя способами, но в реальных проектах используют внешний `.css`-файл.

| Способ | Где пишется | Вес | Кэш браузера | Когда использовать |
| --- | --- | --- | --- | --- |
| Инлайн `style="..."` | В атрибуте тега | Очень высокий | Нет | Избегать (обычно ставит JS) |
| Тег `<style>` | Внутри `<head>` | Обычный | Нет | Быстрые тесты и прототипы |
| Внешний `<link>` | Отдельный `.css` | Обычный | Да | Стандарт для реальных сайтов |

```html
<!-- 1. Инлайн-стиль в атрибуте style (плохая практика) -->
<p style="color: green; font-weight: 700;">Текст</p>

<!-- 2. Тег <style> в <head> (смешивает HTML и CSS) -->
<head>
  <style>
    p {
      color: red;
    }
  </style>
</head>

<!-- 3. Внешний файл — лучший способ (<link> в <head>) -->
<head>
  <link rel="stylesheet" href="styles.css" />
  <!-- При нескольких <link>/<style> и равном весе победит нижний -->
</head>
```

## 2. Анатомия CSS-правила (03:13–05:10)

[+] Любой CSS состоит из правил: селектора (к каким элементам применяем) и блока объявлений `{ свойство: значение; }`. Селектор по тегу (`p`, `a`) затрагивает каждый такой тег на странице.

[!] Точка с запятой `;` разделяет свойства внутри блока. После последнего свойства она формально необязательна, но её ставят всегда — иначе при добавлении новой строки ниже оба свойства сломаются.

```css
/* Селектор по тегу: стили применятся ко всем <p> на странице */
p {
  color: red;
  font-weight: 700;
}

a {
  color: green;
}
```

## 3. Каскад и источники стилей (05:11–06:45)

[+] Каскад — механизм разрешения конфликтов, когда к одному элементу подходит несколько правил. Браузер проверяет их по порядку: сначала **источник правила**, затем **специфичность (вес)** и в конце **порядок в коде** (побеждает нижнее).

| Приоритет | Источник стилей | Пример |
| --- | --- | --- |
| 1 (слабее всех) | Браузерные (User-Agent) | Отступы у `<h1>`, `<p>`, синие `<a>` |
| 2 | Пользовательские | Расширения браузера, настройки ОС |
| 3 | Авторские | Твой `.css`-файл и тег `<style>` |
| 4 | CSS-анимации | Кадры `@keyframes` (Урок 19) |
| 5 | Авторские с `!important` | `color: red !important;` |
| 6 | Пользовательские с `!important` | Принудительные правила пользователя |
| 7 | Браузерные с `!important` | Защищённые системные стили |
| 8 (сильнее всех) | CSS-переходы | Плавный `transition` (Урок 18) |

На вырост: внутри авторских стилей современные проекты также управляют приоритетом с помощью каскадных слоёв `@layer` — они срабатывают ещё до подсчёта специфичности.

## 4. Специфичность (вес правила) (06:46–08:28)

[+] Специфичность — это «вес» правила: более тяжёлое правило перебивает более лёгкое, даже если стоит выше. Инлайн-атрибут `style="..."` тяжелее правил из `<style>` и внешнего `.css`.

[!] Флаг `!important` перебивает даже `style="..."`, потому что переносит свойство на более высокий уровень каскада (см. таблицу выше). Злоупотреблять им нельзя — потом такой стиль трудно переопределить. На вырост: точный расчёт веса с классами и `#id` разберём в Уроке 02.

<!-- demo-html:
<p>Первый абзац (без style — сработает каскад CSS)</p>
<p style="color: green;">Второй абзац (инлайн style="color: green;")</p>
-->
```css
/* У обоих правил одинаковый вес (тег p), победит нижнее (blue) */
p {
  color: red;
}

p {
  color: blue;
}

/* !important перебьёт даже style="color: green;" (использовать редко) */
/* p { color: red !important; } */
```

## 5. Наследование и комментарии в CSS (08:29–10:33)

[+] Наследование — передача значений свойств от родителя ко всем вложенным потомкам (например, от `<header>` к `<nav>`, `<ul>` и `<li>`).

| Группа свойств | Наследуются | Примеры |
| --- | --- | --- |
| Текст и шрифты | Да | `color`, `font-family`, `font-size`, `font-weight`, `text-shadow` |
| Списки и интерфейс | Да | `list-style`, `cursor`, `visibility` |
| Оформление и размеры | Нет | `border`, `background`, `padding`, `margin`, `width`, `height` |

[!] Любое прямое правило на самом элементе всегда сильнее унаследованного значения от родителя — даже если у родителя стоял `!important`. Поэтому `<a>` (браузерный цвет) и `<button>`/`<input>` (браузерные шрифт и цвет) не подхватывают стили от `<body>`. Чтобы вернуть наследование, им явно пишут `inherit` (запись `font: inherit` копирует сразу все параметры шрифта одной строкой).

```css
/* Наследуется потомками (кроме тегов со своими стилями браузера) */
body {
  color: #222;
  font-family: sans-serif;
}

/* Принудительно забираем цвет у родителя */
a {
  color: inherit;
}

/* Забираем шрифт, размер и цвет у родителя */
button {
  font: inherit;
  color: inherit;
}

/* Комментарии // в CSS запрещены — они ломают следующее правило */
```

## 6. Как читать стили в DevTools (`Elements` → `Styles`)

[+] Вкладка `Styles` показывает все правила, которые применились к выбранному элементу, и сразу объясняет результат каскада:

1. **Сверху — победители, снизу — проигравшие:** правила отсортированы по силе. На самом верху `element.style` (туда можно кликнуть и дописать свойство для быстрого теста), ниже — твои правила, ещё ниже — `Inherited from ...` (наследование) и `user agent stylesheet` (стили браузера).
2. **Перечёркнутое свойство** — это не ошибка, а проигрыш в каскаде: оно подошло по селектору, но его перебило правило выше.
3. **Полезные инструменты рядом:**
   - **Галочка** слева от любого свойства — временно выключает его.
   - Кнопка **`:hov`** (вверху справа) — фиксирует состояния `:hover`, `:focus`, чтобы спокойно стилизовать наведение.
   - Вкладка **`Computed`** (рядом со `Styles`) — показывает только итоговые значения без перечёркиваний.

## 3 главные ловушки урока (чек-лист для повторения)

1. Писать комментарии через `//` (как в JS) или забывать `;` между свойствами — браузер отбросит сломанную строку или всё следующее правило целиком.

2. Думать, что `<a>` и `<button>` не наследуют `color` или `font-family` от `<body>`, либо пытаться пробить их через `!important` на родителе — прямое правило браузера на самом теге всегда сильнее наследования (исправляется через `inherit`).

3. Лечить конфликты стилей добавлением `!important` или инлайнового `style="..."` — потом такие правила почти невозможно переопределить в проекте.

## Вопросы для закрепления

**1. В `<head>` сначала подключён `<link rel="stylesheet" href="theme.css">` (где `p { color: blue; }`), а строкой ниже — тег `<style>p { color: red; }</style>`. Какого цвета станет текст `<p>` и почему?**

<details>
<summary>Показать ответ</summary>

Текст станет **красным (`red`)**. И внешний файл `<link>`, и тег `<style>` относятся к одному источнику (авторские стили) и имеют одинаковый селектор `p` с равной специфичностью. При равном весе и одном источнике каскад выбирает правило, расположенное **ниже** в документе.

</details>

**2. Мы задали `body { color: #333; font-family: Arial, sans-serif; }`, но ссылка `<a href="#">Открыть</a>` осталась синей, а `<button>Отправить</button>` — со стандартным мелким шрифтом. Разве `color` и `font-family` не наследуются?**

<details>
<summary>Показать ответ</summary>

Оба свойства **наследуемые**. Проблема в том, что у `<a>` и `<button>` есть **собственные браузерные (User-Agent) стили** цвета и шрифта. Любое прямое правило на самом элементе всегда сильнее унаследованного значения от предка. Чтобы вернуть наследование, им явно пишут `a { color: inherit; }` и `button { font: inherit; color: inherit; }`.

</details>

**3. Какого цвета станет текст внутри `<p>` и почему?**

```css
p {
  color: blue;
}

// временный цвет
p {
  color: green;
}
```

<details>
<summary>Показать ответ</summary>

Текст станет **синим (`blue`)**. В чистом CSS нет однострочных комментариев `//`. Браузер склеит `// временный цвет` со следующим селектором (`// временный цвет p`), посчитает такой селектор синтаксически некорректным и **полностью отбросит второе правило `p`**. Первое правило останется валидным. Комментарии в CSS пишутся только через `/* ... */`.

</details>

Есть HTML-страница с двумя абзацами `<p>`. Подключи внешний файл стилей и проверь на практике, как работают порядок правил в каскаде и инлайн-атрибут `style`.

1. Подключи внешний файл `styles.css` в `<head>` через `<link>`.
2. В `styles.css` задай для `p` красный цвет (`red`) и жирный шрифт (`font-weight: 700`), а правилом ниже переопредели только `color` на синий (`blue`).
3. В HTML добавь второму `<p>` инлайн-атрибут `style="color: green;"`.
4. Над правилами в `styles.css` добавь CSS-комментарии с объяснением итогового вида каждого `<p>`.

Проверка: первый `<p>` стал синим и жирным, второй — зелёным и жирным; в DevTools на вкладке `Styles` у первого `<p>` строка `color: red` перечёркнута.

```html
<!DOCTYPE html>

<head>
  <meta charset="UTF-8" />
  <title>Урок 01 — Каскад</title>
  <!-- Подключи styles.css здесь -->

  <p>Первый абзац</p>
  <p>Второй абзац</p>
```

<details>
<summary>Подсказка и решение</summary>

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8" />
  <title>Урок 01 — Каскад</title>
  <!-- Подключаем внешний файл стилей без смешивания HTML и CSS -->
  <link rel="stylesheet" href="styles.css" />
</head>
<body>
  <p>Первый абзац</p>
  <!-- Инлайн style тяжелее селектора тега, но font-weight сохранится -->
  <p style="color: green;">Второй абзац</p>

</html>
```

```css
/* Базовое правило: font-weight не перебивается ниже и идёт обоим <p> */
p {
  color: red;
  font-weight: 700;
}

/* Равный вес с правилом выше — побеждает нижнее, первый <p> синий */
p {
  color: blue;
}
```

</details>

**Задача 2. Наследование шрифта и цвета от `<body>` без «упрямых» тегов**

На странице есть абзац `<p>`, список `<ul>`, ссылка `<a>` и кнопка `<button>`. Нужно задать общие текстовые стили на `<body>` и исправить теги со встроенными браузерными стилями.

1. Задай на `body` цвет текста `#1e3a8a`, семейство шрифта `Verdana, sans-serif` и размер `16px`.
2. Сделай так, чтобы `<a>` унаследовала цвет от `body`, а `<button>` — и шрифт с размером (`font`), и цвет (`color`).
3. Добавь для `ul` рамку `border: 1px solid #cccccc;` и объясни в комментарии над правилом, почему она не появилась у каждого `<li>`.

Проверка: абзац, список, ссылка и текст кнопки стали одинакового тёмно-синего цвета и шрифта `Verdana` размером `16px`, а рамка обвела только внешний `<ul>`.

```html
<body>
  <p>Обычный текст на странице</p>
  <ul>
    <li>Пункт списка</li>
    <li><a href="#">Ссылка внутри списка</a></li>
  </ul>
  <button type="button">Нажать</button>
</body>
```

<details>
<summary>Подсказка и решение</summary>

```css
/* Текстовые свойства (color и font-*) наследуются потомками */
body {
  color: #1e3a8a;
  font-family: Verdana, sans-serif;
  font-size: 16px;
}

/* Перебиваем синий цвет браузера и берём цвет родителя */
a {
  color: inherit;
}

/* Кнопка не подхватывает шрифт и цвет от body — забираем явно */
button {
  font: inherit;
  color: inherit;
}

/* border не наследуется: рамка рисуется только на самом <ul> */
ul {
  border: 1px solid #cccccc;
}
```

</details>

**Задача 3. Найди и исправь 3 ошибки (синтаксис, `!important` и комментарии)**

Коллега оформлял шапку `<header>` и хотел перекрасить абзац `<p>` из тёмно-синего (`navy`) в бирюзовый (`teal`), но допустил 3 ошибки. Шрифт в шапке не применился, а `<p>` так и остался тёмно-синим.

1. Исправь синтаксическую ошибку в правиле `header`, чтобы заработали и `font-size`, и `font-family`.
2. Убери лишний `!important` в первом правиле `p`, чтобы его можно было переопределить ниже.
3. Замени неправильный комментарий перед вторым правилом `p`, чтобы браузер не отбросил селектор.

Проверка: текст в `<header>` отображается шрифтом `Arial` размером `18px`, а `<p>` стал бирюзовым (`teal`) без использования `!important`.

```html
<header>
  <h1>Заголовок</h1>
  <p>Первый абзац</p>
</header>
```

```css
/* Проблемный CSS: */
header {
  font-size: 18px
  font-family: Arial, sans-serif;
}

p {
  color: navy !important;
}

// переопределяем цвет абзаца на бирюзовый
p {
  color: teal;
}
```

<details>
<summary>Подсказка и решение</summary>

```css
/* Ошибка 1: добавили ; после 18px, иначе обе строки сливались */
header {
  font-size: 18px;
  font-family: Arial, sans-serif;
}

/* Ошибка 2: убрали !important, иначе нижнее правило не перебьёт цвет */
p {
  color: navy;
}

/* Ошибка 3: заменили // на блочный комментарий CSS */
p {
  color: teal;
}
```

</details>
