## Урок 01. Введение: подключение JS к странице, консоль и чтение ошибок

### 1. Способы подключения скриптов к HTML
Браузер парсит HTML сверху вниз построчно. Способ подключения тега `<script>` определяет время загрузки и выполнения:

* **Обычный `<script src="...">`:**  
  Полностью блокирует парсинг HTML. Браузер останавливается, скачивает скрипт, выполняет его и только потом продолжает строить DOM. В `<head>` без атрибутов подключать нельзя — страница зависнет на белом экране, а скрипт не найдет элементы DOM.
* **`<script async src="...">`:**  
  Скачивается параллельно с парсингом HTML. Выполняется **мгновенно по завершении загрузки**, прерывая парсинг HTML. Порядок выполнения нескольких `async`-скриптов не гарантирован (кто быстрее скачался, тот первым и выполнился).  
  *Применение:* Независимые внешние счетчики и аналитика (Google Analytics, Яндекс.Метрика).
* **`<script defer src="...">`:**  
  Скачивается параллельно с парсингом HTML, **не блокируя страницу**. Выполняется **строго после завершения построения DOM**, непосредственно перед событием `DOMContentLoaded`. Строго сохраняет порядок подключения файлов.  
  *Применение:* Стандарт для всего основного кода приложений.

### 2. Консоль разработчика (`console`)
* `console.log(...)` — вывод общей информации, строк и интерактивных объектов.
* `console.table(...)` — вывод массивов и объектов в виде форматированной таблицы (удобно для коллекций).
* `console.dir(...)` — отображение интерактивного списка свойств переданного JS-объекта (особенно полезно для DOM-элементов).
* `console.error(...)` / `console.warn(...)` — вывод ошибок и предупреждений с подсветкой и трассировкой.

### 3. Синтаксис, инструкции и ASI
* **Инструкция (Statement):** Законченное действие/команда для интерпретатора.
* **Точка с запятой (`;`):** Разделитель инструкций.
* **ASI (Automatic Semicolon Insertion):** Механизм парсера JS, который пытается автоматически подставить `;` при переносе строк.
  * *Опасность ASI:* В ряде случаев парсер ошибается (например, когда следующая строка начинается со скобок `(` или `[`), что приводит к фатальным багам. В продакшене принято ставить точки с запятой явно или доверять форматирование Prettier.

### 4. Чтение ошибок в консоли
* Ошибки в JS — это объекты исключений.
* `ReferenceError` возникает при попытке обратиться к переменной, которая не была объявлена или находится в Temporal Dead Zone.
* Справа от каждой ошибки в DevTools есть ссылка `файл:строка:колонка` (например, `main.js:7:13`). Клик по ней открывает вкладку **Sources** с подсветкой упавшей строки и цепочкой вызовов (Call Stack).

## Урок 02. Переменные в JS: динамическая типизация, модель памяти, let / const / var, 'use strict'

### 1. Что такое переменная и её жизненный цикл
**Переменная** — именованная ссылка на ячейку оперативной памяти (RAM) для хранения данных.

#### Жизненный цикл переменной в движке V8 («Имя → Место → Значение»)

Внешне строчка `let total = 100;` кажется одним действием, но движок V8 делит её на **два разных момента времени**:
1. **Фаза парсинга / компиляции** (до запуска первой строчки кода).
2. **Фаза выполнения (рантайм)** (когда интерпретатор доходит до конкретной строки).

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Объявление (Declaration)  👉 «Зарегистрировали ИМЯ» (до запуска)    │
│ 2. Инициализация (Init)      👉 «Выделили МЕСТО в памяти» (рантайм)    │
│ 3. Присваивание (Assignment) 👉 «Положили ЗНАЧЕНИЕ» (рантайм)          │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Declaration (Объявление):**
   * *Когда:* До запуска кода, во время сканирования файла.
   * *Что делает V8:* Резервирует имя переменной в реестре лексического окружения (`LexicalEnvironment`). Переменная существует, но память под неё еще не выделена. Для `let` и `const` она помечается как «неинициализированная» и попадает в **TDZ (Temporal Dead Zone)**.
2. **Initialization (Инициализация):**
   * *Когда:* В рантайме, ровно в момент, когда поток выполнения доходит до строки объявления.
   * *Что делает V8:* Переменная выходит из TDZ, под неё выделяется физическая ячейка в Стэке оперативной памяти. Если значения нет (`let total;`), в ячейку записывается `undefined`.
3. **Assignment (Присваивание):**
   * *Когда:* Сразу после инициализации при наличии знака `=`.
   * *Что делает V8:* Вычисляет выражение справа (число `100`), переводит в бинарный машинный формат и записывает эти биты в выделенную ячейку памяти.

> **💡 Ключевая разница с `var`:**  
> У `var` этапы 1 и 2 объединены еще **до старта кода** (движок объявляет его и сразу инициализирует значением `undefined`).  
> У `let` этап 2 ждет своей очереди при выполнении — эта задержка и создает TDZ.

#### Именование (Clean Code)
* Допустимы буквы, цифры, `$` и `_`. С цифры имя начинаться **не может**.
* Регистрозависимость: `myVar` и `myvar` — разные переменные.
* **`camelCase`** — стандарт для 99% переменных (`currentUser`, `shoppingCartList`).
* **`SCREAMING_SNAKE_CASE`** — только для compile-time констант, известных до запуска (`API_URL`, `COLOR_WHITE`).
* Запрещены зарезервированные слова (`class`, `return`, `let`, `if` и др.).

### 2. Динамическая типизация (Dynamic Typing)
> **Главный закон JS:** Типы данных имеют **значения**, а не переменные.

Переменная — это просто контейнер. В неё можно последовательно положить число, затем строку, затем объект:
```javascript
let val = 100;      // Number
val = "Привет";     // String
val = { id: 1 };    // Object
```

* **Duck Typing (Утиная типизация):** Если объект содержит нужные свойства и методы, движок работает с ним без проверки жесткого класса.
* **Особенность:** Высокая скорость разработки, но ошибки типов ловятся только во время выполнения (Runtime). В масштабном продакшене для устранения этого риска используют **TypeScript**.

### 3. Модель памяти: Стек (Stack) и Куча (Heap)

Движок V8 делит оперативную память процесса на две структуры:

```
┌─────────────────────────────────┐       ┌──────────────────────────────────────┐
│          СТЕК (STACK)           │       │             КУЧА (HEAP)              │
│   Быстрая, упорядоченная память │       │    Большая динамическая память       │
├─────────────────────────────────┤       ├──────────────────────────────────────┤
│ age = 25                        │       │                                      │
│ name = "Alex"                   │       │                                      │
│ user ───────(адрес: 0x00A1)─────┼──────>│ 0x00A1: { role: 'admin', age: 30 }   │
└─────────────────────────────────┘       └──────────────────────────────────────┘
```

#### 1. Стек (Call Stack)
* Быстрая память фиксированного размера (LIFO).
* Хранит контексты вызова функций, примитивные типы (`number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) и адреса-указатели на кучу.
* **Копирование примитивов происходит ПО ЗНАЧЕНИЮ:**
  ```javascript
  let a = 10;
  let b = a; // b получила независимую копию числа 10
  b = 20;
  console.log(a); // 10 (a не изменилась)
  ```

#### 2. Куча (Memory Heap)
* Неструктурированная динамическая память для объектов переменного размера: объекты, массивы, функции.
* Переменная на стеке хранит только **ссылку (адрес)** на область в куче.
* **Копирование объектов происходит ПО ССЫЛКЕ:**
  ```javascript
  let user1 = { name: 'Alex' };
  let user2 = user1; // Скопировался только адрес в куче!
  user2.name = 'John';
  console.log(user1.name); // 'John' (объект один и тот же)
  ```

### 4. Сравнение ключевых слов: `var`, `let`, `const`

| Критерий | `var` | `let` | `const` |
| :--- | :--- | :--- | :--- |
| **Область видимости** | Функциональная / Глобальная | Блочная `{}` | Блочная `{}` |
| **Всплытие (Hoisting)** | Да, инициализируется в `undefined` | Да, попадает в **TDZ** | Да, попадает в **TDZ** |
| **Повторное объявление**| Разрешено (опасность багов) | Запрещено (`SyntaxError`) | Запрещено (`SyntaxError`) |
| **Переприсваивание (`=`)**| Разрешено | Разрешено | **Запрещено** (`TypeError`)|
| **Загрязняет `window`** | Да (`window.x`) | Нет | Нет |
| **Инициализация при объявлении** | Не обязательна | Не обязательна | **Обязательна** |

#### Детали механики:
1. **TDZ (Temporal Dead Zone — Временная мертвая зона):**  
   Зона от начала блока видимости до фактической строки с `let` или `const`. Обращение к переменной внутри TDZ выбрасывает `ReferenceError: Cannot access '...' before initialization`.
2. **Почему для `const` обязательна инициализация:**  
   По умолчанию переменная без значения получает `undefined`. Но `const` намертво запрещает переприсваивание (`TypeError: Assignment to constant variable`). Если бы язык разрешал `const a;`, переменная навсегда осталась бы `undefined` без шанса изменить её значение. Поэтому парсер V8 еще до запуска бросает `SyntaxError: Missing initializer in const declaration`.
3. **`const` и мутабельность объектов:**  
   `const` защищает от перезаписи саму ссылку (адрес в стеке), но **не защищает свойства объекта в куче**. Мутировать свойства можно (`user.name = 'Bob'`), а присвоить новый объект нельзя (`user = {}` ❌). Для полной заморозки объекта используют `Object.freeze(...)`.
4. **Строгий режим (`'use strict'`):**
   - Включается директивой `'use strict';` в начале файла или функции.
   - Запрещает случайное создание глобальных переменных без ключевого слова (`x = 10` выбросит `ReferenceError`, а не создаст `window.x`).
   - Превращает «тихие» ошибки в явные исключения.
   - В ES6-модулях (`<script type="module">`) строгий режим включен по умолчанию.

### 5. Практические правила для Senior-кода
1. **Никакого `var`:** В продакшене `var` запрещен правилом ESLint `no-var`.
2. **`const` по умолчанию:** 90% кода пишется через `const`. Это защищает от случайной перезаписи.
3. **`let` только при необходимости:** Используется строго тогда, когда переменная действительно будет перезаписываться (счетчик цикла `for`, аккумулятор, флаг состояния).
4. **Одна переменная — одна строка:** Конструкции через запятую `let a = 1, b = 2;` снижают читаемость и усложняют чтение диффов в Git.

## Урок 03. Типы данных в JS и приведение типов

### 1. 8 типов данных (7 примитивов + 1 ссылочный)
* **`String`** (`'Привет'`, `` `Привет, ${name}` ``): текстовый тип. Интерполяция `${}` работает только в косых кавычках (бэктиках). Строки иммутабельны.
* **`Number`** (`28`, `3.14`): 64-битный формат IEEE 754 (целые и дробные вместе). Подвохи: неточность дробей (`0.1 + 0.2 !== 0.3`), спец. значения `Infinity`, `-Infinity`, `NaN` (`typeof NaN === 'number'`).
* **`BigInt`** (`999999999999n`): целые числа произвольной длины с суффиксом `n`. Нельзя смешивать в операциях с обычным `Number`.
* **`Boolean`** (`true` / `false`): логический тип.
* **`Undefined`** (`undefined`): значение не было задано системой/языком (дефолт для неинициализированной переменной).
* **`Null`** (`null`): явная пустота, заданная разработчиком. Исторический баг: `typeof null === 'object'`.
* **`Symbol`** (`Symbol()`): уникальный и неизменяемый идентификатор для скрытых ключей объектов.
* **`Object`** (`{}`, `[]`, `function`): единственный сложный (ссылочный) тип, хранится в Куче, мутабелен.

### 2. 8 Falsy-значений (всё остальное — Truthy!)
В логических проверках становятся `false` **только**:
`false`, `0`, `-0`, `0n`, `""` (пустая строка), `null`, `undefined`, `NaN`.
*(Даже `[]`, `{}`, `'0'` и `' '` — это `true`!)*

## Урок 04. Операторы, инкремент, сравнения

### 1. Арифметика и приведение к числу
* Базовые: `+`, `-`, `*`, `/`, `%` (остаток от деления), `**` (степень).
* **Унарный `+`** (`+'42' === 42`, `+true === 1`, `+null === 0`, `+undefined === NaN`) переводит значение в число.
* **Ловушка `+` vs `-/*/`:** Бинарный `+` со строкой делает склеивание (`'2' + 2 === '22'`), а `-`, `*`, `/` всегда переводят к числу (`'5' - 2 === 3`).

### 2. Инкремент (`++`) и декремент (`--`)
* **Префиксная (`++x`):** сначала увеличивает переменную, потом возвращает новое значение.
* **Постфиксная (`x++`):** сначала возвращает старое значение, потом увеличивает переменную.

### 3. Сравнения: строки, `==` и `===`
* **Строки** сравниваются посимвольно по кодам Unicode (`'20' > '100'` → `true`, так как `'2' > '1'`; строчные буквы `'a'` больше заглавных `'A'`).
* **`==` (нестрогое):** приводит типы (источник багов, в продакшене запрещено).
* **`===` (строгое):** стандарт индустрии. Сначала сравнивает тип, затем значение.

## Урок 05. Условные ветвления (`if/else`), логические операторы (`||`, `&&`, `!`, `??`)

### 1. Конструкция `if / else if / else` и Clean Code
* В цепочке выполняется строго **первая** истинная ветка, остальные игнорируются.
* Фигурные скобки `{}` создают блочную область видимости. Всегда ставим `{}`.
* **Позитивное именование булевых:** переменные-факты называем без «не» (`hasMoney`, `isBanned`), а отрицание делаем в условии оператором `!`.
* **Поясняющая переменная (Explaining Variable):** сложные формулы выносим в переменную с понятным именем (`const isLoanApproved = ...`), разделяя вычисление логики и ветвление `if (isLoanApproved)`.
* **Guard Clauses (Ранний выход):** в функциях отсекаем ошибки в начале через `if (!user) return;`, избегая «лесенок» из вложенных `if`.
* **Вложенные тернарники (`? : ? :`)** — антипаттерн. Для простого выбора из 2 вариантов используем один `? :`, для множества вариантов — `if/else`, `switch` или объект-словарь + `??`.

### 2. Логические операторы под капотом (Short-circuiting)
* **`||` (ИЛИ) — «Охотник за первой правдой»:** идет слева направо, возвращает первое **Truthy** значение в исходном виде (или последнее, если всё ложь).
* **`&&` (И) — «Охотник за первой ложью»:** идет слева направо, возвращает первое **Falsy** значение в исходном виде (или последнее, если всё правда).
* **`!` (НЕ):** инвертирует значение в противоположное булево (`!true === false`).
* **Приоритет:** у `&&` приоритет **выше**, чем у `||`. При их смешивании **всегда** ставим круглые скобки `(...)`.

### 3. Оператор нулевого слияния (`??`)
* Возвращает правый операнд, **только если слева `null` или `undefined`**.
* В отличие от `||`, пропускает валидные `0`, `false` и `""` (идеален для значений по умолчанию: `score ?? 0`).

## Урок 06. Модальные окна (alert, prompt, confirm) и конструкция switch / case

### 1. Модальные окна браузера (alert, prompt, confirm)
Все три функции являются **модальными и синхронно-блокирующими**: они полностью замораживают поток JavaScript, анимации и интерфейс страницы до тех пор, пока пользователь не нажмет кнопку в окне.

* **`alert(message)`:**
  * Показывает системное окно с текстом и кнопкой «ОК».
  * Принимает **только 1 аргумент** (все последующие аргументы браузер молча игнорирует!).
  * Принудительно приводит аргумент к строке через `String(...)` (`alert({a: 1})` покажет `"[object Object]"`).
  * Всегда возвращает **`undefined`**.
  * *В продакшене запрещен:* нельзя стилизовать через CSS, блокирует интерфейс (плохой UX). В реальных проектах используют кастомные модалки на HTML/CSS.
* **`prompt(title, [default])`:**
  * Окно с полем ввода, кнопками «ОК» и «Отмена».
  * *Что возвращает:*
    - Нажал «ОК» с текстом → **строка (`string`)**, даже если ввели цифры.
    - Нажал «ОК» с пустым полем → пустая строка **`""`**.
    - Нажал «Отмена» или <kbd>Esc</kbd> → **`null`**!
  * *Ловушка со сложением:* `prompt() + 5` склеит строки (`'20' + 5 === '205'`). Для математики результат всегда приводят к числу: `+prompt('Сколько лет?')`.
* **`confirm(question)`:**
  * Окно подтверждения с кнопками «ОК» и «Отмена».
  * Возвращает строго **`true`** («ОК») или **`false`** («Отмена»).
  * Идеально подставляется напрямую в условие: `if (confirm('Удалить?')) { ... }`.

### 2. Конструкция `switch / case`
Заменяет длинные цепочки `if / else if`, когда одна и та же переменная проверяется на разные точные значения.

* **Строгое сравнение (`===`):** `switch` сравнивает операнды без неявного приведения типов! `case '4':` и `case 4:` — это разные ветки.
* **Инструкция `break` и Fall-through:** Если не поставить `break;`, выполнив совпавший кейс, движок продолжит выполнять все нижележащие кейсы подряд, игнорируя их условия!
* **Группировка кейсов:** Несколько `case` можно писать подряд без `break`, если для них нужно выполнить одно и то же действие.
* **Секция `default`:**
  * Срабатывает, только если ни один `case` не подошел.
  * Движок сначала проверяет все `case`, и только при отсутствии совпадений переходит к `default`.
  * Если `default` расположен не в самом конце, внутри него **обязателен `break;`**, иначе выполнение «провалится» в следующие кейсы. В продакшене `default` всегда пишут строго последним.
* **Паттерн `switch (true)`:** Позволяет проверять диапазоны (`case score >= 90:`), сопоставляя литерал `true` с булевым результатом выражений в кейсах.

## Урок 07 (Часть 1). Циклы `while`, `do while`, `break`, `continue`

### 1. Цикл `while` (Предусловие: «Сначала проверь — потом делай»)
* Если условие с самого начала ложно (`false`), тело цикла выполнится **0 раз**.
* Применяется, когда количество шагов заранее неизвестно (ожидание ввода, пока HP > 0 и т.д.).
* **Опасность бесконечного цикла:** Так как JS в браузере однопоточный, вечный цикл намертво замораживает вкладку (100% CPU). Всегда проверяй, что условие рано или поздно станет `false`.
* **Ловушка `continue` в `while`:** Если увеличение счетчика `i++` стоит в конце цикла, оператор `continue` его перепрыгнет и цикл станет бесконечным! При работе со счетчиком и `continue` безопаснее использовать цикл `for`.

### 2. Цикл `do while` (Постусловие: «Сначала сделай — потом проверь»)
* Тело `do { ... }` **гарантированно выполнится минимум 1 раз**, даже если условие в конце сразу `false`.
* В конце конструкции после `while (условие);` ставится точка с запятой.

## Урок 08. Функции (`Function Declaration`, Scope, параметры, `return`)

### 1. Объявление функции (`Function Declaration`)
* Функция — это «рецепт» действия (принцип DRY — не повторяйся).
* **`logHello`** (без скобок) — ссылка на саму функцию (объект в Куче). **`logHello()`** (со скобками) — команда немедленного запуска.
* **Полное всплытие (Hoisting):** `Function Declaration` загружается в память целиком до выполнения первой строки кода — функцию можно вызывать даже *выше* места её объявления в файле.
* Имена функций (действия) принято начинать с глагола (`get...`, `calc...`, `show...`).

### 2. Область видимости (Scope) — «Правило тонированных окон»
* Локальные переменные, объявленные внутри функции, живут только во время её вызова и недоступны снаружи (`ReferenceError`).
* Изнутри функции видны внешние переменные.
* **Затенение (Shadowing):** Локальная переменная или параметр с тем же именем, что и внешняя переменная, перекрывает внешнюю внутри функции, не меняя оригинал снаружи.

### 3. Параметры, аргументы и значения по умолчанию
* **Параметры** — имена-заглушки при *объявлении* `function fn(a, b)`. **Аргументы** — реальные значения при *вызове* `fn(1, 2)`.
* Недостающие аргументы становятся `undefined`, лишние — игнорируются.
* **Дефолтные параметры (`name = 'Гость'`):** срабатывают **строго на `undefined`** (или отсутствие аргумента). Значения `null`, `0`, `''`, `false` дефолтом **не заменяются**!

### 4. Инструкция `return`
* Функция без `return` всегда возвращает **`undefined`**.
* `return` отдает наружу ровно одну сущность и **мгновенно завершает** работу функции (код после `return` не выполняется).
* **Early Return (Ранний выход):** защитные условия `if (!valid) return 0;` в начале функции избавляют от лишних блоков `else`.
* **Ловушка ASI:** нельзя ставить перенос строки сразу после `return` (`return \n 100` → движок поставит `;` и вернет `undefined`).

## Урок 09. Виды функций, стрелочные функции и колбэки

### 1. `Function Declaration` vs `Function Expression`
* **`Function Declaration` (`function fn() {}`):**
  * Всплывает целиком до старта выполнения кода (можно вызывать выше объявления).
  * **Минус:** нет защиты от случайной перезаписи (вторая функция с тем же именем молча затрёт первую). Внутри блока `if` в `'use strict'` видна только внутри этого блока (объявлять внутри `if` не рекомендуется).
* **`Function Expression` (`const fn = function() {};`):**
  * Функция создается как значение выражения только в момент, когда выполнение доходит до этой строки.
  * **Не всплывает:** подчиняется правилам `const`/`let` (до строки объявления — TDZ → `ReferenceError`).
  * **Плюсы:** `const` защищает от перезаписи (`SyntaxError` / `TypeError`), удобно задавать по условию через `let fn; if (...) fn = ...`.
* **NFE (Named Function Expression):** `const sayHi = function greet() {};` — внутреннее имя `greet` видно **только внутри** самой функции. Помогает при рекурсии, если внешнюю переменную `sayHi` перезапишут или обнулят.

### 2. Стрелочные функции (`Arrow Functions =>`)
* Короткая запись для `Function Expression` (тоже не всплывают, есть TDZ).
* **Неявный `return`:** если тело состоит из одного выражения, убираем `{}` и `return`: `const sum = (a, b) => a + b;`.
* **Один параметр:** скобки можно опустить (`const double = n => n * 2;`), при 0 или 2+ параметрах скобки `()` обязательны.
* **Ловушка возврата объекта:** `() => { name: 'Alex' }` воспримется как тело функции! Чтобы вернуть объект в одну строку, оборачиваем его в круглые скобки: `() => ({ name: 'Alex' })`.
* **Отличия под капотом:** у стрелок **нет своего `this`**, нет псевдомассива `arguments` и их нельзя вызывать через `new`.

### 3. Функция как значение, колбэки и возврат функции
* **First-class citizen:** функция — это обычное значение (её можно копировать в переменные, передавать аргументом, возвращать через `return`).
* **Колбэк (Callback):** функция, переданная аргументом в другую функцию, чтобы та вызвала её позже.
  * *Частая ошибка:* передавать с круглыми скобками `runAction(finish())` — тогда `finish()` запустится мгновенно, а внутрь улетит `undefined`. Передавать нужно **без скобок**: `runAction(finish)`.
* **Функция как результат (Фабрика и Замыкание):** функция может возвращать новую функцию. Внутренняя функция сохраняет доступ к переменным внешней среды, в которой родилась (**Closure / Замыкание**). Вызов фабрики на месте в два шага: `createGreeter('Привет')('Максим')`.

### 4. Чистый код: Именование и SRP
* **Глагольные префиксы:** `get...` (получить), `set...` (установить), `calc...` (посчитать), `show.../render...` (отобразить), `create...` (создать), `is.../has.../can...` (булева проверка).
* **Принцип SRP (Single Responsibility):** 1 функция = 1 конкретная задача.

## Урок 15. Массивы (основы, главные методы и дополнения из learn.javascript.ru)

> **Суть (TL;DR):** Массив — это упорядоченный список (под капотом `object`), который **хранится по ссылке** и, в отличие от строк, **изменяем (мутабелен)**.

### 1. Доступ, изменение и длина
```javascript
const fruits = ['Яблоко', 'Банан'];

/*
Индексы начинаются с 0.
.at(-1) — быстрый способ взять элемент с конца без fruits[fruits.length - 1].
*/
fruits[0];      // 'Яблоко'
fruits.at(-1);  // 'Банан'

/*
const запрещает перезаписать саму переменную (fruits = []),
но менять элементы внутри по ссылке — можно.
*/
fruits[1] = 'Груша'; // ['Яблоко', 'Груша']
fruits.length;       // 2
```

### 2. Карта методов: кто меняет массив, а кто нет

**🔴 Мутируют (меняют исходный массив):**
```javascript
const list = ['b', 'c'];

/* Хвост (БЫСТРО) — работают только с концом массива: */
list.push('d');   // Добавляет в конец -> ['b', 'c', 'd'] (возвращает новую длину: 3)
list.pop();       // Удаляет с конца   -> ['b', 'c']      (возвращает удалённый: 'd')

/* Начало (МЕДЛЕННО) — движку приходится сдвигать и перенумеровывать ВСЕ элементы: */
list.unshift('a'); // Добавляет в начало -> ['a', 'b', 'c']
list.shift();      // Удаляет с начала   -> ['b', 'c']
```

**🟢 Не мутируют (возвращают новый массив или строку):**
```javascript
const nums = [10, 20, 30, 40];

/*
slice(start, end) — вырезает кусок от start до end (НЕ включая end).
Без аргументов nums.slice() делает полную поверхностную копию.
*/
const part = nums.slice(1, 3); // [20, 30] (nums остался прежним!)

/*
Массив <-> Строка:
join(разделитель) склеивает массив в строку (лучше, чем toString(), где всегда запятая).
*/
const str = ['JS', 'топ'].join(' '); // 'JS топ'
const back = str.split(' ');         // ['JS', 'топ']
```

### 3. Копирование, объединение и вложенность
```javascript
const a = [1, 2];
const b = [3, 4];

/*
Spread (...) распаковывает элементы в новый массив:
делает ПОВЕРХНОСТНУЮ копию (вложенные объекты/массивы останутся по ссылке!).
*/
const copy = [...a];          // [1, 2]
const merged = [...a, ...b];  // [1, 2, 3, 4] (современная замена a.concat(b))

/* Если внутри лежат объекты или другие массивы — для независимой копии: */
const deepCopy = structuredClone(a);
```

### 4. Сравнение и проверка типа
```javascript
/* 1. Массивы сравниваются по ССЫЛКЕ (адресу в памяти), а не по значениям: */
[1, 2] === [1, 2]; // false (два разных массива в памяти)

/* 2. Ловушка typeof: массив под капотом объект, поэтому проверяем через Array.isArray(): */
typeof [1, 2];         // 'object'
Array.isArray([1, 2]); // true  ✅
Array.isArray({});     // false
```

### 5. Дополнение из `learn.javascript.ru`
```javascript
const items = ['A', 'B'];

/*
1. Перебор массива: используй for..of (по значениям), а НЕ for..in!
for..in придуман для объектов: на массивах он в разы медленнее и может захватить лишние свойства.
*/
for (const item of items) {
  console.log(item); // 'A', 'B'
}

/*
2. Управление длиной через length:
length — это (последний индекс + 1). Самый быстрый способ очистить массив:
*/
items.length = 0; // [] (массив пуст)

/*
3. Ловушка new Array(3):
Один числовой аргумент создаёт не [3], а массив из 3 пустых слотов (дыр).
Всегда создавай массивы только через [].
*/
const empty = new Array(3); // [ <3 empty items> ], length === 3
```

### ⚡ 3 главные ловушки урока
1. **`unshift` / `shift` тормозят** на больших списках, так как двигают все индексы.
2. **`[...arr]` и `.slice()` копируют только 1-й уровень** (для вложенных структур нужен `structuredClone`).
3. **`typeof arr === 'object'`**, поэтому всегда проверяй через **`Array.isArray(arr)`** (и перебирай через **`for..of`**, а не `for..in`).
