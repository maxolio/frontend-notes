## Урок 04. Операторы, приведение типов и сравнения (Пазлы с собеседований)

### 1. Префиксный и постфиксный инкремент
**Задача:** Чему равны `a` и `b` после выполнения?
```javascript
let a = 3;
let b = a++ + ++a;
```
**Ответ и механика:** `b = 8`, `a = 5`.
* `a++` сначала отдает старое значение `3`, а потом увеличивает `a` в памяти до `4`.
* `++a` сначала увеличивает `a` с `4` до `5`, а потом отдает `5`.
* `3 + 5 = 8`.

### 2. Неявное приведение типов (`-` vs `+`)
**Задача:** Какое значение и какого типа вернет выражение?
```javascript
"5" - 2 + "3"
```
**Ответ и механика:** Строка `"33"`.
* Оператор `-` не работает со строками, поэтому переводит `"5"` в число: `5 - 2 = 3` (число).
* Бинарный `+` видит строку `"3"` и выполняет конкатенацию: `3 + "3" = "33"` (строка).

### 3. Сравнение строк
**Задача:** Что вернет выражение?
```javascript
"20" > "100"
```
**Ответ и механика:** `true`.
* Строки сравниваются посимвольно слева направо по таблице Unicode (как слова в словаре).
* Первый символ `'2'` больше первого символа `'1'`, на этом сравнение заканчивается. Числа из `<input>` нужно обязательно приводить к `Number` перед сравнением.

## Урок 05. Условные ветвления (`if/else`) и логические операторы (`&&`, `||`, `!`)

### 1. Фильтр доступа в онлайн-кинотеатре 🎬
**Условие:** Проверить доступ к фильму 18+. Приоритеты проверок: бан → возраст (< 18) → подписка → просмотр.

**Вариант А (Детальные причины отказа через `else if`):**
```javascript
const age = 20;
const hasSubscription = true;
const isBanned = false;

if (isBanned) {
  console.log('Доступ запрещен: аккаунт заблокирован');
} else if (age < 18) {
  console.log('Контент доступен только с 18 лет');
} else if (!hasSubscription) {
  console.log('Для просмотра оформите подписку');
} else {
  console.log('Приятного просмотра!');
}
```

**Вариант Б (Общая проверка через логическое `&&`):**
```javascript
if (!isBanned && hasSubscription && age >= 18) {
  console.log('Приятного просмотра!');
} else {
  console.log('Доступ запрещен');
}
```
*Вывод:* Булевы переменные проверяем напрямую (`isBanned`, `!hasSubscription`), не пишем `=== true` / `=== false`. Граница «от 18 включительно» — строго `>= 18`.

### 2. Бесплатная доставка в интернет-магазине 🚚
**Условие:** Доставка бесплатна, если клиент **НЕ** в удаленном регионе **И** выполняется хотя бы одно: сумма корзины `>= 3000` ИЛИ статус VIP ИЛИ есть промокод.

**Решение (с поясняющей переменной и скобками):**
```javascript
const cartTotal = 1500;
const isVipClient = true;
const hasPromoCode = false;
const isRemoteRegion = true;

const isFreeDelivery = !isRemoteRegion && (cartTotal >= 3000 || isVipClient || hasPromoCode);

if (isFreeDelivery) {
  console.log('Доставка бесплатная!');
} else {
  console.log('Стоимость доставки: 500 руб.');
}
```
*Вывод:* При смешивании `&&` и `||` всегда ставим круглые скобки `(...)`, так как `&&` имеет более высокий приоритет, чем `||`.

### 3. Банковский скоринг (Одобрение кредита) 🏦
**Условие:** Одобрить кредит, если возраст `>= 21`, нет долгов (`!hasDebt`) И есть либо хорошая кредитная история, либо доход `>= 50000`.

**Решение:**
```javascript
const age = 25;
const hasDebt = false;
const hasCreditHistory = true;
const monthlyIncome = 80000;

const isLoanApproved = age >= 21 && !hasDebt && (hasCreditHistory || monthlyIncome >= 50000);

if (isLoanApproved) {
  console.log('Кредит одобрен!');
} else {
  console.log('В кредите отказано');
}
```
*Вывод:* Использован паттерн **Поясняющая переменная (Explaining Variable)** — отделяем вычисление сложного правила (`isLoanApproved`) от ветвления `if / else`, чтобы избежать путаницы с ветками и сделать код самодокументируемым. Обязательно явное сравнение `monthlyIncome >= 50000`, так как любое ненулевое число само по себе является Truthy!

### 4. Карточка игрока (`||` vs `??` и тернарный оператор `? :`) 🎮
**Условие:** Обработать пустой ник `''` (заменить на `'Аноним'`) и реальный счёт `0` (не заменять на бонус `100`, если только там не `null`/`undefined`). Определить ранг через тернарник.

**Решение:**
```javascript
const userNickname = '';
const userScore = 0;

// || — заменяет пустую строку '' на 'Аноним' (так как '' — falsy)
const displayName = userNickname || 'Аноним';

// ?? — сохраняет реальный 0, срабатывает строго на null / undefined
const finalScore = userScore ?? 100;

// Тернарный оператор для простого выбора значения
const rank = finalScore >= 50 ? 'Профи' : 'Новичок';

console.log(`${displayName} | Очки: ${finalScore} | Ранг: ${rank}`);
// Вывод: Аноним | Очки: 0 | Ранг: Новичок
```
*Вывод:* `||` нужен для фильтрации пустых строк/любого falsy, а `??` — когда `0` и `false` являются валидными данными и их нельзя терять.

## Урок 06. Модальные окна и конструкция switch / case (Пазлы и задачи)

### 1. Ловушка отсутствующего break (Fall-through)
**Код:**
```javascript
const fruit = 'яблоко';

switch (fruit) {
  case 'банан':
    console.log('Жёлтый');
    break;
  case 'яблоко':
    console.log('Красный'); // Нет break!
  case 'груша':
    console.log('Зелёный');
    break;
  default:
    console.log('Неизвестный фрукт');
}
```
**Результат:** `'Красный'`, `'Зелёный'`.  
*Вывод:* Движок находит совпадение `'яблоко'`, выполняет его и, не встретив `break;`, проваливается в следующий `case 'груша'`.

### 2. Ловушка строгого сравнения типов (`===`)
**Код:**
```javascript
const userChoice = '2'; // строка

switch (userChoice) {
  case 1:
    console.log('Выбран один');
    break;
  case 2:
    console.log('Выбран два'); // число 2 !== строке '2'
    break;
  case '2':
    console.log('Выбрана строка два');
    break;
  default:
    console.log('Ничего не выбрано');
}
```
**Результат:** `'Выбрана строка два'`.  
*Вывод:* В `switch` сравнение строгое (`===`). Числовой `case 2` игнорируется для строки `'2'`.

### 3. Группировка кейсов
**Код:**
```javascript
const grade = 'B';

switch (grade) {
  case 'A':
  case 'B':
    console.log('Отличный результат!');
  case 'C':
    console.log('Удовлетворительно');
    break;
  default:
    console.log('Неизвестная оценка');
}
```
**Результат:** `'Отличный результат!'`, `'Удовлетворительно'`.  
*Вывод:* `case 'A'` и `case 'B'` объединены, но из-за отсутствия `break` выполнение провалилось в `case 'C'`.

### 4. Senior-ловушка: default не в конце
**Код:**
```javascript
const role = 'гость';

switch (role) {
  default:
    console.log('1. Роль не опознана'); // Нет break!
  case 'админ':
    console.log('2. Доступ к панели управления');
    break;
  case 'модератор':
    console.log('3. Доступ к модерации');
    break;
}
```
**Результат:** `'1. Роль не опознана'`, `'2. Доступ к панели управления'`.  
*Вывод:* Движок сначала сканирует все `case`. Не найдя совпадений для `'гость'`, переходит к `default`, а затем без `break` «ссыпается» в `case 'админ'`. `default` всегда ставим строго в самом конце!

### 5. Паттерн switch (true) для диапазонов
**Код:**
```javascript
const score = 85;

switch (true) {
  case score >= 90:
    console.log('Золото 🥇');
    break;
  case score >= 70:
    console.log('Серебро 🥈');
    break;
  case score >= 50:
    console.log('Бронза 🥉');
    break;
  default:
    console.log('Без медали ❌');
}
```
**Результат:** `'Серебро 🥈'`.  
*Вывод:* `switch (true)` ищет первый `case`, условие которого вычисляется в `true` (`85 >= 70` → `true`).

## Урок 08. Функции (`Function Declaration`, параметры, `return`)

### 1. Калькулятор цены со скидкой (Early Return + Default Parameter) 🏷️
**Условие:** Написать функцию `calcFinalPrice(price, discount = 0)` с защитой `price <= 0` → возврат `0`, иначе вернуть цену со скидкой.

**Эталонное решение:**
```javascript
function calcFinalPrice(price, discount = 0) {
  if (price <= 0) {
    return 0;
  }

  return price - (price * discount / 100);
}

console.log(calcFinalPrice(1000, 20)); // 800
console.log(calcFinalPrice(500));      // 500
console.log(calcFinalPrice(-100, 10)); // 0
```

### 2. Пазл: Затенение (Shadowing) + `null` в параметре по умолчанию
**Код:**
```javascript
const name = 'Максим';

function greet(name = 'Гость') {
  return `Привет, ${name}`;
}

console.log(greet());     // 'Привет, Гость'
console.log(greet(null)); // 'Привет, null'
console.log(name);        // 'Максим'
```
*Вывод:* Дефолт `name = 'Гость'` срабатывает только на `undefined`, поэтому `null` проходит как есть. Внешняя переменная `name` не затрагивается.

### 3. Пазл: Функция без `return`
**Код:**
```javascript
function sayHi(name) {
  console.log(`Привет, ${name}`);
}

const result = sayHi('Иван');
console.log(result); // undefined
```
*Вывод:* Без явного `return` любая функция возвращает `undefined`.

## Урок 09. Виды функций, стрелочные функции и колбэки (Пазлы)

### 1. Всплытие `Function Declaration` vs `TDZ` стрелочной функции
**Код:**
```javascript
console.log(double(5)); // 10
console.log(triple(5)); // ReferenceError!

function double(n) {
  return n * 2;
}

const triple = (n) => n * 3;
```
*Вывод:* `Function Declaration` всплывает полностью и работает до объявления. Стрелочная функция в `const` подчиняется правилам переменной (TDZ).

### 2. Ловушка возврата объекта из стрелочной функции
**Код с ошибкой:**
```javascript
const makeUser = (name, age) => { name: name, age: age }; // SyntaxError!
```
**Правильное решение:**
```javascript
const makeUser = (name, age) => ({ name: name, age: age });
```
*Вывод:* Фигурные скобки сразу после `=>` движок воспринимает как тело функции. Для неявного возврата объекта его нужно обернуть в круглые скобки `({ ... })`.

### 3. Ловушка передачи колбэка со скобками
**Код с ошибкой:**
```javascript
function runAction(callback) {
  console.log('1. Подготовка...');
  callback();
}

function finish() {
  console.log('2. Готово!');
}

runAction(finish()); // ❌ finish() сработает сразу, передастся undefined -> TypeError!
```
**Правильное решение:**
```javascript
runAction(finish); // ✅ Передаем ссылку на функцию БЕЗ скобок!
```
*Вывод:* Колбэк передается как значение (без вызова `()`), чтобы принимающая функция вызвала его внутри себя в нужный момент.

## Блок 1. Контрольный спринт (Уроки 01–09)

### 1. Калькулятор зарплаты курьера (Разбор с комментариями)
**Условие (ТЗ):**
- Если базовая ставка (`baseRate`) равна `null` или `undefined`, используется ставка по умолчанию `1000`.
- Функция `calcSalary(daysCount, dailyRate = 1000)` считает итоговую зарплату за `daysCount` дней.
- Если `daysCount <= 0`, функция сразу возвращает `0` (Early Return).
- Каждый 7-й день (`day % 7 === 0`) — выходной, он пропускается через `continue`.
- Каждый чётный день (`day % 2 === 0`) курьер получает ставку + премию `500`, нечётный — только ставку.

```javascript
/*
==========================================
1. ВВОДНЫЕ ДАННЫЕ
==========================================
*/
const courierName = 'Максим';
const daysWorked = 7;
const baseRate = null;

/*
==========================================
2. ПОДГОТОВКА СТАВКИ (НУЛЕВОЕ СЛИЯНИЕ ??)
==========================================
finalRate — это итоговая дневная ставка, с которой мы пойдём считать зарплату.
Чтобы её вычислить, пишем: baseRate ?? 1000.
Оператор ?? реагирует только на null или undefined слева: так как в baseRate лежит null, он берёт запасное значение 1000.
(Если бы там лежал 0, ?? оставил бы 0, в отличие от ||).
*/
const finalRate = baseRate ?? 1000;

/*
==========================================
3. ФУНКЦИЯ РАСЧЁТА ЗАРПЛАТЫ
==========================================
calcSalary — функция-калькулятор. Принимает количество дней (daysCount) и ставку (dailyRate = 1000).
Значение по умолчанию '= 1000' сработает, только если dailyRate не передали или передали undefined (на null оно НЕ сработает).
*/
function calcSalary(daysCount, dailyRate = 1000) {
  /*
  Early Return (ранний выход):
  Отсекаем некорректные значения (0 или отрицательные дни) до старта цикла — return 0 сразу завершает функцию.
  */
  if (daysCount <= 0) {
    return 0;
  }

  /*
  totalSalary — «копилка» (аккумулятор) итоговой суммы. Объявляем через let, так как значение будет обновляться на каждом круге цикла.
  */
  let totalSalary = 0;

  /*
  Цикл for проходит по каждому отработанному дню с 1 по daysCount включительно:
  - let day = 1 — стартуем с 1-го дня;
  - day <= daysCount — продолжаем, пока номер дня не превысит общее количество дней;
  - day++ — увеличиваем счётчик на +1 в конце каждой итерации.
  */
  for (let day = 1; day <= daysCount; day++) {
    /*
    Проверка на выходной (каждый 7-й день: 7, 14, 21...).
    Остаток от деления % 7 === 0 означает, что день кратен 7.
    ВАЖНО: стоит ДО проверки на чётность, иначе 14-й день получил бы премию, хотя он выходной.
    continue сразу прерывает текущий круг и переводит цикл на day++ (следующий день).
    */
    if (day % 7 === 0) {
      continue;
    }

    /*
    Проверка на чётный рабочий день (day % 2 === 0):
    В чётный день к копилке прибавляем ставку + премию 500, в ветке else (нечётный) — только ставку.
    */
    if (day % 2 === 0) {
      totalSalary += dailyRate + 500;
    } else {
      totalSalary += dailyRate;
    }
  }

  /*
  После завершения цикла возвращаем накопленную сумму наружу из функции.
  */
  return totalSalary;
}

/*
==========================================
4. ВЫЗОВ ФУНКЦИИ И ВЫВОД РЕЗУЛЬТАТА
==========================================
salary — готовая сумма зарплаты для конкретного курьера.
Чтобы её получить, вызываем calcSalary с аргументами daysWorked (7) и finalRate (1000).
То, что вернёт return (7500), запишется в const salary.
*/
const salary = calcSalary(daysWorked, finalRate);

// Вывод в консоль: "Курьер Максим заработал за 7 дн.: 7500 руб."
console.log(`Курьер ${courierName} заработал за ${daysWorked} дн.: ${salary} руб.`);
```

## Урок 12. Контекст `this` и замыкания (Примеры на повторный разбор и отработку)

> [!NOTE]
> Обязательно вернуться к этим двум примерам, прорешать их руками и проговорить механику: почему обычная функция `this` не замыкает, а стрелочная — запоминает.

### 1. Возврат обычной функции (`function innerFn()`) — `this` НЕ замыкается
```javascript
const user = {
  name: 'Макс',

  outer() {
    const secret = 123;

    /*
    secret — обычная переменная, она попадёт в замыкание и сохранится.
    this — НЕ замыкается! Он по-прежнему зависит только от того, как вызовут fn().
    */
    return function innerFn() {
      console.log(secret, this?.name);
    };
  },
};

const fn = user.outer();
fn(); // 123, undefined (слева от fn() никого нет -> this потерялся!)

const admin = { name: 'Олег', fn };
admin.fn(); // 123, 'Олег' (прицепили к admin -> this стал admin!)
```

### 2. Возврат стрелочной функции (`() => {}`) — `this` запоминается из `outer()`
```javascript
const user = {
  name: 'Макс',

  outer() {
    /*
    Стрелка ищет this во внешнем окружении точно так же, как обычную переменную.
    В момент вызова user.outer() здесь this === user — стрелка запомнит его навсегда.
    */
    return () => {
      console.log(this.name);
    };
  },
};

const fn = user.outer();
fn(); // 'Макс' — даже при обычном вызове fn() контекст не потерялся!
```


### 3. Все 4 способа сохранить объект (`this`) для внутренней функции (Прорешать и разобрать)

> [!NOTE]
> Проверить руками каждый из 4 вариантов на задаче «Обработчик урона для героя» и понять, почему каждый работает по-своему (особенно в чём слабость варианта 4 при копировании/переименовании объекта).

#### Вариант 1. Стрелочная функция `() => {}` (главный современный способ)
```javascript
const hero = {
  heroName: 'Артур',
  hp: 100,

  createHitHandler(damage) {
    /*
    Стрелка не создаёт свой this, поэтому забирает this у родительского метода createHitHandler().
    При вызове hero.createHitHandler(20) здесь this === hero — стрелка запоминает его навсегда.
    */
    return () => {
      this.hp -= damage;
      console.log(`${this.heroName} получил урон ${damage}. Осталось HP: ${this.hp}`);
    };
  },
};
```

#### Вариант 2. Жёсткая привязка через `.bind(this)`
```javascript
const hero = {
  heroName: 'Артур',
  hp: 100,

  createHitHandler(damage) {
    /*
    Обычная function() потеряла бы this при вызове takeHit(), но метод .bind(this)
    создаёт обёртку с намертво приклеенным this === hero.
    */
    return function () {
      this.hp -= damage;
      console.log(`${this.heroName} получил урон ${damage}. Осталось HP: ${this.hp}`);
    }.bind(this);
  },
};
```

#### Вариант 3. Сохранение `this` в обычную переменную (`const self = this;`)
```javascript
const hero = {
  heroName: 'Артур',
  hp: 100,

  createHitHandler(damage) {
    /*
    Обычный this не попадает в замыкание function(), но обычная переменная self — попадает!
    Приём из старого JS (до ES6), важно уметь читать его в чужом коде.
    */
    const self = this;

    return function () {
      self.hp -= damage;
      console.log(`${self.heroName} получил урон ${damage}. Осталось HP: ${self.hp}`);
    };
  },
};
```

#### Вариант 4. Обращение напрямую по имени переменной (`hero.hp`) — антипаттерн
```javascript
const hero = {
  heroName: 'Артур',
  hp: 100,

  createHitHandler(damage) {
    /*
    Технически работает через замыкание на переменную hero, но это плохая практика:
    если объект перенести/скопировать (hero2 = { ...hero }) или обнулить переменную hero = null,
    метод сломается или будет бить по чужому объекту.
    */
    return function () {
      hero.hp -= damage;
      console.log(`${hero.heroName} получил урон ${damage}. Осталось HP: ${hero.hp}`);
    };
  },
};
```
