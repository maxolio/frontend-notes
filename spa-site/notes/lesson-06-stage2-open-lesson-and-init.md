# Этап 2. Урок 3. Подробный разбор `openLesson()` и `init()`: запуск и переключение

Суть урока: Функция `init()` запускает сайт один раз при старте (загружает `lessons.json` и открывает первый урок), а `openLesson(lesson)` отвечает за каждое переключение: обновляет `state.activeId`, перерисовывает меню и загружает нужный `.md`-файл в `#content`.

## 1. Построчный разбор `openLesson(lesson)`

[+] Эта функция срабатывает при каждом клике по кнопке меню (и один раз при старте из `init()`):

```js
async function openLesson(lesson) {
/* Получает объект выбранного урока, например:
   { id: 'lesson-02', title: 'Урок 02...', file: 'lesson-02.md' } */

  state.activeId = lesson.id;
  /* 1. Обновляем состояние: запоминаем в state.activeId, какой урок сейчас активен. */

  renderMenu();
  /* 2. Просим renderMenu() заново нарисовать кнопки:
        старая кнопка потеряет класс "active", а нажатая — получит его. */

  const response = await fetch(lesson.file);
  const markdown = await response.text();
  /* 3. Скачиваем файл именно этого урока (например, 'lesson-02.md')
        и вычитываем его содержимое как строку Markdown. */

  contentEl.innerHTML = marked.parse(markdown);
  /* 4. Переводим Markdown в HTML и заменяем содержимое <article id="content">. */
}
```

[+] **Краткий итог работы `openLesson(lesson)`:** в памяти обновлён `state.activeId`, меню уже перерисовано с подсветкой на новой кнопке, а внутри `<article id="content">` на экране показан свежий урок — и сайт снова замирает в режиме ожидания следующего клика.

## 2. Построчный разбор `init()` и старт сайта

[+] `init()` — это «ключ зажигания», который превращает пустую страницу в готовое приложение:

```js
async function init() {
/* Стартовая функция: срабатывает ровно 1 раз при открытии сайта */

  const response = await fetch('lessons.json');
  state.lessons = await response.json();
  /* 1. Скачиваем lessons.json и через .json() сразу превращаем JSON-текст
        в настоящий JS-массив объектов, который кладём в state.lessons. */

  if (state.lessons.length > 0) {
    openLesson(state.lessons[0]);
  }
  /* 2. Защита от пустого списка: если в массиве есть хотя бы 1 урок,
        сразу открываем самый первый (под индексом 0) и рисуем меню. */
}

init();
/* 3. Точка входа: запускаем всё приложение при загрузке скрипта */
```

[+] **Краткий итог работы `init()`:** она срабатывает ровно один раз при открытии страницы: скачивает `lessons.json`, сохраняет список уроков в `state.lessons` и запускает `openLesson(state.lessons[0])` — после чего на экране сразу показан первый урок, меню нарисовано и сайт полностью готов к кликам.

## 3. Схема полного цикла жизни сайта

```text
[Открытие сайта] ─► init() ─► fetch('lessons.json') ─► state.lessons = [...]
                                                              │
                                                              ▼
   ┌──────────────────◄── [Режим ожидания клика] ◄── openLesson(state.lessons[0])
   │                                                          ▲
   └──► [Клик по кнопке урока N] ─────────────────────────────┘
```

## 4. Что происходит при открытии страницы (6 шагов)

1. **Каркас:** браузер читает `index.html` и создаёт пустые `<nav id="menu">` и `<article id="content">Загрузка...</article>`.
2. **Библиотека:** запускается первый `defer`-скрипт `marked.min.js` и кладёт в память `window.marked`.
3. **Старт скрипта:** запускается `app.js` — находит `#menu` и `#content`, создаёт пустой `state` и вызывает `init()`.
4. **Список уроков:** `init()` скачивает `lessons.json`, парсит через `response.json()` в JS-массив и сохраняет в `state.lessons`.
5. **Отрисовка меню:** `init()` вызывает `openLesson(state.lessons[0])` — та меняет `state.activeId` и через `renderMenu()` рисует кнопки (первую с классом `active`).
6. **Вывод текста:** `openLesson()` скачивает `lesson-01.md` (`response.text()`), переводит через `marked.parse()`, вставляет в `#content` — и сайт переходит в режим ожидания клика.

## 5. Почему срабатывают `openLesson()` и `renderMenu()` — эффект домино

[+] Никакого «автозапуска» у `openLesson()` и `renderMenu()` нет: при старте файла браузер вызывает **только одну последнюю строчку `init();`**, а дальше одна функция просто вызывает другую внутри себя:

```text
Браузер дошёл до последней строки app.js:
  init();
   │
   └──► внутри init() написано: openLesson(state.lessons[0]);
         │
         └──► внутри openLesson() написано: renderMenu();
```

А когда сайт уже открыт и пользователь нажимает на кнопку меню, цепочка стартует сразу со второй костяшки: `клик` → `openLesson(lesson)` → `renderMenu()`.

## 3 главные ловушки урока (чек-лист для повторения)

1. Перепутать `.json()` и `.text()`: в `init()` нужен `response.json()`, чтобы получить JS-массив объектов, а в `openLesson()` нужен `response.text()`, чтобы получить строку Markdown (иначе `.json()` упадёт при парсинге `# Заголовка`).

2. Забыть проверку `if (state.lessons.length > 0)`: если `lessons.json` окажется пустым массивом `[]`, вызов `openLesson(undefined)` упадёт на попытке прочитать `lesson.id`.

3. Забыть вызвать `init()` в самом низу файла: функция будет объявлена в памяти, но никогда не запустится, и страница останется на тексте «Загрузка...».

## Вопросы для закрепления

**1. Почему в `init()` мы пишем `await response.json()`, а в `openLesson()` — `await response.text()`?**

<details>
<summary>Показать ответ</summary>

Потому что `lessons.json` содержит данные в формате JSON — метод `.json()` сразу парсит их в готовый JS-массив. А `lesson-01.md` содержит обычный текст Markdown (не JSON), поэтому для него нужен `.text()`.

</details>

**2. Что произойдёт, если в `openLesson()` поменять строки местами: сначала сделать `await fetch(...)`, а `state.activeId = lesson.id` и `renderMenu()` поставить в самый конец?**

<details>
<summary>Показать ответ</summary>

Подсветка активной кнопки в меню будет срабатывать с задержкой — только после того, как файл полностью скачается по сети. Ставя `state.activeId` и `renderMenu()` до `fetch`, мы даём пользователю мгновенный отклик интерфейса при клике.

</details>
