# Этап 2. Урок 1. Общая картина `app.js` по сущностям: `state`, `renderMenu`, `openLesson`, `init`

Суть урока: На втором этапе `app.js` перестаёт быть линейным скриптом и превращается в 5 чётких сущностей: ссылки на DOM-контейнеры (`menuEl`, `contentEl`), объект памяти (`state`), функцию отрисовки (`renderMenu`), переключатель (`openLesson`) и стартер (`init`).

## 1. Общая карта сущностей в `my-site/app.js`

[+] Если свернуть тела функций в редакторе, весь наш скрипт выглядит как понятный скелет из 5 блоков:

```js
'use strict';

/* 1. Точки входа в DOM (куда будем вставлять кнопки и текст) */
const menuEl = document.getElementById('menu');
const contentEl = document.getElementById('content');

/* 2. Состояние приложения (единый источник правды в памяти) */
const state = {
  lessons: [],
  activeId: null,
};

/* 3. Художник меню: превращает массив state.lessons в кнопки */
function renderMenu() { /* ... */ }

/* 4. Переключатель: обновляет state, меню и загружает .md файл */
async function openLesson(lesson) { /* ... */ }

/* 5. Стартер: один раз грузит lessons.json и запускает первый урок */
async function init() { /* ... */ }

init();
```

## 2. Подробная роль каждой сущности

[+] Разберём, за что отвечает каждый блок и почему их разделили именно так:

- **`menuEl` и `contentEl` (связь с HTML):** ссылки на пустые теги `<nav id="menu">` и `<article id="content">` в `index.html`. Они находятся один раз в начале файла, чтобы не искать их по DOM при каждом клике.
- **`state` (память / данные):** простой объект с двумя полями:
  - `lessons` — массив всех уроков, скачанный из `lessons.json`;
  - `activeId` — `id` урока, который открыт прямо сейчас (нужен, чтобы знать, какую кнопку подсветить классом `active`).
- **`renderMenu()` (отрисовка от состояния):** эта функция **не делает сетевых запросов** и ничего не знает про `fetch()`. Она просто смотрит на `state.lessons` и `state.activeId`, очищает `<nav id="menu">` и заново строит кнопки `<button>`.
- **`openLesson(lesson)` (главное действие):** вызывается при клике на кнопку (или при старте). Сначала обновляет `state.activeId`, потом вызывает `renderMenu()` (подсветка прыгает на нажатую кнопку), а затем скачивает `lesson.file` и вставляет в `contentEl`.
- **`init()` (точка запуска):** срабатывает ровно один раз при открытии вкладки — скачивает `lessons.json`, кладёт массив в `state.lessons` и вызывает `openLesson(state.lessons[0])`.

## 3. Схема взаимодействия сущностей при клике

```text
[Клик по кнопке в меню]
         │
         ▼
  openLesson(lesson)
    ├──► 1. Меняет state.activeId = lesson.id
    ├──► 2. Вызывает renderMenu() ──► перерисовывает кнопки с новым .active
    └──► 3. fetch(lesson.file)    ──► marked.parse() ──► contentEl.innerHTML
```

[!] Обрати внимание на главный принцип **State-Driven UI**: при клике мы не ищем «старую кнопку» руками, чтобы снять с неё класс `active`, и не вешаем класс вручную на новую. Мы просто меняем `state.activeId` и вызываем `renderMenu()` — интерфейс сам приводится в соответствие с состоянием.

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть очистить `menuEl.innerHTML = ''` в начале `renderMenu()`: при каждом переключении урока старые кнопки останутся, и к ним приклеятся ещё 3 дубля.

2. Вызвать `openLesson(state.lessons[0])` **до** завершения `await fetch('lessons.json')` (или забыть `init()` в конце файла): массив `state.lessons` ещё пустой `[]`, и экран останется на надписи «Загрузка...».

3. Пытаться вручную снимать/вешать `.active` на конкретные DOM-кнопки в обход `state.activeId`: при добавлении поиска или закладок логика сразу начнёт расходиться с тем, что реально нарисовано на экране.
