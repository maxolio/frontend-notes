# Этап 1. Урок 2. Как работает CDN-скрипт и библиотека `marked.js`

Суть урока: Ссылка на CDN (`cdn.jsdelivr.net`) доставляет уже собранный и сжатый пакет из `npm` прямо в браузер без сборщика, а `marked.min.js` один раз загружается в оперативную память вкладки как `window.marked` и дальше работает локально через `marked.parse()`.

## 1. Разбор ссылки CDN (jsDelivr) по частям

[+] Когда у проекта нет сборщика (`Vite` / `Webpack`), внешние библиотеки подключают по прямой ссылке CDN (Content Delivery Network):

```text
https://cdn.jsdelivr.net / npm / marked / marked.min.js
         │                  │      │          │
   Сервер CDN        База пакетов Имя     Сжатый файл
  (быстрая сеть)        npm      пакета   для браузера
```

- **`cdn.jsdelivr.net`** — бесплатный сервер, который раздаёт открытые JS-библиотеки по всему миру.
- **`/npm/marked/`** — обращение к пакету `marked` из реестра `npm` (при желании можно зафиксировать точную версию, например `marked@12.0.0`).
- **`marked.min.js`** — файл с суффиксом `.min` (минифицированный: без пробелов, комментариев и длинных имён, чтобы весить меньше и быстрее качаться).

## 2. Как функция живёт в памяти браузера (`window.marked`)

[+] При открытии страницы браузер **один раз** скачивает `marked.min.js`, движок JS (V8) читает его и кладёт объект `marked` с функцией `parse` в оперативную память (RAM) текущей вкладки — внутрь глобального объекта `window`.

```js
/* Под капотом библиотека делает примерно следующее: window.marked = { parse: ... } */
/* Писать window. необязательно — JS сам ищет глобальные имена: */
const markdown = '# Заголовок\n**Важный** текст';
const html = marked.parse(markdown);

/* При вызове marked.parse() интернет уже НЕ нужен — функция работает
   локально на процессоре твоего устройства в памяти этой вкладки. */
console.log(html);
/* Выведет строку: "<h1>Заголовок</h1>\n<p><strong>Важный</strong> текст</p>\n" */
```

[!] Эта память привязана к **текущей вкладке**. После закрытия или обновления (`F5`) память очищается, и браузер загружает скрипты заново (обычно уже из быстрого кэша на диске).

## 3. Можно ли скачать библиотеку локально, как шрифты?

[+] Да — есть два способа вообще не зависеть от серверов CDN:

```html
<!-- Способ 1 (без сборщика): скачать marked.min.js в папку проекта vendor/ -->
<script src="vendor/marked.min.js" defer></script>
```

```js
/* Способ 2 (со сборщиком Vite): установить через npm install marked */
import { marked } from 'marked';
/* При сборке Vite сам упакует код библиотеки в итоговый проект */
```

## 4. Границы ответственности и безопасность (`DOMPurify`)

[!] Важно понимать, что делает `marked.parse()`, а что — нет:
- Он **только переводит** строку Markdown в строку HTML.
- Он **не скачивает** файлы (для этого нужен `fetch`) и **не вставляет** результат на страницу (это делает `innerHTML`).
- По умолчанию `marked` пропускает сырые HTML-теги как есть. Поэтому теги вроде `<script>` в тексте урока нужно брать в обратные кавычки `` `<script>` ``, а чужой ввод от пользователей в реальных проектах обязательно чистят библиотекой вроде `DOMPurify` (защита от XSS-атак).

## 3 главные ловушки урока (чек-лист для повторения)

1. Ожидать, что `marked.parse('lesson-01.md')` сам откроет и прочитает файл — он примет `'lesson-01.md'` за обычный текст и вернёт `<p>lesson-01.md</p>`.

2. Пытаться подключить `import { marked } from 'marked'` без сборщика (`Vite`): чистый браузер не знает, где искать пакет `'marked'` в `node_modules`.

3. Оставить в тексте конспекта неэкранированный тег `<script>` или `<body>` без обратных кавычек — браузер воспримет его как реальный HTML-тег, и слово пропадёт с экрана.

## Вопросы для закрепления

**1. Почему при вызове `marked.parse(markdown)` браузер каждый раз не ходит на сервер `cdn.jsdelivr.net`?**

<details>
<summary>Показать ответ</summary>

Потому что файл `marked.min.js` скачивается один раз при загрузке страницы, а созданная им функция `parse` уже лежит в оперативной памяти (RAM) вкладки внутри `window.marked` и выполняется локально.

</details>

**2. Зачем в продакшене результат `marked.parse()` дополнительно прогоняют через `DOMPurify`, если текст прислал незнакомый пользователь?**

<details>
<summary>Показать ответ</summary>

`marked` пропускает сырой HTML. Злоумышленник может вставить в Markdown вредоносный тег (XSS), который выполнится при записи в `innerHTML`. `DOMPurify` вырезает опасные теги и атрибуты, оставляя безопасный HTML.

</details>
