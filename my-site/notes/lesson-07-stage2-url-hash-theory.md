# Этап 2. Урок 4. Что такое URL-хэш (`window.location.hash`) и событие `hashchange`

Суть урока: Хэш — это часть URL после символа `#` (например, `#lesson-02`); при её изменении браузер **не перезагружает страницу** и не шлёт запрос на сервер, но сам записывает переход в историю «Назад / Вперёд» и запускает событие `hashchange`.

## 1. Из каких частей состоит адрес (URL) в браузере

[+] Любая ссылка в адресной строке делится на понятные части, и браузер хранит их в объекте `window.location`:

```text
https://maxolio.github.io /frontend-notes/site/ ?theme=dark #lesson-02
  │            │                    │                │           │
протокол     домен          путь к странице     параметры      ХЭШ
(protocol)  (host)            (pathname)         (search)     (hash)
```

- **Если поменять `pathname`** (например, с `/page1.html` на `/page2.html`) — браузер сделает запрос на сервер и **полностью перезагрузит** страницу.
- **Если поменять `hash`** (например, с `#lesson-01` на `#lesson-02`) — страница **остаётся на месте**, сеть не трогается, работает только наш JavaScript!

## 2. Откуда взялся `#` и почему его используют в SPA

[+] Изначально символ `#` придумали для «якорей» внутри длинной HTML-страницы (чтобы прокрутить к заголовку `<h2 id="contacts">`). Браузер считал: *«Это та же самая страница, просто другое место внутри неё — качать HTML заново не нужно»*.

Разработчики SPA-приложений использовали эту особенность для переключения экранов:
1. Вся страница (`index.html`) уже загружена в памяти.
2. Когда меняется хэш с `#lesson-01` на `#lesson-02`, вкладка не моргает.
3. **Бонус из коробки:** браузер сам запоминает каждый новый хэш в историю вкладки, поэтому кнопки **«Назад»** и **«Вперёд»** начинают работать, а при нажатии **`F5`** адрес `#lesson-02` сохраняется в строке!

## 3. Как читать и менять хэш через `window.location.hash`

[+] В JavaScript за эту часть URL отвечает свойство `window.location.hash`:

```js
/* 1. ЧТЕНИЕ: если в адресной строке сейчас http://127.0.0.1:8080/my-site/#lesson-02 */
console.log(window.location.hash);         /* "#lesson-02" (всегда приходит с '#' в начале!) */

/* Если в ссылке вообще нет решётки: */
console.log(window.location.hash);         /* "" (пустая строка) */

/* 2. ОЧИСТКА ОТ '#': в state.lessons у нас id хранится без решётки ('lesson-02'),
   поэтому первый символ отрезают методом .slice(1): */
const cleanId = window.location.hash.slice(1); /* "lesson-02" (или "", если хэша не было) */

/* 3. ЗАПИСЬ: меняем адрес в строке браузера без перезагрузки страницы */
window.location.hash = '#lesson-03';       /* URL станет .../#lesson-03, шаг попадёт в историю */
```

## 4. Событие `hashchange`: как поймать клик по кнопке «Назад»

[+] Если пользователь нажал кнопку **«Назад»** в браузере (или сам дописал `#lesson-01` в адресной строке), сам URL изменился, но наш JS об этом ещё не знает. Чтобы отреагировать на это, вешают слушатель события `'hashchange'` на глобальный объект `window`:

```js
window.addEventListener('hashchange', () => {
  /* Этот код сработает каждый раз, когда часть URL после # изменилась */
  console.log('Новый хэш:', window.location.hash);
});
```

[!] Важно: событие `hashchange` срабатывает **только когда хэш реально изменился** (например, с `#lesson-01` на `#lesson-02`). Если записать в `window.location.hash` тот же самый хэш, который там уже стоит — событие не сработает.

## 5. Мини-мостик на будущее: `#hash` против `History API`

[+] Есть два способа делать адреса в SPA:
- **Через `#hash` (`#lesson-02`):** работает везде без настройки сервера (даже на бесплатном GitHub Pages!), именно поэтому мы выбрали его для `my-site/` и `site/`.
- **Через `history.pushState` (`/lesson-02` без `#`):** выглядит «красивее», но при обновлении страницы (`F5`) браузер пойдёт на сервер искать реальный файл `/lesson-02`, и без специальной настройки сервера выдаст `404`.

## 3 главные ловушки урока (чек-лист для повторения)

1. Забыть отрезать `#` через `.slice(1)` при сравнении с `lesson.id`: `"#lesson-02" === "lesson-02"` всегда даст `false`, и урок не найдётся.

2. Перезаписывать `window.location.hash` заново тем же значением или вызывать `openLesson()` из `hashchange` без проверки `lesson.id !== state.activeId` — легко получить лишний повторный вызов функции.

3. Ждать, что часть после `#` отправится на сервер при `fetch()` или открытии страницы: браузер **никогда не отправляет хэш на сервер** — он живёт только локально на стороне клиента.

## Вопросы для закрепления

**1. Почему при изменении `window.location.hash` страница не перезагружается и не уходит новый запрос на сервер?**

<details>
<summary>Показать ответ</summary>

Браузер исторически считает часть после `#` ссылкой-якорем внутри уже открытой страницы. Поэтому при её смене он не перезагружает документ, а лишь обновляет адрес, записывает шаг в историю вкладки и запускает событие `hashchange`.

</details>

**2. Что вернёт `window.location.hash`, если адрес заканчивается на `/my-site/#lesson-03`, и зачем мы применяем `.slice(1)`?**

<details>
<summary>Показать ответ</summary>

`window.location.hash` вернёт строку `"#lesson-03"` вместе с решёткой. Метод `.slice(1)` отрезает первый символ с индексом `0` (`#`), чтобы получить чистое `"lesson-03"` и сравнить его с `lesson.id` из `lessons.json`.

</details>

**3. Что делает слушатель `window.addEventListener('hashchange', ...)`?**

<details>
<summary>Показать ответ</summary>

Он отслеживает любые внешние изменения хэша в адресной строке — например, когда пользователь нажимает в браузере кнопки «Назад» / «Вперёд» или меняет `#...` в строке вручную.

</details>
